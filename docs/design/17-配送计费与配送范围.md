## 1. 目的与范围

起送量、配送范围、运费、楼层费共用"站级参数 + 下单时快照"一套机制，故合为一篇。范围外：给配送员的**楼层补贴**是另一笔钱（成本项，见 `staff_piece_rate` / `staff_earning`）。规则正本是 `util/DeliveryFeeUtil`，单价与押金的正本是 `util/PriceUtil`（站级覆盖判定为"非空且 > 0"），表结构正本是 `sql/schema.sql`。

## 2. 设计口径

### 2.1 起送量：默认软提示，不是硬拦

三档模式（`DeliveryLimitMode`）：`WARN`（**默认**，放行 + `warnings`）/ `REJECT`（拒绝下单，`code = 1` + 可读文案）/ `FEE`（加收 `min_order_fee` 后放行）。桶数与金额门槛**取或**，都为空 = 不限。

- **⚠️ 任何"硬拦"都必须由站长显式开启**：老客户只要 1 桶时站长一定通融，系统硬拦等于逼站长绕过系统下单，那会破坏桶账真实性。**⚠️ 非法 / 空模式值归一化为 `WARN`，绝不回落 `REJECT`** —— 配置写错不该表现为"客户下不了单"。
- **⚠️ 非桶装单（桶数 ≤ 0）桶数条件不适用**：只核金额门槛，没配则整条规则不生效（不拦）；上架非桶装商品时金额门槛为空即拒绝保存（`DeliveryConfigGuideService`）。客户级「免起送门槛」特权（`PrivilegeType.NO_MIN_ORDER`）为真时**整段跳过**：不拦、不加收、不提示，按 `(customer, station)` 隔离。

### 2.2 配送范围：直线距离 + 软处理

用站点到地址的 Haversine **直线距离**（`util/GeoUtil#distanceMeters`）。**不要接地图 API 的骑行 / 驾车距离**：桶装水是电动车 / 三轮车，直线够用，第三方接口还有配额、费用与联网依赖。默认 `WARN`，`REJECT` / `FEE`（加收 `remote_fee`）由站长选。

**⚠️ 三条边界，缺一个就会误拦：**

1. **站点坐标为空** → 跳过范围校验（不是拒单），只提示补坐标；
2. **地址坐标为 NULL** → 跳过校验，只提示。`address.lat/lng` 可空（地图解析失败、客户手填），把"没有数据"当"超出范围"会把客户全挡在门外；`distanceMeters` 因此返回 `null` 而非 0 —— **0 是"同一个点"这个合法值**；
3. **跨站外派单按「归属站（下单水站）」算，且只在下单那一刻算一次**：`calcForOrder` 的两个调用点传的都是下单水站，外派 / 抢单一律不重算（`claimPool` 只改 `delivery_station_id` 与配送员）。

**⚠️ 外派与认领都不得触发第二次计价** —— 重算就是"计价双轨"（见 `util/PriceUtil` 文件头），会出现"抢单页一个价、订单详情另一个价"。抢单池只下发**费用快照 + 定价来源站名 + 去向文案**（`DeliveryController.feeInfoOf`）；**⚠️ 池子是跨租户可见面，不许带归属站的成本 / 库存 / 联系方式**。押金 / 水票 / 桶权益始终在归属站，营收与结算站口径见 `AGENTS.md` §1。

### 2.3 运费

桶数达免运门槛 **或** 水费达免运金额门槛 → `delivery_fee = 0`；否则 `base_delivery_fee + (超范围 ? remote_fee : 0)`。不做动态定价。

- **⚠️ 两个免运费门槛都为空 = 一直收基础配送费**（不是"一直免"）；纯非桶装单只看金额门槛，没配时同此口径（免运费是给优惠，条件不适用时不给是保守的一侧）。由 `DeliveryFeeUtilTest.noFreeThresholdAlwaysCharges` 锁定。
- **「免配送次数」是客户资产，不是配置项**：必须落成"账户 + 流水 + 幂等 + 对账"（同押金 / 水票），运费计算里只做"本次是否用掉一次"。**⚠️ 不要做成配置里的布尔开关或客户画像上的开关** —— 那会退化成没有校验与流水的裸状态。当前 `PrivilegeType.FREE_DELIVERY_TIMES` **未实现**，授予时直接拒绝。

### 2.4 楼层费

`有电梯(has_elevator=1) or floor IS NULL or floor <= floor_free_level → 0`；否则 `floor_fee_per_level × (floor − floor_free_level) × (PER_BUCKET ? 桶数 : 1)`。

- **⚠️ `has_elevator` 是三态**（`NULL` 未确认 / `0` 无电梯 / `1` 有电梯，**NULL 与 0 不可混同**）：把 NULL 当"无电梯"会向客户乱收钱，当"有电梯"会漏收；未确认时**不收、只提示**。`floor_fee_per_level = 0`（没配）时不收也**不提示**；`PER_BUCKET` 下桶数为 0 也算 1 份。
- **默认 `PER_ORDER`**：按桶收更常见（"无电梯 2 元/桶"），但会产生**客户看到 3 桶 × 2 元 = 6 元而放弃下单**的摩擦；未配时回落 `PER_ORDER`（收费更少的那个）。
- **⚠️ 楼层费（向客户收，收入项）与楼层补贴（给配送员，成本项）是两笔钱**，必须分别配置、分别落库；合成一个字段会导致客户投诉时查不清、工钱算不准。电梯楼但有台阶 / 半层不在建模范围，靠 `special_note` / `delivery_time_request` 兜住。

### 2.5 对账影响

**等式1（押金余额 == `SUM(deposit_record.amount)`）、等式3 / 4、E5 不受影响 —— 前提是运费不塞进 `deposit_amount`**；**等式2 受影响**：`payment_record` 必须与 `orders` 口径对齐（现为同名的 `delivery_fee` / `floor_fee` 两列），一边含运费另一边不含会报"有凭证未置已付"，**两边口径必须一次对齐**。

**验收判据：加完费用列后必须跑一次完整日结对账，全部平。** 报价返回的 `totalAmount` 被小程序结算页直接使用，改口径必须同步核对两端展示。

## 3. 数据模型

列定义正本 `sql/schema.sql`，本节只写设计理由。

### 3.1 `station_delivery_config`（站级一行，只存经营参数、不存计算结果）

五组参数：起送量（桶数 / 金额门槛 + 模式 + `FEE` 加收）、配送范围（半径 + 模式 + 远程费）、基础配送费、免运费门槛（桶数 / 金额，取或）、楼层费（免费楼层 / 每层加收 / 计费口径）。

**⚠️ 无行 = 未配置**：代码用 `StationDeliveryConfig.defaults()` 兜底成"全 0、不拦单、只提示"，**存量水站行为与升级前完全一致**；算出来的钱落订单（下单快照），**不落本表**。

### 3.2 坐标与楼层（`station` / `address` 加列）

- `station.lat` / `lng`（`decimal(10,6)`），站长端 `wx.chooseLocation` 选点。**判据：没有站点坐标就无法做距离校验；不能靠"用地址字符串模糊匹配"糊过去。**
- `address.floor`（可空）、`address.has_elevator`（可空，NULL = 未确认）。**⚠️ `has_elevator` 必须可空并区分"未知"与"无电梯"** —— 三种取值对应三种收费结果，压成两态必然在某一侧收错钱。
- **⚠️ 楼层与电梯不在地址解析里**：`miniapp-delivery/utils/address.js` 只做省市区解析（`parseRegion`），与楼层 / 电梯无关。

### 3.3 `orders` / `payment_record` 加费用列（**只加不改**）

`delivery_fee`、`floor_fee`（均 `decimal(10,2) NOT NULL DEFAULT 0`），新口径 `total_amount = water_amount + deposit_amount + delivery_fee + floor_fee`。

**⚠️ 三条硬约束：**

1. **不得塞进 `water_amount`** —— 污染水费口径（水费与退款、报表、对账都相关）。
2. **不得塞进 `deposit_amount`** —— 那是**可退押金**，退款按它释放押金余额，混入运费会导致取消订单时**多退一份运费到客户押金账户**。
3. **必须落在订单上而不是每次重算** —— 与地址快照同一条原则。**⚠️ 地址快照也不含楼层**：`orders` 不要为此加 `floor` / `has_elevator` 列，计费口径已落成 `orders.floor_fee` 这个金额快照。

**⚠️ 写 `payment_record` 必须 `IFNULL(#{deliveryFee}, 0.00)` 兜底**：两列 NOT NULL，而两条写路径（创建支付、在线购票）都不设它们，裸写会把 `NULL` 塞进 NOT NULL 列并报「Column 'delivery_fee' cannot be null」，**整条支付链路全挂**。

**迁移要求**：脚本幂等（`information_schema` 预检 + `PREPARE`）；新列全部可空或带默认值，保证老库补跑后旧订单不炸。

## 4. 接口与权限

### 4.1 计费的唯一入口

纯规则唯一实现在 `util/DeliveryFeeUtil#compute`（只算钱与出提示、不做 IO，可用纯单元测试覆盖）；IO（取配置、站点与地址坐标、算距离）收在 `service/DeliveryFeeService#calcForOrder`。

**⚠️ 报价与下单必须调同一个 `calcForOrder`、传同样的口径**：`PaymentServiceImpl.quote` 与 `OrderServiceImpl.createOrder` 的水费都是 `totalWaterAmount`（**不含押金与费用**），桶数都只数 `category = 1`（桶装水）。**任何一侧内联算费用都会重新制造"计价双轨"**；`blocked` / `blockReason` 由此同源，不会"报价说能下、下单被拒"。

### 4.2 站长端配置端点

`GET` / `PUT /api/manager/delivery-config`（类级 `@RequireRole({"STATION_MANAGER"})`）。**站点取 `AuthContext.requireStationId()`、忽略请求体里的 `stationId`**，否则站长能改别站配置、影响别站客户的订单金额。**没配过时 GET 返回默认配置（全 0、`WARN`、`configured = false`）而不是 404 或空体**，前端可直接渲染表单；**⚠️ 保存刻意宽松**：非法模式值归一化为 `WARN`，**负值一律归零**（负数费用会让 `totalAmount` 变小，属"能少收钱"的输入）。

## 5. 前端落点

- 站长端 `pages/station-mgmt/delivery-config/index`：四组表单，模式文案取后端下发值，未配置时按默认值渲染并提示。
- 顾客端 `pages/address/edit`：楼层（可留空）与电梯（有 / 无 / **不确定**）分开录入，"不确定"必须能选回 `NULL`。
- 顾客端 `pages/order/create`、`order/detail`：费用按后端下发的金额与文案展示；`blocked` 为真时提交前拦住并显示 `blockReason`。
- 配送员端 `pages/home/index`、`order/detail`：各一行楼层信息，文案由 `utils/address.buildFloorText` 统一生成（**只有一处实现**），不确定时整行不显示。

**费用由后端下发文案与金额，前端不自算、不自带映射**（同 `PayMethod` / `OrderStatus` 的铁律）。

**配送员可见楼层（纯读取，没有加列、没有改口径）**：补在三处 —— `Orders` 加关联字段 `addressFloor` / `addressHasElevator`、`OrderMapper.listByDeliveryStaffId` 带出这两列、订单详情在 `DeliveryController` 里按 `address_id` 补读地址。两条判断（`DeliveryFloorVisibilityIntegrationTest`）：**取当前地址的值、不是下单快照**；**`has_elevator` 三态**，只有确认过"无电梯"才说无电梯（把 NULL 说成"无电梯"既误导配送员，也与后端收费口径相反）。

## 6. 验收用例

| 用例 | 锁住的判据 |
|---|---|
| `DeliveryFeeUtilTest` | 默认 / `null` 配置都不收费不拦单；三种模式；桶数与金额取或；距离算不出永不拦单；**免运费两门槛都为空 = 一直收基础配送费**；楼层费四态（有电梯 / 未知 / 没配 / 按桶） |
| `DeliveryFeeIntegrationTest` | **报价 `totalAmount` = 落库 `total_amount`**；没配过的站费用恒 0 且 `total = 水费 + 押金`；`REJECT` 时两侧同源；站点没选点放行；配置 API 三项护栏 |
| `DeliveryFloorVisibilityIntegrationTest`、`DeliveryFeeNonBarrelOrderTest`、`DeliveryFeeFieldsIntegrationTest`、`GeoUtilTest` | 楼层三态不塌成 0 且取当前地址；非桶装只看金额门槛；费用列落库口径；缺坐标返回 `null` |
| `OrderCancelRollbackIntegrationTest`、`PaymentRefundOriginalRouteIntegrationTest`、`ReconciliationAfterNewFeaturesIntegrationTest` | 取消退款释放的 `deposit_amount` **不含**运费；新增费用列后日结仍平 |
