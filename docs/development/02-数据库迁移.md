# 数据库变更指南

写给编写或复核数据库变更的工程师。基线为 sql/schema.sql，适用顺序、执行证据及历史特殊脚本正本为 sql/README.md；本文件不复制另一份迁移列表。

## 1. 新库与存量库

新库导入基线；存量库按实际已安装结构和清单执行增量，不把整库基线当成升级脚本。当前未使用 Flyway，不存在自动版本表帮操作人员决定哪些应执行。

## 2. 编写变更

新建前检索 sql/ 的实际编号，避免按文档最后数字推断。文件说明对象、目的、幂等和危险性，并同步基线及清单。MySQL 不支持的 ALTER IF NOT EXISTS 不能凭语法印象使用，应按现有 information_schema 预检模式及真实验证。

## 3. 验证

使用新建隔离库验证基线、目标脚本及重复执行；保留实际执行输出及前后结构。代码需要的结构先核对完整性，结构成功不等于业务迁移已经正确。

## 4. 破坏性与历史补偿

删表/列、清库、历史回填或补偿先按 AGENTS.md 报证据及影响、备份并等明确确认。不能因脚本名字带 migration 就把所有历史脚本对新库或生产再跑一遍；v63/v64 等升级顺序及已有首版库补偿按清单办理。

## 5. v71 切换

独立权益增量建立凭据，不推断重写旧资产。部署前关闭初次启用开关、装兼容代码、备份及核对、安装结构、核对后启用。开启新业务后保持模型，不能关开关继续按旧规则经营。关闭业务入口和数据模型切换是不同操作。

原批次金额、实收事实、未交付/待退和合作债务保留；历史拿到的桶不重新获得免回资格。完整切换与回退限制见 SQL 清单 v71 节。
