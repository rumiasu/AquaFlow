## 先核对文件与数据库

1. 用清单核对源码提交、JAR与两端小程序。不要使用此前旧ZIP覆盖本批文件。
2. 在数据库工具中先明确选择已核实的库，执行同包 `schema-preflight-v89-readonly.sql`。核对返回的库名、服务器UUID、表、字段和唯一键。只读预检不改数据。
3. 如果 `case_handling_action` 缺失，核对目标后只执行 `migration_v89_case_handling_action.sql` 中那一条 `CREATE TABLE IF NOT EXISTS`。已有表时核对定义，不DROP、不覆盖旧记录、不把“IF NOT EXISTS未报错”当成结构一致。
4. 再执行一次只读预检：应为InnoDB；包含kind/case_id/station_id/actor_id/version/action/reason/idempotency_key/request_digest/create_time等列；两条唯一键分别覆盖 `(kind,case_id,station_id,version)` 与 `(kind,case_id,station_id,actor_id,idempotency_key)`。精确定义以同包迁移为准。

v88及此前迁移依已有清单核对。本轮没有新迁移，**215条演示数据不用重导**；不运行初始化、清库、重置密码或种子脚本。

## 一页核验

- 站长按系统建议补偿：成功后显示最新结果，不再追加执行；模拟断网后只核对原单，勿再次交付补偿。

- 配送员收益：能选历史日期、继续看更早工资单并打开本人明细；他人工资及顾客访问被拒绝。
- 跨站现场问题：提醒与异常进入同一责任站，不增加他站客户资料可见范围。
- 手机检查小屏、放大字体、长数字与姓名地址、键盘、底部安全区及图片失败。源码回归不等同真机视觉验收。
