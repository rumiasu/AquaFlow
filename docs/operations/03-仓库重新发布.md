# 独立仓库重新发布

写给仓库所有者，说明本次 Git 整理的边界和之后的上传步骤。

## 1. 本次选择

用户已选择独立目录生成新历史。原工作区、原 `.git`、未提交内容和旧远程都保留；没有对旧分支执行 reset、过滤历史、删除或强推。此前单提交副本保留；用户随后授权依据真实旧提交归并历史并上传重建的远程。发布仓库在 `main` 上形成整理后的阶段记录，不直接承接旧 Git 对象，原作者日期与实际整理日期分别记录。

当前交付路径为原工作区 `build/repository-publication/AquaFlow-complete-history`，此前 `AquaFlow` 单提交副本保留。该路径处于本机忽略目录，需作为一个独立仓库打开。旧历史 bundle、导出清单及检查结果放在相邻的交付目录，均不在新仓库可上传树中。它是本地交付路径，不是要求克隆者具备的目录。

## 2. 文件边界

保留当前源码、SQL 基线及历史增量、测试、CI 输入、现行文档和明确的历史审计材料。迁移脚本是存量库升级依据，不能因为 Git 换新历史而删掉。

不导出本机配置、真实凭据、构建产物、缓存、备份、机器记忆和本地审计临时文件。源仓库 `.git/info/exclude` 的本机排除规则保留在新仓库同位置，不发布为项目配置。对这些路径的历史记述不是克隆后存在的文件承诺。

本次新历史是仓库整理，不代表凭据轮换、生产发布、真机验收或全部业务决策完成。各项边界仍见 [SECURITY](../../SECURITY.md) 和[范围决策](../design/16-范围决策与实施路线图.md)。

## 3. 重建的 GitHub 与上传

用户已重建 `https://github.com/rumiasu/AquaFlow.git` 并授权上传。操作针对上述独立历史仓库，用户随后要求覆盖所有历史线，并将作者和提交日期都对齐原记录。本次先备份上一版，再用精确远端提交号的 force-with-lease 替换；远端若有他人新提交立即停止。历史阶段与来源见 [整理说明](04-历史提交整理说明.md)。

```powershell
git remote add origin git@github.com:rumiasu/AquaFlow.git
git push --force-with-lease=refs/heads/main:<本次核对的远端提交号> -u origin main
```

历史替换和上传由本次修正授权办理，实际结果以远端分支核对为准。上面租约值必须来自本次远端核对，不能照抄旧值。GitHub 删除及重建由用户自行完成。

## 4. 可复核范围

导出按 Git 的跟踪文件和非忽略新文件筛选，而不是复制整个工作目录。交付清单记录路径及摘要。新仓库检查发布输入、文档链接及契约门禁，再从新提交克隆一次核对文件一致性。静态凭据筛查有局限，不能据此声称生产环境已经安全验收。


## 5. 本机交付路径与验证

本机交付目录位于 build 下。当前待拍板扫描器按绝对路径排除 build，因此在那里可能空扫描；验证应在不含 build 的实际克隆目录运行，并核对扫描文件数和源码标记数。空扫描不作为通过证据。新克隆没有构建 XML 时，矩阵运行件数检查会明确跳过，不能宣称重新执行过测试。
