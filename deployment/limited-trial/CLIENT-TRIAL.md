# 甲方单站六条体验操作稿（一页）

这是具名人员、小范围合成业务体验，不是真实经营或收退款。两端体验入口由负责人交付；使用正常微信登录，不需开调试、装额外软件或改变网络。打不开或身份/站别不符时停止该步骤并反馈，不自行换环境。

准备：指定一间“合成试用水站”、客户一名、站长兼配送一名、另一配送员按需；有可用库存、合法地址、已获本站现金权限的客户，以及来源明确的合成桶票资产。由获准操作者按既有准备方式办理，不拿真实库/真实余额冒充夹具。不开模拟微信、不实际收取或退还钱；不触发真实支付。未准备好资产的项目标未测，不用新交押金绕过。

| 操作 | 体验人员要看什么 | 通过后保留的最少反馈 |
|---|---|---|
| 1. 客户用票/COD下单 | 选本站、商品和地址，核对费用与本次需付；已备票场景用票，或用已开通COD。票不足不混付，未知结果先查原单，勿连下多单。 | 订单编号、所选方式；票使用不说成新收现金。不能正常报价则记阻塞。 |
| 2. 员工配送 | 用正确员工身份看派给自己的单；核对备货、接单、实际合成回桶数量并完成。缺货按提示处理，不把缺货单硬完成。 | 同一订单在客户/员工端的末态、数量是否一致。仅合成账务登记。 |
| 3. 客户资产与退桶 | 查看本站容量/票/押金，使用已准备的合成闲置容量申请退还；未领桶不交桶，免费原安排不需再次确认；新费用/站方新安排才作必要授权。 | 申请编号及安排；实际交接与退款状态分清。真实渠道退款不操作、不称已测。 |
| 4. 本站查看与返回 | 从订单/资产进入详情再返回，核本站、对象、金额和列表刷新；重开仍应看到原记录。 | 哪一页返回后对象或状态不对；不修改存储来掩盖问题。 |
| 5. 站长兼配送 | 用站长本人处理本站允许自接的合成单，完成接单/配送；核对无需另建假配送员绕权限。 | 实际角色、站名、订单编号与结果；不要发送令牌。 |
| 6. 异常与重试 | 正常操作中若断网/超时，恢复网络后核原记录再重试；可在不涉及真实资金的已安排样本中验证。不要反复点击制造多单，也不强求现场制造故障。 | 当时提示、前后结果、是否恢复原单；未发生则标“未测”。 |

统一反馈格式：步骤号／端与角色／订单或申请编号／预期／实际／发生时间；截图避免电话、地址与凭据。体验负责人负责处理剩余合成待办与暂停入口，不向客户追加“必须确认所有收尾”的义务。服务资格、主体资料和真实售后责任不由这张试用稿裁定。
