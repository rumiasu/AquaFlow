## 1. 目的与范围

本文定义**水票档位套餐**（站级定价结构）与**水票批次单价**（余额与单价的真相源）。范围外：营销引擎（满减 / 优惠券 / 活动叠加 / 优先级 / 退款摊分）、配送费实体本身（见 [17-配送计费与配送范围.md](17-配送计费与配送范围.md)）。

**不做通用促销引擎**：1 张散买按 `inventory.ticket_price`，10 / 20 / 100 张一组给更低的均价。档位是**站长挂出来的固定价目表**，永远可买、不叠加、不互斥——这是「定价结构」而非「促销活动」，所以不需要活动引擎。

## 2. 设计口径

| 判据 | 说明 | 违反的后果 |
|---|---|---|
| **余额真相源是 `ticket_lot`** | `ticket_account` 只是派生汇总：`remain_quantity == Σ lot.remain_qty`、`right_amount == Σ remain_qty × unit_price` | 只改汇总会漂移，由对账 E8 抓出 |
| **批次唯一写入口是 `TicketLotService`** | `createLot` / `consumeFifo` | 别处直接写批次表 = 绕开批次账 |
| **单价取实付均价** | `payment_record.amount / ticket_qty`；拿不到付款依据时按当时站级水票价并标记为推断值 | 均价失真 → 退票金额错 |
| **消耗按 FIFO** | `TicketLotMapper#listUsableFifo` 按 `id asc`，先买先扣 | 「退票退的是哪一批」各处理解不同 |
| **退款按流水里的当时单价还原** | 回补批次的单价取自 `ticket_record.unit_price`（跨批次时为加权均价，4 位小数） | 按当前价退还 = 改价改到客户已付过的钱 |
| **任何改动水票数量的路径都必须过批次账** | 在线购票入账、站长加票、用票支付、订单取消回补、资产调整单 | 漏一条 E8 就报不平 |
| **档位是站级的，不是全局的** | 与 `inventory` 站级定价、`ticket_account` 按站隔离一致 | 全局档位会让 A 站买的票在 B 站有价差 |

三条前提：水票价是**单张价、站级配置**（`inventory.ticket_price`，经 `PriceUtil#calcUnitPrice` 取值），`product.ticket_price` 是**历史列、实际恒为 0**；水票**无有效期**；**赠送水票没有正式入口**——`ticket_record.source` 的「赠送」只有语义位，实际写入口是购买 / 消费 / 退款 / 人工调整。

**参照物**：`customer_barrel_lot` 已实现「批次单价快照」——`unit_price`（买入时快照，「2026 年 30 元买的，2027 年退就退 30 元」）、`remain_qty`、`source_type`、`price_source`、`is_migrated`。水票档位是同一类场景，**照抄桶的批次模型，不要另发明一套**。

## 3. 数据模型（只写设计理由，DDL 见 `sql/schema.sql`）

**`ticket_package`（站级档位表）**：`station_id` / `product_id` / `qty` / `price`，唯一键 `uk_ticket_package(station_id, product_id, qty)`；`unit_price` = `price / qty` **落库冗余**（用于快照与展示，不要每次相除）；`title` 展示名（可空则按张数生成）；`status` 上架 / 下架；`sort` 排序。提案里的 `bonus_delivery_count` **未落地**，见 §5。

**`ticket_lot`（水票批次）**：字段与 `customer_barrel_lot` 对齐——`lot_no` / `customer_id` / `station_id` / `product_id` / `unit_price` / `qty` / `remain_qty` / `source_type` / `price_source` / `is_migrated` / `payment_record_id` / `status` / `operator_id` / `note`。`lot_no` 形如 `TMyyyymmdd-000001`，与押金条 `DP` 同款：先插占位号，拿到自增 id 后改正式号。

**三处标识列**

- `payment_record.ticket_package_id`（可空）——**档位价格会变**。历史流水若只记「买了 100 张、收了 800 元」，几个月后无法自证当时是哪个档位，也就无法解释「为什么这 100 张均价 8 元而现在均价 9 元」。与 `orders.deposit_amount`、`customer_barrel_lot.unit_price` 是同一条快照原则。
- `ticket_record.unit_price` + `ticket_lot_id`——让流水自证单价来源。`ticket_lot_id` 仅当该笔变动只涉及一个批次时有值，跨批次为 NULL（此时看 `unit_price` 的加权均价）。
- `ticket_record.account_product_id` **已撤回**：它曾用于记「这一笔扣的是哪个账户」（统一票原先是 `product_id = 0` 的独立账户）。口径改为「统一的是**折扣率**、价格按各款水自己的票价折算」之后，**订单行商品与扣票账户恒等**，该列已由破坏性迁移 `sql/migration_v59_drop_ticket_account_product.sql` 删除（先上代码再执行 SQL；脚本自带「列内有值就中止」护栏）。统一折扣档位现状见 `sql/migration_v58_station_ticket_discount.sql` 与 [26-水票两方案评估.md](26-水票两方案评估.md)。

## 4. 在线购票必须带客户端幂等键

**漏洞本体**：`payment_record` 的防重靠生成列 `active_order_id`（仅当 `status in (1,2)` 时等于 `order_id`）加唯一键 `uk_payment_active_order`；在线购票的 `order_id` 是 NULL → `active_order_id` 也是 NULL → **MySQL 唯一键中 NULL 互不冲突 → 这条路径零保护**（与 `uk_ticket_consume` 在 `order_id IS NULL` 时零保护同形）。**后果**：客户连点两次「买 100 张票」→ 两笔 PENDING 流水 + 两次入账，站长端「待确认收款」出现两条几乎一样的记录，**很可能两条都确认**。

| 判据 | 落地要求 |
|---|---|
| 唯一键 | `uk_payment_idempotency(customer_id, idempotency_key)`——**带上 `customer_id` 是必需的**：只按 token 唯一的话，传别人的 token 会拿回别人的支付记录（跨客户泄露） |
| 幂等键 | `POST /api/tickets/purchase` 的 `idempotencyKey` **必传**（缺 / 空串 / 纯空白一律 `code = 1`）。设成必传而非可选：「可选」等于默认没有保护，漏传的代价是重复入账 |
| 命中时机 | 幂等判定放在**所有业务校验之前**——已成功建过流水后，站长即使关掉水票开关或改价，重放也应返回原流水 |
| 并发 | 真并发由唯一键兜底；捕获 `DuplicateKeyException` 后**抛出**而不是吞掉（本方法在事务内，吞掉会让 Spring 抛 `UnexpectedRollbackException`，把并发拒绝伪装成 500）；客户端用同一个 key 重试即命中幂等分支 |
| 金额后果 | 用例断言的**不是**「流水条数」而是「确认收款后水票只多一份」——流水条数只是手段 |

迁移 `sql/migration_v33_payment_idempotency.sql`；用例 `TicketPurchaseIdempotencyIntegrationTest`（`keyIsScopedByCustomer` 锁跨客户泄露、`concurrentSameKeyCreatesOnePayment` 锁并发只建一笔）。

## 5. 规则设计

**退票按批次单价退，与退押金同口径**。`PriceUtil#calcDeposit` 的注释已把这条原则写死：退押金一律按 `customer_barrel_lot.unit_price`（买入时快照）结算，**不要**调本方法重算，否则改价会改到客户已经付过的钱。水票退票沿用同一口径：按 `ticket_lot.unit_price` 退，不退现金而退到水票账户或按站长规则。是否允许退票由站长可配（现实中大量水站「票不退不换」），但**只要允许退，就必须按批次价退**；`is_migrated = 1` 的批次单价是推断值，**退票需二次确认**。

⚠️ **「买得多免几次配送费」不能做成配置里的布尔开关**。「免 N 次配送费」本质是一种**客户资产（次数账户）**，与水票 / 押金同类，需要账户 + 流水 + 幂等 + 有效期 + 对账；做成画像上的一个勾会出现「站长说还有 3 次、客户说还有 5 次」的扯皮。正确形态是次数账户 + 流水表（赠送记 `+N`、抵扣记 `-1`、唯一键防重），且**有前置依赖**：得先有「配送费」这个实体（见 [17-配送计费与配送范围.md](17-配送计费与配送范围.md)）。**已定取舍：只做「档位单价便宜」，「免配送次数」单独切一期**——前者纯属定价，后者是新的资产账户，风险高一个量级。

**档位与散买共存**：`inventory.ticket_price` 继续作为散买单张价，档位是「批量更便宜」；`PriceUtil` 的取值阶梯不变（站级覆盖 → 通用库参考值），**档位不走 `PriceUtil`**（它不是单价，是套餐）。**判据：不要让 `PriceUtil` 开始认「数量」参数**——它的职责是「单价 / 押金」，一旦引入数量维度，所有调用点都要重审，那正是「计价双轨」事故的入口。

## 6. 批次账的并发与状态判据

⚠️ **`TicketLotMapper#decrementRemain` 的 `status` 赋值必须排在 `remain_qty` 前面**，不要顺手调换：MySQL 的 `SET` 从左到右求值，后面的表达式看到的是**已更新后**的列值。写成 `set remain_qty = remain_qty - q, status = case when remain_qty - q = 0 ...` 时 CASE 里的 `remain_qty` 已是 0，算出 `-q`，永远不等于 0——**批次扣光了状态也停在「有效」，永不置为「已退完」**（实测表现：断言 `status = 2` 却拿到 1，极易误判成「扣减没生效」）。

⚠️ **判断与扣减必须在同一条 SQL 里完成**，条件带 `remain_qty >= qty`，且**调用方必须检查返回值**：本仓在并发桶账上踩过「普通 SELECT 读到旧快照、两个事务双双通过」的坑（`aquaflow-known-traps` §8.2）。返回 0 表示被并发改过，应跳过该批次继续往后找，而不是当成失败。

**批次不足要出声**：`consumeFifo` 扣完仍有缺口时抛 `BusinessException`——正常流程不该走到这里（调用方先用 `ticket_account.remain_quantity` 校验），走到这里说明批次与账户余额已经不一致（正是 E8 要抓的），宁可失败出声也不要静默少扣。跨批次消耗写流水用**加权均价（4 位小数）**，只留 2 位会在部分退款时累积舍入误差。**夹具必须建批次**：`createTicketAccount` 若只插账户不建批次，会打红既有用例。

## 7. 对账等式 E8

```
E8: ticket_account.right_amount    == SUM(ticket_lot.remain_qty × ticket_lot.unit_price)
AND ticket_account.remain_quantity == SUM(ticket_lot.remain_qty)
```

与 E3（权益汇总 vs 押金条批次）同构，判定分两半：汇总错、有批次无汇总（`ReconciliationService#dailyReconcile` 的 `E8_ticketBalanceVsLot`）。**告警分级**：按 `constant/AlertType`，账目不平属**系统故障** → `SYSTEM`（`station_id` 必须为 NULL），与 E3 / E5 同级，**不要投给站长**。

## 8. 接口与权限

| 方法 | 路径 | 角色 | 站点归属校验 | 说明 |
|---|---|---|---|---|
| `GET` | `/api/ticket-packages` | 无鉴权（同其它公开商品接口） | 显式传 `stationId` + `productId` | 返回**这一款水**的档位，可能是定制档位或站级统一折扣，用 `source` 区分；判据唯一实现在 `TicketTierService#customerTiers` |
| `GET` | `/api/ticket-packages/manage` | `STATION_MANAGER` | 站点取自 `AuthContext`，忽略请求参数 | 本商品全部**定制**档位（含已下架）；统一折扣档位走 `/api/ticket-discounts` |
| `POST` | `/api/ticket-packages` | `STATION_MANAGER` | 站点取自 `AuthContext` | 按 `station + product + qty` upsert；`unit_price` 由**服务端**用 `price / qty` 推导 |
| `DELETE` | `/api/ticket-packages/{id}` | `STATION_MANAGER` | `ticketPackageMapper.delete(id, stationId)` | 0 行 = 业务错误 |
| `POST` | `/api/tickets/purchase` | 顾客 | 身份取自 `AuthContext` | `idempotencyKey` 必传，见 §4 |

**站点一律取自 `AuthContext.requireStationId()`**：否则站长能改别人站的档位，进而影响别人站客户的购票价。

## 9. 前端落点

**档位必须出现在站长的必经路径上。** 只做独立模块页（`miniapp-delivery/pages/station-mgmt/ticket-packages/`）时，站长的实际感受是「水票还是按张卖」——他上架商品时配的是「推出水票 + 水票价格(元/张)」，档位那页不在必经路径上。改法：**基本档位就地配，更多设置才跳独立模块**。

- **就地入口**：商品上架 → 「本站设置」（及自定义商品弹窗）里，打开「推出水票」后多出一块「水票档位（成组更便宜）」：每行填「张数 + 总价」，保存时与本站设置**同一次提交**落库；新建自定义商品用 `POST /api/manager/my-products` 返回的 id 挂上去。
- **清空总价 = 删除该档位**（界面已写明），另有显式「删除」；已存在的档位只标记、保存时才真删，再点一次可撤销。
- 独立模块保留档位标题、排序、单档上下架这类「进一步丰富」的设置。
- ⚠️ **必须写明「没挂档位时客户只能按单张价买」**——否则站长会以为打开开关就自动有档位。
- ⚠️ **金额口径不变**：`unit_price` 仍由**服务端**用 `price / qty` 推导，前端不传、也不显示自己算的均价（它是快照进水票批次的值）。前端自己算一遍就会出现「界面一个价、批次另一个价」（`TicketPackageController#save` 的注释已点名这个风险），所以站长端在**保存之后**才显示均价。
- ⚠️ **顾客端改张数要自动退回散买**：后端校验 `quantity === pkg.qty`，张数一变档位价就不再适用；留着 `packageId` 提交会被以「购买张数与档位不一致，请重新选择」拒回。与其让客户撞一次错误，不如在改数量的那一刻就退回散买并把单价换回单张水票价。

**删除档位的两条护栏**（用例 `deletePackageGuardsStationAndKeepsSoldTickets`）：① 传别人的档位 id 删不掉（`delete(id, stationId)` 校验归属，0 行 = 业务错误）；② **删档位只动价目表，不动已售出的票**——票的价值由 `ticket_lot.unit_price` 快照记着，删掉档位后客户账上的余额与价值必须一张不少（用例直接断言 `remain_quantity` 与 E8 仍成立）。这条 DELETE 在快捷配置上线后从「只有接口」变成「界面天天点」，必须有覆盖。

## 10. 迁移与验收

**迁移 `v36`**：建 `ticket_package` 与 `ticket_lot` 并**回填**——现有 `ticket_account.remain_quantity` 必须生成对应的 `ticket_lot` 批次行，单价按 `inventory.ticket_price` 当时值推断，标记 `source_type = 2 历史迁移` / `is_migrated = 1`（单价为推断 → 退票需二次确认）。做法照抄桶账的回填脚本（见 [sql/README.md](../../AquaFlow-backend/sql/README.md)）。回填脚本**必须跑在真实库**并在测试库先验证：本仓记录过「测试库全绿但真实库不可用」的事故（`aquaflow-known-traps` §8.12），涉及唯一键的改动尤其要看真实库的 `information_schema.STATISTICS`。

| 用例 | 锁住的判据 |
|---|---|
| `TicketPurchaseIdempotencyIntegrationTest` | 同一 `idempotencyKey` 连提两次只产生一笔流水、只入账一次；key 按客户隔离；缺 key 被拒 |
| `packagePurchaseSnapshotsPaidUnitPrice` | 批次单价 = **实付均价**；`payment_record.ticket_package_id` 落库 |
| `packageGuards` | 张数不一致 / 跨站 / 档位不存在三种拒绝 |
| `consumeIsFifoAcrossLots` | 跨批次消耗按 FIFO 依次扣减，批次扣完状态转「已退完」 |
| `addAndConsumeKeepLotBookConsistent` | 加票与扣票都保持批次账一致（E8 成立） |
| `deletePackageGuardsStationAndKeepsSoldTickets` | 删档位只动价目表，已售出的票一张不少 |

另需成立：站长改档位价后**已购批次的 `unit_price` 不变**（快照生效）；站间隔离——A 站买的票不在 B 站可见 / 可用（沿用 `ticket_account` 唯一键）。
