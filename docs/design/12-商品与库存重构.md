## 1. 目的与范围

重构前，商品是"全平台一张表"：任何站长都能建、能改、能停用所有水站共用的商品，本站售价在 DTO / VO / 表三处都不存在（前端填了也不落库），"改库存"还能绕过库存流水。本文规定重构后的模型：**平台方维护通用商品库，站长只配置本站**（上架 / 库存 / 售价 / 押金 / 水票 / 优先展示），自定义商品作为本站私有补充并允许上报通用库。

范围内：`product` / `inventory` / `inventory_record` / `product_submission` 四张表的口径，单价与押金的唯一计算入口，站长端与顾客端的端点、可见性判据与页面落点。范围外：水票档位与批次单价；配送计费；平台侧运营界面 —— 本仓没有平台端，通用库由开发者以 SQL / COS 维护。允许必要的接口替换与前端页面重做，不追求"最小改动"。

## 2. 设计口径

### 2.1 产品口径

| # | 约束 | 判据 / 违反表现 |
|---|---|---|
| 1 | 平台方维护**通用商品库**，站长只做"选品" | 站长打开商品页第一眼是**选项列表**（选什么水），而不是空白表单 |
| 2 | 通用库商品的名称 / 规格 / 图片 / 描述对站长**锁死** | 站长能改的只有本站项：上架 / 库存 / 本站售价 / 本站押金 / 水票开关与价格 / 优先展示 |
| 3 | 只有**自定义商品**能改名称 / 规格 / 图片 / 描述 | `CatalogServiceImpl.updateMyProduct` 先 `getOwnedById` 验归属；通用库商品走到这里即报"商品不存在，或不是本站自定义商品" |
| 4 | 自定义商品**不入通用库** | `owner_station_id = 本站`，仅本站可见可用；站长可上报，由开发者人工补进通用库 |
| 5 | 历史订单与历史桶权益**继续用快照** | 改价只影响之后新产生的订单与批次；退桶金额按批次买入单价 |
| 6 | 站级价**不做强制护栏**，超出只给提醒 | 偏离参考价超阈值 → 响应 `warnings`，**保存照常成功** |
| 7 | 只做本站级，**站长之间严格隔离** | 没有"平台停售影响所有站"这类动作；站长的任何界面都不出现"平台停售"概念 |
| 8 | 上架但 0 库存**仍可下单** | 语义是"暂时没货，需要等待配送"；下单响应带 `warnings`，而不是拒绝 |
| 9 | 站长的商品写入口只有两个 | `/api/manager/catalog*`（本站设置）与 `/api/manager/my-products*`（自定义商品） |

`product.status` 只是**开发者维护目录时的数据位**（撤掉某个选品），不是站长的经营动作。但通用库商品被下架后，**本站已选用**的行仍然可见（否则站长只能看着库存却找不到入口），只是不能再改配置 —— `saveStationSetting` 报"该商品已被开发者下架，无法在本站配置"。

**本站没有 `inventory` 行不得下单，也不得自动补建**。下单流程里曾经有一段"本站没有 inventory 行就自动补建（`quantity = 0, enabled = 1`）"的代码，是上膛的枪：它让"本站没上架的商品"凭空变成可售。现在该分支改为抛业务异常，并由用例锁住。

### 2.2 计价与金额口径

| 金额 | 唯一入口 | 阶梯 |
|---|---|---|
| 单价（零售 / 水票） | `util/PriceUtil#calcUnitPrice(product, inventory, paymentMethod)` | 水票：`inventory.ticket_price > 0` → `product.ticket_price > 0` → 站级售价 → `product.price`；其余：`inventory.sale_price > 0` → `product.price` |
| 押金 | `util/PriceUtil#calcDeposit(product, inventory)` | `inventory.deposit_price > 0` → `product.deposit`；**非桶装商品一律返回 0**（品类判据的唯一实现在 `util/BarrelScope`） |

**⚠️ 覆盖判定统一为「非空且 > 0」**：留空或填 0 都表示"用通用库参考值"。这不是风格问题 —— `customer_barrel_lot.unit_price = 0` 会被 `BarrelLedgerService#resolveUnitPrice` 按 [DEF-2] 当成"无快照"而回退到商品押金，即**"免押金"在当前桶账模型下表达不出来**。前端"清除覆盖"用显式的 0 表达，后端由 `CatalogServiceImpl.pickPrice` 归一化为 NULL（三态：`null` = 保持原值，`<= 0` = 清除覆盖，`> 0` = 设为该值）。

**⚠️ 不允许出现第 4 处自成一体的计价**。报价（`PaymentServiceImpl.quote`）、下单（`OrderServiceImpl.createOrder`）、买水票（`TicketAccountServiceImpl`）、员工端水票价值展示、批次单价来源（`BarrelLedgerService`、`BarrelAssetServiceImpl`、`StationAdjustmentServiceImpl`）必须全部走上面两个入口。

**押金的写侧校验必须与读侧同向**（`CatalogServiceImpl`）：桶装水必须设 > 0 的押金（没押金 = 桶白送，与桶账模型冲突）；非桶装**不许**有押金（押金是循环桶的押金，非桶装不建押金条 → 收了退不出）。只靠读侧会变成"站长填了、系统不认、还不报错"，那是本仓最忌讳的静默不一致。

### 2.3 快照口径（改价不影响历史，必须保持不变）

- 下单时快照：`order_item.price/deposit/subtotal`、`orders.water_amount/deposit_amount/total_amount`、`customer_barrel_in_transit.unit_price`（本站押金）。
- `customer_barrel_lot.unit_price` 必须继续**优先取 in_transit 快照** —— 它直接决定退桶能退多少钱。**⚠️ 退押金一律按 `lot.unit_price` 结算，不要调 `calcDeposit` 重算**，否则改价会改到客户已经付过的钱。
- `ReconciliationService` 的对账口径（`Σ lot.remain_qty × unit_price`）本来就与当前押金解耦，**不要改回去**。
- **唯一的调价泄漏点**：`BarrelLedgerService#resolveUnitPrice` 的第三级兜底（无快照的老 / 迁移数据）读的是当前押金 —— 该兜底必须取**本站押金**；`customer_barrel_lot.is_migrated = 1` 的批次退款继续走"二次确认"。

### 2.4 展示口径

| 场景 | 口径 |
|---|---|
| 商城 / 商品详情 / 下单页 | 后端下发**本站有效价** `effectivePrice` / `effectiveDeposit` / `effectiveTicketPrice`，前端不自己拼价 |
| 订单详情 / 支付流水 | 用订单快照（`order_item.price`、`orders.*`） |
| 桶权益"可退金额" | 用批次快照（`customer_barrel_asset.right_amount` = `Σ lot.remain_qty × lot.unit_price`） |
| 概览类"押金合计" | **批次快照口径**：权益部分 `Σ customer_barrel_asset.right_amount` + 配送中部分 `Σ customer_barrel_in_transit.unit_price × qty`；无快照的历史行才回落当前本站押金 —— 站长调价不再改变客户"已经付过的钱" |

### 2.5 站级价提醒（不阻断）

保存本站售价 / 押金时若偏离通用库参考价超过阈值 → 响应带 `warnings`，**保存照常成功**。阈值取配置项 `catalog.price-warn-ratio`（默认 `0.5` = ±50%）；参考值为 0 或 NULL 时不提醒（此时"偏离比例"没有意义）。该提醒与既有的"欠桶提醒 `warnings`"同构，前端以**非阻断**提示展示，不得当失败处理。

## 3. 数据模型

### 3.1 三个层次

```
通用商品库 product（owner_station_id IS NULL，开发者 / 运维维护，站长只读）
        │  ← 站长"选用"
        ▼
本站设置 inventory（station_id + product_id 唯一，一行 = 本站对某商品的全部可售信息）
   ├─ enabled          本站是否上架
   ├─ quantity         本站库存（唯一写入口 InventoryService，必须落 inventory_record 流水）
   ├─ sale_price       本站售价（NULL → 回落 product.price 参考价）
   ├─ deposit_price    本站押金（NULL → 回落 product.deposit 参考押金）
   ├─ ticket_enabled   本站是否开水票
   ├─ ticket_price     本站水票价（> 0 生效；NULL / 0 → 回落 product.price）
   └─ priority_display 优先展示

自定义商品 product（owner_station_id = 本站，完整可编辑，仅本站可见）
   └─ 同时自动建一行本站 inventory（与通用库商品走完全相同的可售模型）
   └─ 站长可上报 → product_submission（开发者人工补进通用库）
```

**「优先展示上限 3」的正本**是 `CatalogServiceImpl.MAX_PRIORITY_DISPLAY = 3`：保存分支里已达上限即抛业务异常；切换到自己时先把自身排除，否则"已经是第 3 个"会被自己顶掉。旧控制台类 `ManagerProductController` **已删除**，引用前先认类名。

### 3.2 v31 的变更

全部为**新增可空列 / 新增表**，不改既有列类型与含义，不动存量数据。

| 对象 | 变更 | 语义 |
|---|---|---|
| `product.owner_station_id` | 新增 `bigint NULL` + `idx_product_owner_station(owner_station_id, status)` | NULL = 通用库；非 NULL = 该站自定义 |
| `product.preset_uk` | 新增 STORED 生成列 + `uk_product_preset` | 通用库行 = `名称\|品牌\|规格`，自定义行 = NULL → 防通用库重复录入 |
| `product.station_uk` | 新增 STORED 生成列 + `uk_product_station` | 自定义行 = `站号:名称\|品牌\|规格`，通用库行 = NULL → 防同站重复自定义 |
| `inventory.sale_price` / `deposit_price` | 新增 `decimal(10,2) NULL` | 站级覆盖值；NULL = 用 `product` 上的参考值 |
| `product_submission` | 新增表 | 自定义商品上报登记（`status` 0 待处理 / 1 已纳入 / 2 已驳回） |

表结构与列定义的正本是 `sql/schema.sql`，本文不复述 DDL。

**⚠️ 为什么用生成列**：`owner_station_id` 可空，而 MySQL 唯一键中 NULL 互不冲突 → 普通 `UNIQUE(owner_station_id, name, spec)` 对"通用库行"零保护。生成列表达"条件唯一"是本仓已验证的手法（先例 `payment_record.active_order_id`）。

**⚠️ 去重键必须含品牌**：生成列原为 `名称|规格`，会把"同名同规格不同品牌"的选品判重（桶装水很常见）。键必须是 **名称|品牌|规格**。

**⚠️ 不拆表**：`product.id` 被 `order_item` / `orders` / `barrel_record` / `customer_barrel_*` / `ticket_*` / `inventory_record` / `station_adjustment` / `order_barrel_exception` / `order_template_item` 等业务表，以及 7 个含 `product_id` 唯一键的锚点引用。物理拆出第二张商品表会让这些引用的 id 语义分叉（历史行对不上新表），运维与对账都会变痛苦。**"不入通用库"是查询口径，不是物理分表。**

**⚠️ 不要用 `inventory` 承载"平台默认库存"**：`inventory.station_id` 可空，而唯一键含它 → NULL 行可重复；平台默认值一直在 `product` 上。

**存量回填**：v31 **不自动回填**归属 —— 现有 `product` 行没有 creator 字段，无法判断当初是哪个站长建的。一律保持 NULL（= 通用库）；确应归某站私有的行只能手工 `UPDATE`。

**`inventory.ticket_price` 为 `NOT NULL DEFAULT 0`**（与新增的两个可空列风格不一致）**保留现状**：`> 0 才生效`的语义已由 `PriceUtil` 固化，改列类型收益低、风险高。

## 4. 接口与权限

### 4.1 权限与可见性

| 对象 | 顾客 | 配送员 | 本站站长 | 别站站长 | 开发者（SQL） |
|---|---|---|---|---|---|
| 通用库商品（读） | 仅本站已上架 | 仅本站已上架 | 全部（用于选品） | 全部（用于选品） | 全部 |
| 通用库商品（写 name / spec / 图片 / 描述 / status） | ✗ | ✗ | ✗ | ✗ | ✔ |
| 本站自定义商品（读 + 写全部字段） | 仅本站已上架 | 仅本站已上架 | ✔ | ✗ | ✔ |
| 本站 `inventory`（上架 / 库存 / 价格 / 水票 / 优先） | ✗ | ✗ | ✔ | ✗ | ✔ |
| 别站 `inventory` | ✗ | ✗ | ✗ | ✗ | ✔ |
| `product_submission` | ✗ | ✗ | 只写只读自己的 | ✗ | ✔ |

**顾客端可售判据**（`ProductMapper.listSellableByStationWithInventory`）：`inventory.enabled = 1 AND product.status = 1 AND (product.owner_station_id IS NULL OR = 本站)`。该查询**不要加 `distinct`**：`inventory` 上有唯一键 `(station_id, product_id)`，join 不可能产生重复行，而 MySQL 对"`SELECT DISTINCT` + `ORDER BY` 非选择列表列"直接报 3065。

**站长端选品列表可见性三条，缺一不可**（`CatalogServiceImpl.listCatalog`）：① 本站自定义商品（`ownerStationId` 非空）始终可见，平台下架管不到它；② 通用库商品须 `status = 1`；③ 例外 —— 通用库商品虽已下架但**本站已选用**（`inventoryId` 非空）仍可见。若一刀切按 `status = 1` 过滤，站长就会看不到自己已选用的商品、无法再管库存与站级价。

**详情接口可见性**（`ProductController`）：通用库商品在售（`status = 1`）即可见；本站自定义商品必须带对 `stationId`；下架 / 停售一律不可见，统一按"商品不存在"处理 —— **不透露"这个 id 存在但属于别人"**。该端点此前不带站校验，一旦有自定义商品就是跨租户泄露通道。

**⚠️ 归属校验**：所有"按 id 操作"的站长端点必须逐条验证 `owner_station_id` / `station_id`，并检查 affected 行数；拿不到行数就不要返回成功（判据见 `AGENTS.md`）。

**⚠️ 商品图片必须由后端统一注入**：`image_object_name` 有两种口径 —— 本地资源路径（`/assets/product/xxx.webp`，原样下发）与 COS 对象键（签成临时 URL）。前端只认 `imageUrl` 一个字段，翻译只有一处实现 `util/ProductImageResolver#resolve`（站长端两个列表共用 `CatalogServiceImpl#withImageUrls`）。**漏了这一步的表现是"图片全空"而不是报错**，最容易被当成前端问题。写入侧同理：`CatalogServiceImpl.pickImageValue` 只接受对象键、或以 `/` 开头的本地路径 —— 上传接口返回的是预签名 URL，直接当对象键落库会让商品图**即使配好 COS 也永远不显示**；此时宁可存 null（半坏的图比明确的"无图"更难排查）。可选项的正本是 `constant/ProductImageKeys`。

**⚠️ `categoryText` 由后端下发**，前端只保留"表单下拉选项"这一个数组，禁止自带展示映射表（两端各写一套映射曾导致下单 100% 失败）。

### 4.2 站长端端点

类级 `@RequireRole("STATION_MANAGER")`；站点一律取 `AuthContext.requireStationId()`，**忽略请求体里的 stationId**。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/manager/catalog` | 选品列表：通用库 + 本站自定义，带本站状态 |
| GET | `/api/manager/catalog/preset-images` | 平台预设商品图清单 `[{key, path}]`，前端可直接当 `src` 用 |
| POST | `/api/manager/catalog/{productId}/select` | 选用：upsert 本站 `inventory` 行并返回 `warnings`；**默认未上架**（选了不等于开卖） |
| PUT | `/api/manager/catalog/{productId}` | 更新本站设置（patch：未传字段保持**当前行原值**，传 `<= 0` 清除价格覆盖，**绝不落 0**） |
| DELETE | `/api/manager/catalog/{productId}` | 移除本站配置：仅当 `quantity = 0`，否则报"请先盘点为 0"（带库存删行 = 库存数与 `inventory_record` 断链） |
| POST | `/api/manager/catalog/{productId}/stock` | 盘点：库存设为 `target`，差额写 `ADJUST` 流水并返回 `delta`；入库走 `POST /api/inventory/inbound` |
| GET | `/api/inventory/records` | 本站库存流水 |
| GET / POST | `/api/manager/my-products` | 本站自定义商品列表 / 新建（自动建本站 `inventory` 行） |
| PUT / DELETE | `/api/manager/my-products/{id}` | 编辑 / 停用（软删 `status = 0`，物理行保留，历史订单 / 桶账 / 水票的引用不断） |
| POST | `/api/manager/my-products/{id}/submit` | 上报通用库；同一商品已有待处理上报则拒绝 |
| GET | `/api/manager/my-products/submissions` | 本站上报记录 |

**库存只有一个写入口**：`InventoryService#setStock`（行锁 + 差额 + **必写 `inventory_record`**，类型含 `INBOUND` / `CONSUME` / `CANCEL_RESTORE` / `REFUND_RESTORE` / `ADJUST`）；`saveStationSetting` **禁止改库存**。任何绕过它的 `quantity` 直写都会让库存流水断链。

**⚠️ 已下线的旧端点，不得加回**：`/api/manager/products*`（含 `/{id}/shelf`、`/priority`、`/inbound`）、`/api/products` 的 POST / PUT / DELETE、`/api/products/my`（恒空死端点）。它们正是"任何站长可改全平台商品"的根；`CatalogOwnershipIntegrationTest` 断言其必须已下线、且被拒请求不得落库。

### 4.3 顾客端端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/products/sale-by-station` | 返回 `StationProductVO`，价格是**本站有效价**；排序改为 `priority_display desc, sort asc, id asc`，让"优先展示"对顾客真正生效 |
| GET | `/api/products/{id}` | 同样返回 `StationProductVO`；带 `stationId` 时给本站有效价（否则会出现"列表按本站价、详情按平台价"），并按 §4.1 的可见性判据拒绝 |
| GET | `/api/products` | 可选 `stationId`：传了返回"通用库 + 该站自定义"，不传只返回通用库商品；支持 `keyword` 按名称 / 品牌 / 规格匹配 |
| GET | `/api/products/on-sale`、`/api/products/with-stock` | 保留：前者只给通用库在售；后者是站长视角（通用库 + 本站自定义，含下架 / 停售，便于排查"为什么顾客看不到"） |
| GET | `/api/tickets`、`/api/ticket-records` | **必须 join `inventory`** 返回本站有效水票价（`TicketAccountMapper.listByCustomerAndStationWithDetail`，阶梯同 `PriceUtil`）—— 口径不一致会让"页面一个价、扣款另一个价" |

`StationProductVO` 字段：`id/name/brand/spec/imageUrl/description/category/categoryText/effectivePrice/effectiveDeposit/effectiveTicketPrice/ticketEnabled/maxPerOrder/priorityDisplay/inStock`。
