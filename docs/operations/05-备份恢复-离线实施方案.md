# 备份与恢复：离线实施方案

状态：2026-10-05 已实现并验证本机隔离恢复执行器的无库安全护栏，真实导出/恢复尚未运行。未启定时、连接业务库、创建凭据、上传或删除备份。**RPO 1小时、RTO 4小时只是目标**；预算、保留期、加密异地目的地与管理权限仍只在 [design/16 C-11](../design/16-范围决策与实施路线图.md#c-11备份恢复目标保留期与异地目的地2026-10-05) 待拍板，不指定虚设留存天数或清理周期。

## 恢复范围和成功判据

保留 schema/迁移版本、完整业务数据、购买封存及分配/退款原款凭据、对应程序版本与受控配置。密钥配置和数据备份分开保护，不能把本地配置、SQL或凭据提交 Git/发到未批准的异地位置。恢复环境先关闭定时、外发通知及真实支付/对象存储连接，不能启动旧程序重写新模型。

RPO量“最新有效恢复点到故障点”的差，不看文件修改时间。单次一致性备份不足以保证一小时目标；后续评估按数据量持续生成可验证恢复点，或采用全量基线加连续 binlog。binlog 链完整、坐标/GTID及源版本必须核对，不能凭存在一个日志文件宣称可恢复；本批没有打开 binlog、刷新日志或改权限。[MySQL时间点恢复说明](https://dev.mysql.com/doc/refman/8.0/en/point-in-time-recovery.html)

RTO从确认故障计到可安全经营，包括取回备份、恢复、完整性核对、程序启动及业务抽样。后续演练记录各段实际耗时；未完成包含真实取回路径的演练，就不宣称四小时达标。

## 当前受控执行器（本批仅stub验证）

入口 `scripts/backup-restore-drill.js`，安全规则 `scripts/lib/backup-safety.js`，执行流程 `scripts/lib/backup-runner.js`。先 `node scripts/backup-restore-drill.js help`；无配置时backup/drill立即拒绝，help不读私有配置或调用客户端。旧位置参数、cleanup、--keep及未知/重复参数均拒绝。

```text
node scripts/backup-restore-drill.js backup --config <核准非密配置.json>
node scripts/backup-restore-drill.js drill --config <核准非密配置.json>
node scripts/backup-restore-drill.js restore --config <核准非密配置.json> --backup <既有dump.sql>
node scripts/backup-restore-drill.js verify --config <核准非密配置.json> --backup <既有dump.sql>
```

配置仅含source及需要时的target，每个对象只接受host、port、database、user、identity与confirmation。host目前必须是明确的 `127.0.0.1`，port为整数；source必须是核准新命名的 `aquaflow_test_` 专用库，target为不同的 `aquaflow_restoredrill_` 专用库，禁止业务/生产/备份标记。identity包含实际hostname、同一port、完整小写server_uuid。confirmation必须精确为 `TCP|host|port|database|user|hostname|port|uuid`，不能只确认库名。命名不提供授权，QA在用的库不得作为本批源/目标；新目标及准备操作由后续任务明确授权，不由脚本猜测或创建。

`AQUAFLOW_MYSQL_BIN` 指定既有客户端绝对目录；只使用已授权的临时 `AQUAFLOW_BACKUP_SOURCE_PASSWORD` / `AQUAFLOW_BACKUP_TARGET_PASSWORD`，不从application-local读取、不创建账号/密钥、无口令时停止。不得把口令写到配置/命令参数/Git。子进程环境白名单仅系统路径/临时目录等必要变量与本次MYSQL_PWD；隐式MYSQL_HOST、MYSQL_HOME、MYSQL_TEST_LOGIN_FILE等不继承。

恢复目标须已存在、无表/视图/例程/事件，且当前服务器 `event_scheduler` 必须为OFF；执行器不改系统开关。预检拒绝已存在业务对象，导入同一连接内在第一条dump语句前再检查当前库、hostname/port/server_uuid、空目标和OFF，不符以非法PREPARE语句终止，无--force。导出身份在前后分别核对，不虚称mysqldump连接本身执行了同连接检查；演练环境须独占，窗口无DDL和其他创建对象者。

独审P1修正：MySQL引号语义必须与有限检查器一致，目标预检及同一导入连接均拒绝NO_BACKSLASH_ESCAPES/ANSI_QUOTES，SQL模式缺失同样拒绝，不修改共享或会话模式绕前置。dump的SQL_MODE赋值仅支持标准保存当前模式、NO_AUTO_VALUE_ON_ZERO及已保存原模式恢复序列；未经保存恢复、直接/间接切入其他变量或未知模式拒绝进入导入。此为有限格式约束，不宣称通用SQL parser或任意模式兼容。

客户端首参数固定no-defaults/no-login-paths/TCP，host/port/user/schema由已核准对象生成，shell=false，SQL字节直接走FD，stderr独立保留。mysql另固定skip-reconnect/local-infile=0，断线不得重连后绕过同连接护栏；导入使用binary-mode，SQL解析器拒绝客户端命令。[MySQL客户端参数说明](https://dev.mysql.com/doc/refman/8.0/en/mysql-command-options.html)。每次运行只新建 `backup/safety/<唯一会话>/` 文件，使用排他写入，不覆盖既有dump或现场；成功和失败均保留目标、原dump、清单、恢复输入与诊断。不重建目标、不自动drop、不提供永久删除；C-11未定前不实施清理。

当前有限SQL解析器支持普通InnoDB表及仓库使用的生成列表达式、完整逐行literal INSERT、已知会话设置；含中文/引号/分号的业务文字保留原字节。版本条件注释作为可执行SQL审查，拒USE/CREATE或DROP DATABASE、跨库对象、外部文件、全局设置、shell客户端命令及不支持语法。视图/触发器/例程/事件不会静默省略，源预检或dump审查拒绝，须另批评审；此工具不宣称任意MySQL SQL或跨版本恢复兼容。

清单format=2包含完整源、服务器版本、导出开始/完成时间、原字节数和SHA及从**同一dump**提取的逐表结构/排序后逐行内容指纹，不再事后查源行数作快照证据。源/目标版本须相同，目标再导出逐表比较结构（含中文注释）、行数及内容；等行数内容变化同样失败。E8/E5以账户与批次分组键并集核查，NULL维度采用null-safe连接，包括只有批次无账户及只有账户无批次的组；另查订单客户/水站孤儿，查询失败不算通过。

导出、导入、内容核验、E8/E5/孤儿及总时长按单调时钟记入result.json。导出开始时间仅是快照窗口起点记录，不能假定为精确事务/GTID恢复点。尚缺真实客户端/schema兼容性、取回路径、完整资产/库存/资金对账、程序版本配置封存及恢复后启动/业务抽样；stub结果不证明已达RPO/RTO或具备生产恢复能力。

## 后续完整恢复流程模板（未授权执行）

先核准两个完整目标：源 IPv4/端口/库名及独立恢复 IPv4/端口/库名，库名不同，恢复目标已有且为空，不是生产或QA正在用的库。源备份权限不等于目标恢复/删除权限。若需准备新库另行确认具体目标，不用“名字像 test”推定授权。

以下只是 argv 模板，所有大写词都是待核准的参数；口令只在已授权的子进程环境内传入，命令行和日志不含口令。`--no-defaults` 放在首位，结合客户端支持的 `--no-login-paths` 隔离隐式登录配置；本机两个客户端离线 `--help` 已确认支持，后续目标客户端也须先核实，不能为兼容静默删掉隔离参数。远程连接的TLS/证书按核准目标配置，不为通畅关闭校验。

```text
mysql.exe --no-defaults --no-login-paths --protocol=TCP
  --host=SOURCE_IPV4 --port=SOURCE_PORT --user=APPROVED_USER
  --default-character-set=utf8mb4 --database=SOURCE_SCHEMA
  --batch --skip-column-names
  --execute="SELECT @@hostname, @@port, @@server_uuid, DATABASE();"

mysqldump.exe --no-defaults --no-login-paths --protocol=TCP
  --host=SOURCE_IPV4 --port=SOURCE_PORT --user=APPROVED_USER
  --default-character-set=utf8mb4 --single-transaction --quick
  --hex-blob --routines --events --triggers --no-tablespaces
  --result-file=APPROVED_DUMP_PARTIAL SOURCE_SCHEMA

mysql.exe --no-defaults --no-login-paths --protocol=TCP
  --host=RESTORE_IPV4 --port=RESTORE_PORT --user=APPROVED_USER
  --default-character-set=utf8mb4 --database=RESTORE_SCHEMA
  [stdin：已核准SQL文件的原始字节，仅写明确授权的独立恢复库]
```

同一实际连接再次核当前库及完整目标后才允许写。恢复前审查 dump 不含切回源库的 USE/CREATE/DROP DATABASE、越库对象或未批准外部路径；不能直接用 `--databases`/`--all-databases` 输出去恢复另一个库。不得使用 `--force` 跳过失败，不加自动 cleanup，不在失败后删除现场。表/事件/例程/definer与GTID兼容性逐项核实，不靠简单替换整个SQL中的库名修正。

仅在已确认全部相关表可一致性导出、备份窗口无冲突DDL时采用上述快照方式；缺相关权限先报告，不创建新凭据或提高权限。Windows PowerShell不以 `>` 重编码SQL，采用客户端 `--result-file` 或二进制输出，stdout与stderr分开；成功退出后还须核有效性，再将临时文件登记为可用备份。[MySQL mysqldump 参数、一致性及 Windows 输出说明](https://dev.mysql.com/doc/refman/8.0/en/mysqldump.html)
