# AquaFlow 双端页面与组件优化清单 · K3.1 最小勘误副本

> 日期：2026-10-25
> 范围：`miniapp-user` 26 个路由、`miniapp-delivery` 46 个路由，共 72 页；另含共享组件、导航、页面内弹层与反馈状态。
> 预览：`index.k31-reviewed.html`，包含 9 个代表页面和 4 组共享组件。
> 边界：保持现有功能、路由、角色、操作流程、服务端报价、支付/退款、权限与桶账口径不变。本清单是下一轮呈现层优化方案，不把静态审阅写成真机缺陷或已验收结论。

## 本副本勘误边界

保留原稿不覆盖。本副本仅将静态收款选项改为均未选择、将不支持的“水票 + 现金”例子改为“水票支付（本单已结清）”、将桶账示例改为有效权益/当前可用/订单占用，明确并非实物盘点。未据此新增支付能力或更改金额、权益和收款规则。页面与组件列表属于待核对方向，不代表72页及全部弹层状态已经验收。

已付款订单不再次询问收款；含本单新增押金且未收齐款项时，不得套用普通订单的“未收款仍完成交桶”示例。

## 1. 盘点依据与现状判断

- 路由正本：两端 `app.json`。
- 现有视觉正本：`miniapp-user/styles/variable.wxss`、`miniapp-delivery/app.wxss`、`docs/design/37-两端全页视觉定稿.md`。
- 页面覆盖参照：`docs/audit/native-ui-20261022/README.md`；其中多数页面仅完成静态审阅，仍需后续原生与真机视觉验收。
- 抽查了首页、确认订单、配送任务、完成配送、站长工作台、水站管理、经营看板、共享订单卡、空态、加载与底栏源码。

**总体判断：**现有“功能蓝 + 浅灰底 + 白色内容面”的方向应保留。当前主要优化空间不是换色，而是：

1. 同类页面在标题、卡片、按钮、状态条、弹层和底部操作上仍有表现差异。
2. 业务分支很多，加载、部分失败、真实空结果、禁用、处理中、结果未知需要形成统一组合规则。
3. 长地址、长站名、混合商品、大金额、大字体和窄屏下，要继续防止信息截断、操作挤出与底栏遮挡。
4. 用户端要减少阅读负担；配送端要提升现场辨识与触控；站长端要让“待办、事实、配置、报表”各有明确层级。

## 2. 统一设计规范（落地值）

| 项目 | 规范 |
|---|---|
| 主色 | 继续 `#1264D6`；深色按压 `#0D4FA8`；选中浅底 `#EAF3FF`。不新增第二品牌色，不恢复渐变。 |
| 功能色 | 成功 `#16834A`；待关注 `#A95516`；危险 `#BD3328`。状态章使用对应浅底，文字使用实色；始终带文字，不只靠颜色。 |
| 中性色 | 正文 `#182230`；常规 `#4B596A`；辅助 `#637083`；占位 `#9CA7B5`；页面 `#F5F6F7`；内容面 `#FFFFFF`。 |
| 字体 | 系统 `-apple-system / PingFang SC / Microsoft YaHei`。页面结论 20–22px 等效；卡片标题 16–18；正文 14–16；辅助 12–13。数字使用系统表格数字能力时只改善对齐，不改金额格式。 |
| 间距 | 4px 等效基础步长；页面左右 16；卡片内 16；相关项 8–12；区块间 20–24。先减少无意义留白，不先缩字。 |
| 圆角 | 卡片 12；按钮/输入 10；状态章 6；胶囊只用于短状态与筛选。 |
| 阴影 | 常规卡片以 1px 浅边框和分隔线为主；吸底操作、底部弹层才用轻阴影。 |
| 触控 | 普通动作至少 44px；配送现场和主提交 48px；步进器热区不小于视觉图形；底部预留 `safe-area-inset-bottom`。 |
| 信息层级 | 当前任务与动作常显；影响决定的风险在动作前可见；复核依据可展开；内部术语和重复说明退出默认视图。 |
| 金额 | 价格与正文同深色，以字重区分；待收款才用警示色。未知写“待核实”，不写 `¥0.00`。 |
| 图片 | 统一比例、`aspectFit` 与中性回退；商品示意图和场景示意图分别标明，不冒充品牌实拍。 |
| 动效 | 只做 120–200ms 的按压、选中、弹层与骨架屏过渡；支持减少动态效果，不做营销动效。 |

## 3. 代表页结构说明

| 代表页 | 顶部与正文顺序 | 主动作与滚动 | 底部 |
|---|---|---|---|
| 用户·订水首页 | 标准安全区；水站/营业状态 → 地址 → 当前订单 → 复购 → 商品 → 桶与押金 | 单纵向滚动；商品变化不自动跳结算 | “零售预估 + 确认订单”位于原生底栏上方；三项底栏保持 |
| 用户·确认订单 | 地址 → 商品数量 → 支付方式 → 费用摘要 → 备注 → 必要告知 | 修改任一报价相关项后原地显示重新核实；主动作固定 | 合计/待核实 + 明细 + 当前唯一主动作；无 tab |
| 用户·订单详情 | 配送/支付双状态 → 地址与联系 → 商品费用 → 进度 → 管理信息 | 页面滚动；低频动作在正文末尾，不抢状态 | 无固定营销按钮；按现有能力保留下一步 |
| 用户·桶与押金 | 资产水站 → 汇总与口径 → 按商品明细 → 可办理事项 → 流水 | 退桶先预览再确认；独立押金保持原入口 | 无 tab；避免双主按钮同时吸底 |
| 配送·配送任务 | 当前站 → 待收款入口/恢复提示 → 状态筛选 → 地址/商品/收款/联系人 | 卡片主按钮为接单或完成；电话/导航为辅助 | 角色对应 2 或 3 项自绘底栏；列表留足底部空间 |
| 配送·完成配送 | 原单识别 → 本次送货 → 实际回桶 → 本次收款 → 凭证/选填 | 收款不默认选择；少回桶就地提示；底部确认防重复 | 单主按钮吸底；成功/未知状态仍在原单上下文 |
| 站长·工作台 | 水站与身份 → 真实待办 → 常驻管理入口 → 调度页签与队列 | 队列主动作清晰；跨站风险在确认前完整展开 | 自绘底栏保留 P0 红点；弹层时按现有规则避让 |
| 站长·水站管理 | 五组入口：订单客户/收款工资/桶库存/水站设置/经营数据 | 全页单滚动；徽标点击与整行同一去向 | 无额外漂浮入口；未知徽标显示“未核对” |
| 站长·经营看板 | 时间范围 → 指标与口径 → 趋势 → 分布 → 排行 | 图表独立阅读但不嵌套纵向滚动；筛选后保留位置 | 无固定底栏；数据为空给换周期动作 |

## 4. 用户端：26 页逐项优化

| 路由 / 页面 | 当前问题或风险 | 具体优化方向 |
|---|---|---|
| `home/index` 订水首页 | 水站、地址、当前单、复购、商品、海报和桶入口的条件组合多，页面长短变化大；固定结算与 tab 易形成遮挡风险 | 保留现有任务顺序；统一各状态组合的卡片间距与首屏优先级；海报不与选购争抢；结算栏按 tab 高度和安全区留白；加载用商品行骨架，失败不覆盖已选数量 |
| `home/notice` 首页公告详情 | 长标题、长正文、来源和时间的阅读层级易混在一起；刷新失败与旧正文需同时存在 | 标题 20px、正文 15–16px/1.75；来源时间次一级；失败提示固定正文上方且保留旧内容；链接/电话等可行动内容统一样式 |
| `order/list` 订单列表 | 配送状态筛选与支付状态同时出现，容易只看到一个维度；多商品与多动作使卡片高度不一 | 卡头保留配送+支付双章；商品完整摘要优先，地址和时间次级；金额与主动作同底行；筛选可换行；空态按“全部/当前筛选”分别给动作 |
| `order/detail` 订单详情 | 状态、费用、商品、配送、凭证和管理信息多，长页中下一步易被稀释 | 顶部事实区只放双状态、金额和当前结论；配送与商品先于单号；恢复支付/取消/再次购买按状态只露适用动作；费用与凭证可展开但金额责任不折叠 |
| `order/create` 确认订单 | 页面长且含费用抽屉、综合确认、缺货/线下/在途提醒；警告和恢复信息可能离提交按钮较远 | 保持六段顺序；报价加载用费用行骨架；风险就近展示并在底栏保留阻断原因；抽屉锁背景、内部滚动、底部固定；未知结果围绕原单恢复，不回成新单表单 |
| `order/success` 下单结果 | 装饰性结果图形可能强于真实支付/配送状态；待付款与结果未知不能都表现为成功 | 缩小图形；首屏直接显示“待付款/等待配送/结果待核实”等真实结论、金额和原单号；主入口按状态为继续支付或看订单；模板等次级入口降权 |
| `address/list` 地址列表 | 地址、联系人、默认标记、编辑删除和新增入口争夺注意力 | 地址作为主标题，联系人/电话次级；默认标签只一个；编辑与删除放整行底部或更多菜单；新增地址固定底部；空态区分无地址和读取失败 |
| `address/edit` 地址编辑 | 字段多、地图定位、楼层/电梯与费用条件交叉；键盘易遮保存按钮 | 标签全部置上；按联系人/位置/配送条件分组；定位结果显示来源与失败重试；楼层费提示邻近楼层字段；保存吸底并随键盘避让 |
| `barrel/index` 桶与押金 | 有效权益、当前可用、订单占用、欠桶/暂存、余额和本次可退易被混读；账面数量不等于实物盘点 | 保留按商品并集；汇总只给必要三项并附口径；每商品同一顺序展示；余额与可退分开；退桶预览明确交桶数/金额/安排；流水折叠不隐藏欠桶与责任 |
| `barrel/purchase` 独立押金 | 新购买、原购买待核实与历史记录同页，容易误重复付款 | 首屏先给本次商品/数量/报价；原购买未知结果单独恢复区并优先于新付款；支付按钮处理中禁用；历史记录降为次级列表 |
| `shop/index` 商品目录 | 搜索、切站、图片、押金参考、数量与订水清单并存；长商品名和图片失败影响整齐度 | 搜索置顶且保留范围说明；商品行统一图片框、名称两行以上可扩、真实单位；价格与步进器同底行；清单入口显示已选件数；图片失败用文字回退不留空白 |
| `template/index` 常用配置 | 模板名称、商品数量、编辑删除与“是否自动使用”容易误解 | 首行说明“仅用于管理常用配置，不承诺首页自动填”；模板卡显示商品明细与最近编辑；编辑为次按钮、删除为危险文字；编辑弹层复用确认订单的商品行和步进器 |
| `ticket/index` 水票 | 可用张数、适用商品/水站、购票档位、批次记录和原购买恢复信息密度高 | 顶部仅显示当前站可用总数与适用范围；档位按真实价格排列；原购买恢复独立突出；记录按商品分组；不展示无依据优惠承诺；退出/恢复动作层级明确 |
| `mine/index` 我的 | 当前站、三项资产、退桶入口、地址/账单/客服等菜单并列，站别边界容易被忽略 | 水站范围置顶；水票/桶/押金三格统一加载与未知态；资产入口高度一致；退桶办理保留责任说明；菜单改连续行列表，减少装饰身份信息 |
| `login/index` 登录 | 登录、协议、隐私与开发测试入口的层级不同；授权失败需有出口 | 品牌区压缩；主登录按钮唯一；协议告知紧邻按钮且链接可点；失败给可理解原因和重试；测试入口只在既有条件下出现，不进入主视觉 |
| `service/index` 客服与反馈 | 联系水站、普通反馈、退款争议、记录和匿名后果共页，表单较长 | 联系方式前置；按真实模式显示对应说明与表单；争议责任/未结事项常显；历史记录连续列表；提交中禁用，未知结果先查原反馈 |
| `mine/about` 关于 | 内容少但入口类型不同，容易样式过散 | 单栏版本信息 + 协议/隐私/反馈三行；统一箭头、触控和分组间距；只阅读，不制造“已同意”状态 |
| `mine/edit` 个人资料 | 输入对齐、保存与取消层级不统一；长昵称可能挤压 | 标签置上、输入全宽；头像/昵称等按字段分组；保存为主按钮，返回为普通导航；保存成功轻提示，失败保留输入 |
| `mine/agreement/index` 协议 | 长文、版本、草稿/占位条款与“阅读不等于同意”需要清晰区分 | 版本与状态置顶；段标题层级固定；正文 15px/1.8；【待补】用警示标签而不是隐藏；目录可展开；失败时不清空旧正文 |
| `mine/account-data/index` 账户数据 | 导出/更正/注销等请求的后果、处理状态与未开放能力不同 | 先选事项再显示说明和表单；不可自动注销、未结事项等责任在提交前常显；记录显示申请时间/状态/结果；未开放入口禁用并解释，不伪装可提交 |
| `payment/records` 账单记录 | 金额方向、支付方式、原订单和刷新失败可能挤在卡片中 | 改连续流水行；金额右对齐、正负方向带文字；订单号与时间次级；筛选固定顶部；失败保留旧流水并给重试；空态区分无记录与无筛选结果 |

| `notice/index` 公告列表 | 长标题、时间、来源和未读状态容易同质化 | 连续白底列表；标题最多不作为硬截断依据，必要全文入口明确；未读用小蓝点+文字；时间与来源合并次级行；详情整行可点 |
| `mine/company` 企业信息 | 公司身份、联系人、结算/账期字段与编辑操作混杂，长公司名易挤压 | 公司名为主标题；身份状态章次之；联系与结算分区；编辑表单标签置上；只读与编辑模式视觉一致；保存不承诺审核通过 |
| `exception/list/list` 异常记录 | 异常状态、差异数量、补偿、处理进度在同一卡中重复强调 | 卡头只强调一次当前状态；差异与补偿用事实行；时间线节点统一；补偿金额不当作已实际退款；原始记录可展开 |
| `mine/asset-claims/index` 历史资产认领 | 客户/商品/旧押金/桶容量/水票、审核状态与恢复请求信息复杂 | 表单按对象→资产→凭据分组；移除可见 E/H；审核中/待核实与可编辑状态区分；“审核即入账”在按钮前常显；未知结果恢复原申请 |

## 6. 导航、共享组件与小型控件

| 所属端 / 组件 | 当前问题或风险 | 具体优化方向 |

| 两端·选择器/日期/地图 | 原生选择与页面选中态差异大；长值可能截断 | 触发行显示当前完整值与箭头；弹层标题写任务；日期范围有清除；地图定位显示来源和失败，不自动覆盖手填 |
| 两端·单选/复选/开关 | 选择、确认与即时生效语义容易混 | 单选用于支付方式/收款事实；复选用于明确授权；开关只用于即时偏好；不在开关里执行资金动作；选中态有勾或填充 |
| 两端·数量步进器 | 加减图形小、输入窄、禁用原因不明显 | 热区 ≥44px，配送完成页 48px；数量居中且可直接输入时保留原能力；到边界禁用；非桶商品不得出现回桶步进器 |
| 两端·费用行与合计 | 标签和金额换行时错位，未知可能显示成免费 | 标签左、金额右，长标签先换行；合计分隔线+大字号；费用明细使用同一报价快照；未知写待核实 |
| 两端·空状态 `Empty` | 当前组件主要是图片+一句话，难以覆盖不同任务和失败 | 改为“中性图形 + 具体标题 + 一句原因 + 可选下一步”；无订单/无筛选结果/无权限/未绑定分别写，不用一张图包全部 |
| 两端·加载 `Loading` | 通用 spinner 会造成布局跳动，也无法表达局部加载 | 首屏使用匹配真实结构的骨架；局部刷新保留旧数据并在对应区显示小 spinner；提交按钮内 loading；全页加载只用于无可用内容 |
| 两端·骨架屏 | 骨架与实际卡片结构不一致会闪跳 | 为商品行、订单卡、流水行、指标区各做固定骨架；高度接近最终内容；加载完成后同位替换 |
| 两端·`load-error` / 部分失败 | 普通读取失败与真实风险都容易变红，且重试入口不一 | 普通失败用灰白信息条+蓝边；真实资金/少回桶用警示/错误；写清影响范围和重试；旧数据保留并标“可能不是最新” |
| 两端·结果未知 /  stale 数据 | 网络未知与读取失败若相同样式，会诱发重复提交 | 未知结果用独立持续提示，包含原单/原申请识别和“核实原结果”；不直接显示再次付款/退款/提交主按钮 |
| 两端·Toast | 成功、普通信息和失败反馈时间/样式可能不一致 | 成功/普通信息用深色轻 toast，1.5–2s；失败需行动的不用纯 toast，改页面内提示；不覆盖底部主动作 |
| 两端·原生 `showModal` | 原生样式不可完全定制，文案长度和按钮色容易不统一 | 只统一标题、后果、按钮顺序和 confirmColor；普通确认蓝、危险红；长内容改用可滚动底部弹层；取消回调保持原语义 |
| 两端·底部动作单 | 条目多、描述长、遮罩与底栏容易冲突 | 标题+用途说明；条目整行 ≥48px，主描述/后果两层；滚动区限高；取消固定；打开时背景锁滚并避让 tab |
| 两端·确认弹窗 | 缺货、支付、押金、退款等后果不同，不能一套泛化文案 | 标题写具体动作；正文列金额/数量/责任；主次按钮明确；多风险合并为一个分块确认，不连续弹多个“知道了” |
| 用户·水站选择弹层 | 加载、失败、真空与当前站状态需要区分 | 站点行显示名称/地址/营业状态；当前站用文字勾；加载骨架、失败重试、无站说明分别实现；切站中防重复 |
| 用户·费用明细抽屉 | 长清单滚动、合计固定与背景滚动冲突 | 头部关闭、正文 scroll、底部合计固定；滚动锁背景；费用与确认页同一次报价；关闭热区 ≥44px |
| 用户·综合下单确认 | 缺货/线下/在途/新增押金可能同时出现 | 分块展示并只保留必要项；每块标题+事实+后果；费用预览末置；返回修改与确认下单固定底部 |
| 用户·购票/退桶预览 | 金额、数量和原购买/原申请恢复容易混 | 新操作与原结果恢复分区；预览只读显示适用商品、数量、金额与安排；主按钮写具体动作，不泛称“确定” |
| 配送·分配配送员弹层 | 名单为空和名单未加载不能一样；长姓名电话可能挤压 | 员工行姓名/电话/当前状态；加载骨架、失败重试、真空引导分别处理；选中即走原确认，不新增权限判断 |
| 配送·“配送遇到问题”动作单 | 上报问题与转单/退回的责任层级不同 | 上报问题首项；“确实送不了”单独分组；每项说明后续去向；危险动作二次确认；不改变业务 reason 标识 |
| 配送·更多操作 | 转给同事、退回、撤回、取消、异常与拒付并列风险高 | 普通操作在前、危险操作末组；每项写后果；只显示当前有资格动作；点击先关弹层再进入原确认 |
| 配送·收款确认 | 待收款与待确认流水名称近、误点成本高 | 标题带订单与金额；正文写“款项实际到手后才确认”；处理中禁用；结果未知先查流水，不再次确认 |
| 两端·照片上传/预览 | 上传中、失败、删除与图片解码失败状态不一 | 固定缩略图框；上传进度覆盖当前项；失败项可重试不整批清空；删除热区足够；解码失败仍可尝试预览原图 |
| 两端·`PrivacyPopup` | 隐私授权与业务弹层叠加时容易混乱 | 保持系统要求时机；样式与底部弹层一致；协议链接可点；拒绝/取消有明确出口；不提前伪造授权状态 |
| 配送·`HelpTip` | 说明入口可能过小或解释抢过主任务 | 图标热区 ≥44px；只解释复核依据，不隐藏金额/责任；气泡/弹层在窄屏完整可读；打开后不遮关闭按钮 |
| 用户·`Price` | 符号、整数、小数与单位基线不一致 | 统一符号小一号、金额字重 700、单位辅助色；大金额允许换行不缩到不可读；未知走“待核实”组件而非价格 0 |
| 用户·`AssetStationView` | 跨站资产与当前站选择容易误解为可通用 | 站名与资产范围绑定显示；切换只改变查看上下文；空资产与未加载分开；保留原站记录不清空说明 |
| 两端·分页/加载更多 | 加载中会重复触发，失败可能让旧列表消失 | 已加载内容保持；底部显示“正在加载/加载失败重试/没有更多”；按钮热区足够；空列表不显示“没有更多” |
| 两端·图表与排行 | Canvas 加载空白、颜色过多、窄屏标签拥挤 | 只用主蓝/成功绿/中性灰；加载和失败占位同尺寸；横条图优先；数值与标签同时给，不只靠饼图颜色；排行连续行 |
| 两端·安全区与键盘 | 吸底按钮、tab、弹层和输入可能互相遮挡 | 统一底部预留变量；键盘弹起时当前输入滚入视野；弹层正文可滚；320/390 等效宽度和大字体专项验收 |

## 7. 建议实施顺序（后续执行，不在本次静态预览中改小程序）

1. **P0 共享地基**：色板兼容 token、字体/间距/圆角、按钮、状态章、空/错/加载、底栏与安全区。两端分别维护同值，不建立跨小程序运行时依赖。
2. **P1 高频主链路**：用户首页/确认订单/订单列表与详情；配送任务/订单详情/完成配送；站长工作台。先验证长文本、弱网、未知结果和底部遮挡。
3. **P2 资产与资金**：桶、押金、水票、退桶审批、应收、待确认收款、站间结算、工资与利润。只改呈现，口径文案仍由服务端下发。
4. **P3 配置与低频页**：地址、资料、协议、员工、商品配置、公告、账户数据、历史记录等，复用已验模板。
5. **P4 原生收口**：微信开发者工具 + 真机，覆盖 320/390 等效宽度、大字体、长站名/地址/商品、大金额、键盘、弹层、返回、弱网和重复点击。

## 8. 验收清单

- 72 个路由全部有页面状态审查记录；原入口、处理函数、路由和角色权限不减少。
- 每页至少检查：正常、加载、部分失败、真实空、无权限/不可用、操作中；涉及写操作再查结果未知与恢复。
- 所有地址、商品、站名、金额做长内容样本；不用省略号隐藏费用、地址、责任和完整商品摘要。
- 主动作热区 ≥48px，普通动作 ≥44px；底部操作不被 tab、home indicator、键盘或弹层遮挡。
- 配送列表 5 秒可辨认：送哪里、送什么、收多少钱、下一步是什么。
- 确认订单可辨认：水费、新增押金、配送费、楼层费、本次合计、报价是否有效。
- 资产页区分余额/本次可退、有效权益/当前可用/订单占用；账面数量不冒充实物盘点，缺少实物证据不标成已到手；失败不显示成 0。
- 待确认收款、实际退款、工资实付、调整执行等操作前，金额与责任后果紧邻按钮；未知结果不直接重试写操作。
- 颜色对比、字体放大、减少动态效果和屏幕阅读标签做基础可访问性检查。
- 浏览器 HTML 预览仅用于方向评审；最终视觉通过必须以微信原生渲染与真机为准。
