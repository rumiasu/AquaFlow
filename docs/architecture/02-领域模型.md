# 领域模型

核对日期：2026-10-01。本文描述当前新业务模型；历史订单的兼容边界单列，不把两种规则混为一个默认行为。未决目标见 [design/16 §12](../design/16-范围决策与实施路线图.md#12-核心业务决策复核2026-10-01)。

## 1. 业务对象和责任

客户购买水及配送服务，以独立押金获得循环桶使用容量，并对实际拿到的桶承担归还责任。水站同时承担服务交付、押金退款、水票兑现及合作站结算责任。

订单表示本次消费与履约安排，不替代客户资产账户。付款记录表示发生或待核实的资金行为，不替代交付记录。水票表示特定站和商品的消费资格，不是平台通用余额。

## 2. 客户与经营归属

客户身份全局唯一，没有客户所属站字段。经营关联为绑定与本站订单的并集；桶、押金和水票分别按客户、资产站、商品管理。只购买权益而没有水订单的客户仍可按本站绑定查询资产。

个人与固定联系人企业复用现有客户身份，企业申请补充经营资料及账期，不产生独立企业资产账户。跨企业经办人、自动资产移站及商品兼容桶型不在首期范围。

## 3. 三站与钱流

| 站 | 对本单的含义 |
|---|---|
| 归属站 A | 客户选择的站、定价方、客户资产责任站 |
| 履约站 B | 当前库存、配送及沟通责任方；未外派时等于 A |
| 结算站 | 订单服务收入及应收的归属；正常等于实际履约站 |

资产留在 A。历史已收资金仍保留原收款站事实，仅待收款可随合法换站移交。A 已收的消费款或已消耗的 A 水票与 B 的履约报酬形成站间往来；不能因为订单指向 B 就声称资金已经到了 B。

新外派以接单前完整报酬为依据，差额由发起方承担；首次净送桶或额外回桶另定同型空桶/折款安排。客户原价格不随外派重算。服务失败及部分退款的最终责任仍有未决范围，不能把全部损失默认转给某一站。

## 4. 桶：权益、实物及分配

按客户、站、商品分别计算：

| 符号 | 含义 | 依据 |
|---|---|---|
| E | 生效且尚未终止的桶权益容量 | 桶权益批次剩余数量 |
| over | 实物相对权益的差额，可为负 | 桶差额账 |
| H = E + over | 客户实际持桶 | 实际送出、收回及合法调整 |
| R | 已被进行中订单或申请分配的权益 | 活跃分配凭据，兼容历史活动流程 |
| E − R | 可继续分配的权益 | 不小于零，不等于可还空桶数 |

独立购买 q 份权益：E 增 q、over 减 q，H 不变。新增容量先覆盖现有超占用；只有剩余未领取容量可以免回领桶。负 over 可能来自预付未领，也可能来自多还暂存，不能一律称为“已经还过桶”。

订单按数量锁定容量及本次领取部分。默认应回 = 本次送出 − 本次分配的免回领取数；实际回收另记。新权益可以先于实物生效，同一份容量在本单结束前不能被另一单使用。购票仅检查有相应 E，不按 E 限购票张数；兑水及退还均检查可分配数量。

申请退款时固定原批次及应退金额。实际收桶减少 H，随后终止权益减少 E；两步不能重复减实物。收桶之后仍有未退款责任，但该权益不能重新领桶。

欠桶只提醒、不自动阻断客户下单；欠桶与退该商品押金互斥。额外借桶的经营责任边界见决策 C-02，不擅自恢复固定欠桶上限。

## 5. 消费、资产退出与补偿

| 动作 | 后果 |
|---|---|
| 未交付消费取消/退款 | 取消履约，释放库存和本单权益分配，已独立买入的资产保留 |
| 已交付退水费 | 退该项原款；不抹交付、不撤合法桶权益 |
| 已交付退服务费 | 独立退对应费用，不自动结束用桶 |
| 水票消费售后 | 整笔回补原消费资格；不折现金，不以“保留服务费”名义重复兑现整票 |
| 结束用桶 | 申请、批准、客户确认、实际交桶、原批次实际退款分别完成 |
| 额外赔偿 | 站长按异常/调整依据裁决，记录金额、原因和承担方，不能超额退原消费款伪装赔偿 |

现金退款登记真实交付事实；真实微信渠道未接入时不能标自动退成功。未使用的真实购票批次可按原款剩余数量退出；赠送、推断或无原款来源的批次由站长核实，不自动兑换现金。

## 6. 信用、欠款和正常账期

正常账期、争议和确认拒付不同。确认拒付后保留原欠款、关闭新增货到付款，不直接扣押金；新单可建，支付新单前需补旧债，旧债仍可独立登记收款。跨站 B 的拒付记录不能自行冻结无关站，相关 A 资产由 A 核实。

还债不自动恢复新增货到付款权限。错判、复核、免债及认损的目标尚未完整确定，见决策 C-03；当前没有完整申诉结案能力，不能宣称限制都能自动解除。

## 7. 生命周期与等待

### 7.1 订单

状态正本为 `constant/OrderStatus.java`：待配送、配送中、已送达、已完成、已取消。已送达/已完成不能通过取消抹去事实；配送中取消须走员工审批流程。客户可查询未付款订单，履约人员只处理已付款或获授权的货到付款订单。

### 7.2 支付

状态正本为 `constant/PaymentStatus.java`，订单支付状态是订单收款结论。待收款不等于到账。只退部分费用保留原支付结论及退款明细，全部消费退完再进入相应终态。

### 7.3 资产申请及站间往来

新退还申请：APPLIED → APPROVED → 客户确认 → RECEIVED → REFUNDED；未实收桶前可依规定撤回/驳回，已经交桶须继续办理退款。收桶费独立支付，不能从押金偷偷净扣。

外包协议 OFFERED → ACCEPTED；接受后金额固定。净桶差异须双方确认方案和实际交接。正常站间结清沿用付款方线下登记；新增返还债务须分别登记实际交付和确认到账。

## 8. 历史兼容

历史路径的权益是在送达时生成，其“配送中押金桶”不是新预付未领容量。新订单/退还以永久保留的分配或申请凭据识别，终态仍保留来源。旧活动订单和退还也占用相关容量，避免切换期间双重分配。

不得按现有桶数重发首次免回资格，不按当前价格重算旧押金，不能将历史人工权益自动变为实收可退现金。产生新业务后保持模型开启，回退按 [SQL 部署说明](../../AquaFlow-backend/sql/README.md)核对。

## 9. 模型边界

无逐桶编号、跨商品兼容、自动资产跨站迁移或正常部分交付。这里的数量守恒不是物理盘点证明，收款登记也不是银行到账证明。免押循环桶、平台资金主体、争议最终裁决和水站退出保障不能由字段默认值替产品做决定。
