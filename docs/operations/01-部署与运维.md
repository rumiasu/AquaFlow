# 部署与运行责任

写给部署及运维人员。核对日期：2026-10-01。开发运行见 CONTRIBUTING，迁移适用顺序见 sql/README；生产操作须确认具体目标和备份。

## 1. 当前部署边界

单实例后端和 MySQL 8.4，正式 HTTPS 入口及两个微信小程序。内存限流及部分作业未按多实例设计；增加实例之前需解决集中计数和作业重复执行。

## 2. 配置

变量清单为 AquaFlow-backend/.env.example，生产 profile 为 application-prod.yml。数据源、JWT、两端微信及 CORS 配置须解析为真实可用值；生产关闭 DEV_LOGIN_ENABLED、MOCK_WECHAT_PAY。配置样例是占位符，不是可复用真实密钥。

JWT 长度及危险开关由 RequiredConfigChecker 检查，数据源缺值在 prod 显式拒启。COS/告警外部渠道未配置可降级，但影响上传或消息实际发送。BarrelBusinessPolicy 在新模型开启时检查 v71 表组。

F-75 后端的 PaymentSchemaGuard 检查 v72 可空 varchar 摘要列的类型、长度与可空性，以及 v73 `ticket_purchase_fence` 的必要列、完整主键、InnoDB 引擎和与支付编号一致的字符比较规则；缺失或不兼容形状拒启，不静默修改既有结构。新库基线已含，存量库须先备份并核实目标，按 sql/README 安装适用增量和一致的新程序。该准备过程不代表真实支付渠道已接通，也不授权操作业务库。

新增的购票请求终结只在没有任何原款时永久封锁原编号，已登记款不取消、不退款。购票与独立押金的实际支付编号建款均加入同一事务封锁协议；独立押金申请原键与实际 `BR:` 支付键不同。开放终结入口前须停止所有不识别封锁的旧建款实例，不能新旧混跑后接受“封锁了就不会再建款”的承诺。技术凭据及 `closed_time` 永久保留，不作定时清理；备份/恢复须一并保留，否则迟到原请求可重新建款。未来真实渠道仍须先形成受保护的款记录再发起收款，不能以数据库没有记录推断客户一定没有付款。真实业务库迁移和渠道验收仍未执行；购买封存及同款退款的锁/回滚已有隔离 MySQL 集成回归，准确版本和范围见阶段交付，不能据此声称真实库升级或渠道已验。

登录限流当前只认 TCP 连接地址。保持 `server.forward-headers-strategy=none` 且不设置 Tomcat 的 `remoteip.remote-ip-header` / `remoteip.protocol-header`；这些重写入口开启时拒启。反向代理后的所有客户、员工共享代理 IP 的配额，正常登录/刷新可能互相触发 429；既有“能经代理访问”不能证明此配额适用于实际人数和流量。仓库未发现受维护的代理部署模板，本次没有修改外部代理配置或实现逐客户代理限流。真实采用代理前须评估这个限制，需要逐客户配额时另行验证明确可信来源及多跳防伪方案。

## 3. 发布前条件

确认产品主体和相关未决业务目标，真实渠道不可用时不能开放假付款。正式 API 域名、小程序应用配置、必要上传域名及真机可用性核对。发布包不含 application-local.yml，启动姿态及探针按发布脚本验证。

通过测试不证明真实资金可收退或真机页面可用。本轮没有完成生产迁移和正式发布；具体记录见 design/16 §11.6。

## 4. 数据库升级

新库才导入 schema；真实存量库先备份、确认已安装版本和待结业务，再按清单只执行适用增量。v71 先兼容代码和完整结构，切换核对后启用；新业务发生后不能回退旧代码或关闭模型继续旧规则营业。

## 5. 备份与恢复

备份结构、业务和必要渠道凭据配置，存储在受控位置，不提交 backup。现有 `scripts/backup-restore-drill.js` 只作为工具入口参考：它默认备份源库 `aquaflow`，客户端尚无完整地址绑定，会读取本机数据库配置；不能直接用默认命令执行本期隔离演练。演练须显式指定本次自建源库及不同恢复目标，核对实际 TCP 地址、隔离隐式客户端配置并记录完整校验，再执行授权范围内的备份/恢复。真实恢复前另行确认目标，不能把演练件指向生产。库名像 test 也不能证明里面没有必须保留的数据。

验证工具重建/清理临时库前，必须确认目标可清空，并设置 `AQUAFLOW_ALLOW_DB_RESET` 为该次目标的精确库名。测试准备仅允许 `aquaflow_test`，启动演练仅允许 `aquaflow_prodstartup_check`，恢复演练仅允许 `aquaflow_restoredrill`，各自可加小写字母、数字及下划线组成的会话后缀；业务/生产/备份标记及源目标相同均拒绝。默认名称也不能免除明确确认，多个会话需不同目标。此变量是执行边界，不证明源库备份或恢复后业务已经可用。未通过的演练保留目标供排查，不自动删除失败现场。

测试准备与后端测试另须 `AQUAFLOW_ALLOW_TEST_DB_TARGET=IPv4:端口/库名` 完整确认，实际准备目标与 JDBC 连接必须一致，直跑 Gradle 也受启动和清表前护栏约束。配置和支持范围见 CONTRIBUTING §4 与测试体系；启动/恢复工具尚未完成同等全地址绑定，完整 verify 因现有启动检查只支持 `127.0.0.1:3306` 而拒绝其它目标。替身与无库验证通过不授予真实建库、清表、迁移或恢复权限，也不表示 F-68 的剩余工具与实库边界已验收。

后端测试自动 SQL 初始化已禁用，结构由同目标准备脚本显式安装。外部初始化脚本、凭据或未支持的启动迁移覆盖必须在数据源建立前拒绝；`spring.sql.init` 仅接受精确的 `mode=never`，不能仅依赖清表前的当前库检查补救已经执行的启动 SQL。此限制属于测试入口，不能据此声称生产迁移、启动演练或恢复工具已取得同等保护。

## 6. 日常业务等待

站长跟进未收款、缺货、退还审批、收到桶后退款和站间交接。新未付桶装订单仅在有权益分配且没有活跃支付请求时可按超时取消；付款未知和已付等货不自动丢弃。系统不通过提醒替站方许诺具体送达时间。

站长首页已接入缺货、已收桶待退款、返还款发送/接收及净桶交接/争议的当前责任，点入业务等待页，再按原申请办理。缺货默认 P0，其余新项默认 P1；红点仍只报非零 P0。页面列表有展示上限，总数独立聚合，办理后刷新查看后续记录。失败或结构未就绪显示未核对并可重试，不把空白或旧数字当已办完；提醒时间不构成送达或退款承诺。接口字段与权限见 API 参考的“站长日常责任读数”。当前页面流程与专项单元证据不替代实际数据库、开发者工具或真机验收。

## 7. 对账与告警

系统作业按配置生成结果；站长只读本站即时视角。对账不平先核事实及来源，不通过直接写派生账户“消掉差异”。系统故障向系统管理员，经营问题向对应站长，渠道失败仍保留落库告警，通知不能连累主业务。

## 8. 故障处理

健康探针、数据库探针和授权拒绝分别验证，不把 HTTP 200 当业务成功。付款/退款结果未知核实原交易；预留不足核当前站和原凭据；客户投诉核原款、实际交接与责任，不恢复终态订单当补救。

## 9. 暂停与永久退出

暂休/预约状态是软经营提示，不能当停用账号或永远清结。需要停业时关闭适用业务入口并保留客户资产办理路径。永久退出和经营者变更的资产清结责任仍待 C-06，不把“暂不移站”写成“可以删除资产”。

见 [03-仓库重新发布](03-仓库重新发布.md)。本地新 Git 快照与数据库升级是两个操作，上传代码不授权改生产数据，也不自动启用未接通资金渠道。
