## 最终行为

- 商品：平台选用和本站自定义商品共用一个原生底部编辑面板、图片区域、字段顺序、库存操作和保存按钮。来源只在缩略卡右上角显示；两类卡片都有同样的红色“更多”，只在该处提供“移除商品”，详情内不再重复危险入口，也不再提供来源专属的上报菜单项。原上报处理函数和后端接口未删除。
- 平台选用商品仍使用原本站设置接口，仅写本站售价、押金覆盖、上架、优先展示和水票设置。`StationCatalogSettingDTO` 本来没有名称、品牌、规格、类型、说明和图片覆盖字段；`CatalogServiceImpl.updateMyProduct` 本来也只接受本站自定义商品。本轮在共同面板逐字段只读并解释具体限制，没有新增本站覆盖模型，没有写公共模板或别站商品。图片区域及按钮位置一致，受限制的图片操作显示禁用。
- “实物短缺”统一改为“商品短缺”；库存仍由原独立命令提交，不混进资料保存。原单恢复、保存快照、图片回执和身份隔离继续保留；面板关闭释放滚动锁，继续编辑恢复对应模式。
- 配送计费保留单页一次保存，增加“起送条件 / 配送范围 / 配送费 / 楼层费”四个锚点。导航扣除实测自身高度，避开标题和错误字段；三种处理方式与楼层按单/按桶改为横向选项，只展示所选说明及必要金额框。切换时保留隐藏字段原输入，提交仍包含原 13 个字段，空值与 0 转换未改。原加收费必填校验定位实际字段；没有新增计费规则。
- 保存计费栏贴底，包含安全区占位、正文末尾留白及键盘偏移；窗口已消费的键盘高度不会重复上抬。
- 上线准备：首页只显示后端 `doneCount/totalCount` 的紧凑入口，待上线且尚有必填时用常亮橙点；状态或进度未知明确写待核实。已营业或必填齐全时收为查看入口，不铺七项清单，也不闪烁。复用营业状态准备面板，按后端 `route/where` 分组，沿用后端目的路由。
- 水站资料、商品、配送计费三处仅显示本模块未完成的 `P0` 必填任务，任务定位对应字段、表单或商品列表；资料、选点、商品及计费保存后重读真实清单。计费页不再展示其他模块的大块“本站还差这些”。读取失败保留明确重试状态，不当作完成或 0 项。

## 上线规则核对

现有 `ManagerStationStatusController` 在待上线水站转正常运营时调用 `StationSetupGuideService.guide`，只检查 `p0PendingCount`。现行四项必填是联系电话、位置、上架商品、配送计费；水票、工资等建议项不挡上线。已经营业的水站不因后续建议项缺失被重新下线。本轮完全复用这个后端闸门，前端进度只展示事实，不自行宣布可上线，没有增加必填功能。
