## 事实基准

发生冲突时，以这个顺序为准（高 → 低）：

```
1. 源码               AquaFlow-backend/src/**、miniapp-*/**（含 wxml / js）
2. 表结构             AquaFlow-backend/sql/schema.sql
3. 通过的集成测试      与接口的实际行为
4. 根 AGENTS.md       工程契约（领域不变量、已知坑、禁改项）
5. docs/**            说明性文档（本目录）
```

**任何一条文档若与代码冲突，以代码为准，并回来改文档。**

## 维护规则

本目录的文档曾经大面积过期，根因是**同一个数值被写在多处**，改代码时改不全。
因此立三条规则：

1. **数值不重述，指向正本。** 会漂移的计数（测试类数、用例数、表数、迁移号、页数…）
   只在唯一真相源处定义，其他文档写指针。

   | 想知道 | 真相源 |
   |---|---|
   | 表与字段 | `AquaFlow-backend/sql/schema.sql` |
   | 迁移顺序与执行证据 | `AquaFlow-backend/sql/README.md` |
   | 枚举取值 | `AquaFlow-backend/src/main/java/com/example/aquaflow/constant/*.java` |
   | 接口实路径 | `controller/**` 上的注解（与 `api/01-REST-API参考.md` 双向对账） |
   | 测试件数 | `AquaFlow-backend/build/test-results/test/*.xml` |
   | 仓库结构 | 直接看目录树 / `code_map` |

2. **代码变更时同步更新它的真相源**，其他文档通过引用获取该事实，不复制。
3. **文档过期按缺陷处理** —— 发现漂移就修，不做"顺手改一下"。

## 文档分区：哪些入库、哪些只在本地

**一份文档只服务一类读者、只干一个活**（判据见 `AGENTS.md` §6.3）。除此之外还有一条**入库口径**，新增文档前必须知道：

| 区 | 位置 | 入库 | 说明 |
|---|---|---|---|
| 规格与契约 | `architecture/` `api/` `operations/` `development/` `design/11-35` | ✅ | 读者是仓库外的人，必须能被 clone 到 |
| 工程契约 | `audit/` 根上那 4 份 | ✅ | CI 与源码注释直接引用它们 |
| 历史记录 | `audit/` 下的历史区 | ❌ | 交付报告、回传包、演练记录、评审意见 —— **只追加、不当规范读** |
| 归档区 | `_archive/` | ❌ | 已冻结或不再维护的体系（含被产品裁定"当它不存在"的日式 `AQ-*` 规格体系） |

⚠️ **本机件不得被已入库文件点名**：写进本文件 / `AGENTS.md` / `CONTRIBUTING.md` 的路径，必须是 `git ls-files --error-unmatch <路径>` 能命中的，否则推上去就是死链。判据全文见 `AGENTS.md` §6.3。

> ⚠️ **日式规范体系（`AQ-*`）已冻结（2026-09-24 产品裁定）**：`AQ-REQ-*` / `AQ-BDD-*` / `AQ-DDD-*` / `AQ-TST-*` / `AQ-TSTR-*` / `AQ-OPS-*` / `AQ-PROC-*` **一律不再维护，不作为规格或判据来源**，已整体移入归档区。**不要引用、不要按它们改别的文档。**
