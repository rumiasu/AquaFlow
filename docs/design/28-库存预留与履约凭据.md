# 28 · 库存承诺、预留与实际交付

状态：当前规格；2026-10-01 核对。实物总量与活跃预留分别管理，不再把下单镜像字段称为已出库。

## 1. 两个数量

`inventory.quantity` 是本站尚未交付的实物总量。可用量 = 实物总量 − 活跃凭据已预留数量。订单需求可以高于当前可预留量，差额是等待需求，不是已承诺现货。

不区分库房和车仓，不做路线装车模块；这项范围不等于可以把已经给客户的货算在库存。

## 2. 下单与缺货

下单只预留，不扣实物。缺货必须明确展示不足并得到知情等待确认；不能仅给员工提醒、同时向客户显示现货交付。

有效权益占用与库存预留协调，但两个资源分别校验：有权益不表示有水，有水也不表示客户可复用已经分配的容量。

## 3. 补货、释放及改派

入库增加实物后按 FIFO 补待预留需求。取消只释放凭据，不“补回”从未出库的货。释放、换站后同样重算可用量及等待分配。

合法换站时释放原站凭据、新站按可用量重建，缺货明确保留。订单指向新站不证明那个站以前扣过货，不能按新指针凭空回补原库存。

## 4. 实际完成交付

必须是当前履约站、足额凭据和足够实物才可完成出库；任一条件不足拒绝标记完成，不能静默少扣。正常交付整单完成，少送/错货记录真实事实并走异常，不虚填全量。

## 5. 实物盘亏

站长登记实际损失及当时库存依据。损失只减少实物，保留较早 FIFO 预留，后续不足回到待补需求；不能为让库存数合理而自动取消客户已付订单。

客户是否延期、换单或退款由服务责任站联系处理，独立押金不因此消失。无库存成本不等于成本零，利润报表不得靠默认零给出完整净利。

## 6. 等待与释放

有新权益凭据的未付桶装订单，在无活跃付款请求时默认 15 分钟取消释放。付款请求待确认时不猜结果；其他未付单沿用人工取消。已付等货不自动删除，缺货待办由站长处理。

可选期望时间属于请求，不自动形成交付承诺，不新增复杂预约审批；唯一正本见 [design/16 C-05](16-范围决策与实施路线图.md#c-05预约时间是请求还是站方承诺超过承诺如何退出)。库存不足仍提示实际等待原因，不伪造已备齐。

## 7. 数据和验收

事实来源为 `inventory`、`inventory_reservation`、`inventory_record`。`order_item.deducted_qty` 只是当前预留镜像。校验下单/取消实物不变、跨站凭据正确、补货 FIFO、盘亏保留需求和送达足额出库。
