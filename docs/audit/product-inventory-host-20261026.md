## 可验证根因

原 `products/index.wxml` 常驻两个 `page-container`，首个绑定 `showEdit`，第二个绑定 `showInventory`。库存事件将 `showInventory` 置真，同时 `page-meta` 写入 `overflow: hidden`。微信原生只生效首个容器，第二个未显示，页面却被锁住。

本轮在微信开发者工具中使用原商品 JS/WXML/WXSS 与离线合成目录复现：点击卡片库存后，运行时 `showInventory=true`、`showEdit=false`，截图仍是目录；随后点击编辑，编辑弹层出现。修复版同一原生渲染器中，库存弹层可见，实测左上角 `(0,56)`、尺寸 `390×697`。这是实际模拟器截图证据，不是 HTML 投影；合成目录、请求适配器和简化 App 仅用于隔离测试，没有生产业务写入。

原通用 WXML 测试把第二个容器子节点当成可见，未检查原生 host 的 show 状态，因而此前库存状态断言不能发现此问题。

## 修改

- 商品与库存共用一个常驻原生容器；按当前任务路由遮罩与原生返回事件，保留两个独立表单和滚动区。
- 相同商品库存连点不清空已输入数量；从库存切到编辑先保存未提交库存草稿，之后可恢复。
- 卡片直接显示红色“移除”，去掉只有一个移除选项的菜单层；调用原来源对应的移除确认，未改危险确认、库存清零要求或身份检查。
- 新增 11 项库存 host 回归并接入总跑；更新原菜单与原生容器的相关断言。

## 上报核对与简化依据

按只读全文引用检索、沿处理函数/API 下看一跳及原生事件追踪核实：

1. 原 `onProductMore` 只有“移除商品”，不包含异常业务；其定义及两个 WXML 调用点都在商品页。移除的一项菜单原用于折叠危险操作，本轮将入口直接命名为“移除”。
2. `onSubmitToPlatform` 调 `submitMyProduct`，用于将本站自定义商品上报给开发者考虑加入通用库。它仍可从顶部“上报记录”→“选择本站商品上报”→`onChooseReportProduct` 到达；不删除该业务/API。
3. 配送异常实现在 `utils/delivery-problem.js`，首页“配送遇到问题”和订单详情“异常反馈”共用它；后续由 `DeliveryTaskController` 的配送异常接口受理。它不是商品菜单的目录上报，不应为凑菜单移入。
4. 直接入口仍调用 `onDeactivate` / `onRemoveProduct`，因此只是少一层选择；取消和变更账号后的迟到确认不会写入。原确认文本、红色确认、公共商品库存要求及自定义商品历史保留未变。
5. 推荐保留必要业务并简化单项菜单，理由是入口语义更明确且不重复危险按钮；未删后端、端点或文件。
6. 风险为低：前端可逆交互调整；仍需真机复测原生返回、键盘及安全区。
