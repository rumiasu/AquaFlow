# 12 商品目录、本站销售与库存

写给配置商品的站长和维护商品域的工程师。本文是现行规格；库存凭据的完整规则见 [28](28-库存预留与履约凭据.md)，资产规则见[领域模型](../architecture/02-领域模型.md)。

## 1. 商品和经营配置分别负责什么

`product` 定义商品身份、包装、分类和参考信息。`owner_station_id=NULL` 是通用商品，站属自定义商品只供所属站使用。本站的选用、上架、价格、押金、水票设置和实物库存由站级配置承载。选用不等于上架，上架不等于有现货。

客户按所选归属站看到该站可卖的商品与价格。跨站履约不改变客户成交价。通用库由受控维护流程管理，仓库没有平台商品管理前端；站长提交收录申请也不等于自动进入通用库。

## 2. 报价和历史

报价和建单使用同一商品计价、配送计费规则。本站配置优先，参考值只按既有回落规则使用；不能把参考价当作平台统一成交价。水费、配送费、楼层费分别快照，独立押金购买另成款项。

成交后的商品名、数量、单价及费用不会跟随商品改名或改价重算。已买权益按原批次退押金，水票按实付批次记录价值。停售阻止新的经营入口，不能抹掉客户已有资产或历史售后。

新购水票同样要求商品在售、属于通用库或本站、且本站已选用并上架；统一折扣不绕过这些条件。现货数量为零不等于停售，仍可预购水票，不承诺即时配送。停售前已建立的购票申请仍按原款查回、继续收款并按原金额入账，不能因当前商品配置变化重新建款或重复入票。

本站价格偏离参考值可给非阻断提醒；参考值未知不能伪造偏离比例。提醒配置是经营参数，不是尚待决定的核心规则。

## 3. 分类的业务影响

循环桶装水涉及权益、交桶和回桶。瓶装水、饮水机等不进入回桶模型。当前没有独立的免押循环桶方案；一次性包装不能借用循环桶分类来绕过资产规则。商品兼容不等于桶型可互换，首期按商品隔离，不能用一种水的多桶抵另一种水的欠桶。

## 4. 库存承诺

实物在库量和可用量分别展示。订单建立预留，正常完成配送时才出库；取消只释放预留。盘点和损失是实物事实，不是取消订单退款。缺货可以在知情确认后等待，但缺货订单不具备凭空完成配送的资格。完整跨站搬预留、FIFO 待补及盘亏规则以 [28](28-库存预留与履约凭据.md) 为正本。

## 5. 维护入口与验证

站长在商品页选品、设置本站价格与销售状态、入库或盘点；顾客在本站商品列表和结算页消费。当前 API 实路径查 [API 参考](../api/01-REST-API参考.md)，不另维护一份端点清单。

三款首批水商品资料模板复用上述公共选品与本站自定义入口，带可编辑基础资料和中性示意图，站级售价/押金/库存仍需确认、默认不上架。公共SKU身份不被模板改写；需改容量时可明确另存本站商品。来源与图片边界只在[商品素材 §5](14-商品图片库与常见水种清单.md#5-2026-10-21-首批可编辑水商品模板)维护。

新空库的可选公共身份初始化使用 `sql/seed_platform_pulisi_185.sql`，只补缺失，不修改存量、站级配置或历史凭据；不自动选用/上架。参考金额必须显式确认，不把缺参当0，也不改变现有合法零值/清除覆盖语义。执行方式、升级和回退边界以 [SQL初始化正本](../../AquaFlow-backend/sql/README.md#可选公共商品目录三款185l2026-10-21) 为准；脚本存在不证明真实云库已执行。

验证应覆盖站属商品隔离、上下架、报价与建单一致、改价不改历史、非桶装商品不回桶，以及缺货和释放后的待补后果；通过某个页面保存不等于这些后果均已验证。

### 5.1 商城读取与经营输入边界（2026-10-21）

顾客商城的商品、营业提示和水站候选读取绑定登录周期、当前选站与本页读取轮次；隐藏/卸载使旧回执失效，同站刷新也只接受最新结果。切站的两次弹窗回调重新核对原上下文和当前候选；旧回执不写选站或“不再提示”偏好。公开目录失败清除旧候选，正常空目录仍是空状态，损坏的非数组响应不是有效目录。

加清单和立即购买只接受当前页面、当前身份/站点的已加载商品；过期卡片事件不写另一站清单或跳转。购物车仍复用App原有按客户/水站隔离的持久化，不清空、合并或迁移；切站即刷新本站数量角标。商品读取失败时，同一客户同一站的已有清单仍可进入结算核实，不把局部读取失败变为资产或下单权限政策。营业软提示、待营业站筛选及服务端建单重算保持原规则。

站长新增/编辑、本站价格设置和库存动作必须完整解析输入，不能用parseFloat/parseInt把`12junk`变成12或把1.5桶变成1桶后提交。金额的有效业务范围仍由现有服务端规则决定；库存必须是非负安全整数，入库仍须大于0。空选填值、0清除本站价格覆盖、非桶装不提交押金覆盖，以及模板默认不上架/经营数据确认保持原口径。仅同步ManagerProductDTO注释，不修改API、SQL、服务端金额规则或权限。
