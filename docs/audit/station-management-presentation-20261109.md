# 站长经营数据呈现与订单管理收口（2026-11-09）

本记录写给接手工程师，说明本轮站长页调整、数据口径和验证边界，不替代经营规格或上线验收。

## 范围与取舍

基线为开发分支 `codex/stage-handoff-20261004` 的 `f05e2ae894dd6af79e6b9c194e72807ed837b651`。按站长日常流程核对：先安排待配送，再确认实际收款及逾期，最后按期间查看销售与合作款；订单详情和明细承担下钻，不把所有解释铺在首屏。

- 订单管理是查询入口，派单/外派复用工作台，收款复用收款确认，避免另外建立操作链。
- 看板已有订单金额、已付款订单与口径说明，工作台已有待办优先层次；不为增加改动量再造指标或重排全部模块。
- 本轮不改变价格、实收、应收、退款、工资或站间结算写入逻辑，不新增表、迁移或配置。

## 实施内容

### 订单：先看当前待办，再查历史

- 默认进入待配送，历史和全部仍保留筛选；本站订单先于跨站归并信息。
- 配送安排、付款状态和付款方式使用已有服务端数据；仅在服务端明确 `needCollect` 且待收数值可用时显示现场待收。
- `collectAmount` 与 `totalAmount` 分列，组合水票单不把订单总额当现场余款；未知待收金额不回退到总额。
- 订单金额始终明确命名，跨站履约汇总不称实收；完整商品摘要保留，历史地址与收付款明细下钻。
- 派单和收款有直达入口，短说明不复述按钮含义。

### 利润与合作款：重要金额常显，依据按需展开

- 核心数字旁显示服务端确认的期间，不让用户猜测正在看哪段时间。详细日期控件按需展开，避免筛选表单把合作待交/待收推到首屏之后；小屏日期选项保持整词与触控尺寸。
- 既有销售收入统计包含订单金额与购票实收，不是现金实收；本轮只澄清展示，不改公式或历史口径。
- 成本不全只遮住不能核实的利润，不再连带隐藏合作待交/待收和商品明细；缺成本不展示为零利润。
- 合作待交、待收先显示，原约定、客户实款、合作交收款及退款后返还按组展开，登记净现金不冒充利润。
- 本月快捷重进页面仍由服务端确认当前月份；近 7/30 天按日历日期回退，不按固定毫秒数减天。

### 合作报表：保留原票价，不改变实际结算

`GrossProfitCooperationMapper.agreements` 原先只从已消费的 `ticket_record` 算票值。v90 票仍预留时没有消费流水，已接受外派的原报价差额会少计票值。

现对 v90 单读取 `order_ticket_hold` 的原批次数量与单价快照；不与消费流水相加，避免消费后双计。消费、退款或交付前释放均保留原报价事实，不能随当前持票状态重写历史约定。旧单仍沿用原消费流水路径。该值是原报价差额，不是实际收款或利润，也不改合作款、退款和返还的实际状态。

### 应收：入口与回执保持当前查看对象

- 工作台逾期客户入口带逾期筛选，普通应收入口仍查看全部待收。
- 已有待收订单没有到期日，不再被说成客户当前未设账期。
- 收款回执离开客户或更换登录会话即清理；发出登记后切到其他客户，迟到结果也不能写到新客户。
- 现金可登记、微信原款、跨站仅能登记不能查看订单等不同下一步仍沿用服务端指引。
