# 16 · 范围、业务决策与执行记录

核对日期：2026-10-01。本文区分已经确定的目标、已经验证的实现和仍待产品决定的核心规则。新决策只在 §12 留一处正本；原收款主体问题继续在 §9.3 登记。旧稿已保留为[历史快照](../audit/2026-10-01-范围决策重写前快照.md)。

## 1. 项目目标

为水站建立可解释的订水、配送、桶资产及资金闭环。客户知道自己的消费、押金、实物和未完成申请；站长知道待履约、欠款、待退款及合作站责任；配送员只登记自己实际执行的事实。

目标是支持真实经营，不以功能数量、测试数量或技术栈定义“企业级”。真实渠道、业务承诺和可收口的异常是上线目标的一部分。

## 2. 已确定的产品范围

## 3. 经营责任

客户价是归属站给出的承诺，不能随外派重新收取。外包报酬可以高于客户实收，差额由 A 承担；费用快照、收款事实、客户资产和站间债务分别可查。实际容器交接不自动等于客户押金金额。

现有“水厂承担库存桶损耗”是旧范围中的不入自有桶资产账取舍，不表示对合作站或客户的一切桶损均可免责。合作交接及搬运保管责任仍须按事实核对。

## 4. 产品验收原则

资金只在实际发生后登记，权益不能重复兑现，实物不能因付款或退款凭空增减。取消不能抹去已经交付；冻结应有事实依据；业务等待应有人负责并有退出动作。每项例外都说明客户、本站、合作站分别受到什么后果。

## 5. 已形成的用户入口

客户办理权益、购票、订水、申请资产退出；站长调度/外派、确认各类实际款、消费售后、批准退桶、缺货和信用待办、站间交接/返还、余票退出。相关入口见 design/15、19、27、28、34、35。

### 11.2 必须补入规格的设计约束

这些约束用于防止既有事实被新模型误解释；其中经营选项在第 11.3 节登记，不能由实现者临时决定。

1. **付款、资产和实物是不同事实。** 收到一份押金后客户可以有权益却没有桶；实际送出、收回决定客户手上的桶数；买/退权益决定合法容量与可退金额。取消水单不自动撤销已独立付款的权益，也不再套用旧模型“权益等于已到手桶”的解释。桶已收而退款未到账时，仍保留退款责任并阻止原权益再次领取。
2. **水票和已履行的服务不能在退款中被重复兑现。** 当一张票已包含水和配送，而只退水费保留已履行配送费时，退回完整一张票会重新赋予一整次配送。需要选择整票退回且责任方承担服务成本，或引入可解释的拆分结算；不能同退整票又宣称已经从票里扣了服务费。
3. **退款不能让未交付订单继续无条件履约。** “只退钱、不取消订单”适合已交付后的售后；交付前退掉消费款，须明确取消履约或存在经站长授权的补偿供水。首次资格只随真实交付消耗，退款申请本身不证明已经交过桶。
4. **买押金失败与买水失败有不同后果。** 押金成功、购票/订水失败时，保留真实资产并允许继续或申请退出；不假装整组交易从未发生。支付结果未知时先核实原交易，不能重收或贸然解除可能仍被有效订单占用的资源。
5. **信用、欠款、免债与认损分别表达。** 站长确认拒付才能启用拒付限制；会计认损不当然等于免除客户债务。真正免债后不能继续追缴同一应收。关闭新增货到付款权限不能同时使原欠款无法偿还；原债务收款由原债权站确认，不因客户不能创建新的现金订单而失去登记入口。欠 B 的钱若影响 A 的资产，须有 A 可核实的合作订单与处置依据，不能跨平台自动冻结。
6. **实物与退款的钱分开核销。** 批次买入金额决定应退押金，当前涨价不重算旧批次；首次领取/暂存取回/退桶中的占用都不能抹去批次来源。无押金赠送、历史人工补录不得仅因数量相同自动变成可退现金资产。
7. **跨站移交不搬走已经发生的收款。** A 已收服务款或消耗 A 的票时形成 A 对 B 的结算；B 已实际收现金时不再让 A 重付。首次由 B 净送出一个桶必须说明谁供桶、谁补偿，容器价值不自动等于客户押金。
8. **跨站退款要区分承诺和已付款。** 未付 B 时取消/调整应付；已付 B 时另保留应追回或责任方承担的金额。冲销历史记录不表示现金已收回。客户消费款按原路退，A/B 内部追偿独立跟进，不把两站协商状态伪装成客户已退款。
9. **外派价格、退款承诺和退桶金额要有当时依据。** 接单后不能读取新配置重算已承诺收入；改派后的新接收方取得新的明确承诺，旧方已履行费用按异常约定处理。追偿按退款责任决定，不能无条件追回 B 的全部报酬。
10. **商品不自动等于可互换桶型。** 现有资产和票按商品隔离；若不同商品共用一种物理桶，必须决定是否认可换水时复用权益。首期保持原隔离时，要说明客户不能直接换用其他商品，不静默扩张兼容关系。
11. **等待有负责人和退出动作。** 未付占用须能超时释放；已付等货订单不能同样静默删除，须通知结果并允许延期、取消或异常处理。退款和协商也须可查询、可催办，不能靠客户一直等待。
12. **新旧模型不能混算。** 旧待交付订单、已付押金、已到手资产、暂存/欠桶、待退押金、已结清跨站款按历史来源分类。历史桶数量不能作为生成首次免回资格的唯一依据；须保留原单、批次单价、实际资金状态及迁移前后核对结果。

### 11.3.1 双路径范围纠正（2026-10-03 已确认）

单独买押金是增加一种办理方式，不能据此强制把所有水单拆成两次付款。水与新增押金可同次支付，逐商品押金购买、资产及退款仍分别留凭据。以下三个边界已经确认，无须新建待拍板议题：

1. 已付未交付取消，只退本单新增且尚未被其他用途占用的容量押金；先前独立购买的资产保留。
2. 现金可到门收水款与押金，须实际收齐后才激活容量并交付；失败时钱、资产和履约写入同时回滚。
3. 已有容量被占用时，客户可等待释放或明确另买；未经确认不得静默多收押金。

实现落点为 `OrderBarrelPurchaseService`、新原款凭据及 SQL v74；报价与建单使用同一缺口算法。C-01 实际商户主体、C-07 实际退款回执等未决议题继续在原位置维护，本纠正不替它们作决定。

### 11.5 场景验收清单（实施核对口径，实测记录见 §11.6）

| 场景 | 必须成立的业务结果 |
|---|---|
| 只买权益后退出 | 付款成功即有权益，没有实物；申请退款不要求交桶，不产生收桶费，实际资金成功后终止领取资格 |
| 押金成功，购票或订水失败 | 已购权益保留；用户能继续办理或退出；不重复收款，不自动把独立资产款算成水单退款 |
| 一份权益买十张票 | 购票十张允许；每次兑水仍按桶容量分配；订单占用期间可储票，不能复用同一份权益兑水 |
| 买票后退掉权益 | 提前说明剩余票可用条件/退出路径；再次兑水检查权益，不能绕过前置门槛 |
| 一份权益并发两水单/水单与退桶 | 只有一个请求取得该份占用；其他闲置权益仍可使用；未知付款不能导致重收或重复分配 |
| 旧二份加新一份送三桶 | 默认回二桶，新领一桶免回；实际数量独立记录；取消前/交付后首次资格结果不同 |
| 客户已有额外欠桶再买权益 | 按拍板口径解释已持有实物和可领取数量；不会既声称已补欠桶又重复赠出相同无担保容量 |
| 已有桶暂存在站里再订水 | 不要求客户交不存在的旧桶；领取数量来自可用权益和实际暂存，不无上限发免回资格 |
| 送达后只退水款 | 合法桶权益与原押金保留；服务费按责任处理；用票退款不重复获得未扣清的额外服务资格 |
| 未送达先退水款 | 停止原未授权履约并释放相关占用；独立买的权益仍保留；额外免费供水须是明确补偿决定 |
| 拒付、正常账期、服务争议各一单 | 状态与限制分别正确；拒付不扣旧押金；旧债清偿、免债或争议结案后的恢复结果明确 |
| 退桶申请与顺路订单取消 | 相关数量锁定；不经同意不改收费上门；桶交接与到账确认分开，退款失败保留待退责任 |
| A 收押金，B 首次配送 | A 资产不迁移；B 净出桶有供给/补偿约定；水费、服务报酬与容器补偿不会混算 |

| 加价外包及接单后的配置变化 | A 看清完整给 B 的报酬及补差；接受后承诺保留；改派需新接收方明确接受，客户价格不被暗改 |

| 盘亏/停售/经营停止 | 保留真实损失和已收资产责任；受影响客户有延期、退款或同意替代的出口 |
| 旧资产/旧待交付/旧待退款切换 | 买入批次金额、领取资格、实际桶数和未结款项前后可核对；旧已领桶不重新获得首次免回资格 |

### 11.6 实施交付与边界（2026-10-01）

第 11.4 节各阶段已形成代码与两端入口：独立权益购买、按数量分配、购票/兑水门槛、交付默认回桶、消费组成退款、申请制资产退出、拒付保留欠款、外派总报价、逐商品实际净桶协商、站间返还追收、实物损失与待补、真实购票批次退出。验证的最终结果在本节下方登记，不能把模拟资金联调当作线上真实支付验收。

客户路径：桶页面“交押金办理权益” → 原归属站确认实际款 → 买票或订水 → 新领部分免回桶、旧有部分换桶 → 结束服务时先线上申请 → 站长审批安排和单独收费 → 客户确认 → 双方确认桶已交接 → 原渠道实际退押金。未领取的容量退款不要求交不存在的桶，也不收上门收桶费。

站长路径：订单详情分水费/服务费退款；退桶审批页批准、收费及实际退款分别办理；外派详情可改完整报酬和桶安排，B 接受后冻结；“业务待办与退出”查看缺货、超时退款、拒付冻结、站间返还、实物/桶款交接，以及按原款剩余票退出。

资产展示已区分有效权益与客户实际持桶；只交押金而未下水单的客户也可按本站绑定查到权益。退还试算排除已被其他订单分配的未领取容量，避免把尚未领到的桶误要求交回。待收款用途由服务端区分订单消费、水票、独立押金和上门收桶费。

现有销售及利润报表仍沿用原统计口径；外包完整报酬、补差、桶款与追偿查看站间协议和台账。本轮没有把它们自动并入一套新的财务报表，不把销售金额展示当作站间资金已经结清。

售后赔偿继续走既有站长异常/资产调整单，记录原因、正向金额与责任，不把赔偿伪装为无限额正常退款。企业独立账户、跨商品兼容桶型、逐桶编号、车辆分仓、自动资产跨站迁移、正常部分交付均未扩入本轮。真实微信支付/退款接入仍是原有未完成事项；本轮已做到不可用时拒绝假成功。

2026-10-01 实现的部署入口为 `AquaFlow-backend/sql/README.md` 的 v71；2026-10-03 双路径修正还需 v74，现行安装要求以 SQL 索引为准。隔离库验证不能授权执行真实业务库迁移；本轮没有部署生产、没有改生产数据，也没有提交推送。

## 12. 核心业务决策复核（2026-10-01）

这次复核只检查目标、权利、责任和范围。C-01 是此前尚未决定的老问题，其唯一正本仍为 §9.3。以下 C-02–C-11 是场景推演、渠道接入及本地审计准备确认的缺口。2026-10-05 用户已确认其中部分经营方向；各项明确区分已定口径、仍待拍板的细节与实际实现。模块对应位置只留指针，决策详情只在本节维护，不能把方向确认写成能力已经上线。

### C-02：欠桶可以下单，是否必须继续借出更多实物桶

已定（2026-10-05）：借桶/欠桶按回桶异常处理，不新增系统级事前借桶审批或固定欠桶上限。配送现场醒目显示应回、实回及差额，如实记录实际回桶数，原因选填；没有原因时保留未说明差额，不自动补成“其他”，已有合法原因照实留痕。原因可只说明已知部分，已填数量不能超过实际差额。

这项裁定只降低回桶异常填写摩擦，不取消客户已付容量及用途占用，不把未付押金视为有效容量，不放行尚未收齐本单水款与新增押金的现金交桶，不因欠桶自动收钱或扣押金。账务物理上限、库存预留、订单状态与幂等仍校验。

实现落点：design/15、18、20 的配送口径，完成页差额提醒/原因选填及 `OrderWorkflowServiceImpl.completeDelivery` 的原因校验；未新增借桶审批端点或状态。历史推荐事前批准方案不实施。
