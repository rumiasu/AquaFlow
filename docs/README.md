## 4. 维护规则

代码与表结构决定“现在实际怎样”；产品决策决定目标，尚未实施的目标必须明确标注，不能靠改文档假装功能已经具备。通过的测试证明覆盖到的后果，不保证未测场景或真实渠道。

文档编号和文件名保留，避免源码引用断掉。修改一个业务规则时，同步领域模型、流程和模块规格；待决策只登记一个正本。历史审计只追加说明。目录不手写会漂移的表数、端点数和测试数。

本轮逐篇状态见[文档复核清单](documentation-status.md)。数据库升级顺序只维护在 SQL 清单，不因 Git 新历史而重排。
