## 1. 本机事实（换机器/换网络后需重新核对）

| 项 | 值 | 怎么自查 |
|---|---|---|
| 后端端口 | 8080，监听 `0.0.0.0`（Tomcat 默认，未设 `server.address`） | `netstat -ano \| Select-String ':8080\s'`，看是不是 `0.0.0.0:8080` |
| **dev 规范地址** | `192.168.137.1`（**笔记本「移动热点」**，恒定；真机走它、开发者工具走 `127.0.0.1`） | `pwsh -File scripts/set-dev-api-host.ps1`；见 §1.1 |
| 局域网 IP（**仅逃生口用**） | `192.168.0.243`（WLAN，**DHCP 分配**，会变） | `ipconfig`；**不用 VirtualBox 的 `192.168.56.1`** |
| WLAN 网卡 MAC | `2C-98-11-4E-67-2B` | `ipconfig /all` → WLAN → 物理地址 |
| 网关 | `192.168.0.1`（**就是你的移动WiFi**） | 同上 |
| MySQL | Windows 服务名 **`MySQL`**（Running，自动启动）；库 `aquaflow` | `Get-Service *mysql*` |
| JDK | `D:\backend\jdk17`（Java 17，项目 toolchain 要求） | `java -version` |
| 小程序 appid | **两端各自独立**：顾客端 `wx12632a1cdca9fbcc`、员工端 `wxc6211615c79da9f9`（沿革见「当前实际在用的 appid 组合」那节） | `miniapp-*/project.config.json` 的 `appid`（私有配置里没有 appid，不会覆盖） |

**为什么真机不能用 `127.0.0.1`**：真机上的 `127.0.0.1` 指**手机自己**。手机必须打笔记本的地址，
所以两端 `config/api.js` 的 `dev.baseUrl` 写的是 `http://192.168.137.1:8080`（两端一致，见 §1.1）。

### 1.1 dev 地址：定成一个值，切上行网络不用改

**结论（2026-09-21 定）**：`dev.baseUrl` = **`http://192.168.137.1:8080`** —— 笔记本「移动热点」的地址。
**它与笔记本自己用哪个网上行无关**，所以移动WiFi ⇄ 手机热点来回切，这一行都不用动。

| 谁 | 走哪个地址 | 为什么 |
|---|---|---|
| **真机**（预览扫码 / 体验版） | `http://192.168.137.1:8080` | 手机连的是**笔记本热点**，这个地址就是它的网关，恒定不变 |
| **微信开发者工具** | `http://127.0.0.1:8080` | 工具与后端在**同一台笔记本**上；这样热点没开也能写代码 |

- 两端 `config/api.js` 里分别写作 `dev.baseUrl` 与 `dev.devtoolsBaseUrl`，由 `isDevtools()` 分流；
  分流是「**先确认是工具**才用回环」，取不到设备信息一律当真机（失败必须朝向真机地址）。
- `192.168.137.1` 是本机 ICS 的规范地址，实测注册表
  `HKLM:\SYSTEM\CurrentControlSet\Services\SharedAccess\Parameters\ScopeAddress` = `192.168.137.1`。

**为什么只有它能"一个值走天下"**：`dev.baseUrl` 是**手机**要访问的地址，而手机连在笔记本热点上 ——
笔记本自己用哪个网上行（移动WiFi / 手机热点）**根本不参与这个地址**。对比：

| 钉哪个地址 | 移动WiFi 上行 | 手机热点 上行 |
|---|---|---|
| WLAN 局域网 IP（如 `192.168.0.243`） | ✅ | ❌ 网段不同不可达；**且会被 DHCP 换掉**（实测 `192.168.0.243` ⇄ `10.213.244.181`） |
| 移动WiFi 网关 `192.168.0.1` | ❌ 那是网关、不是笔记本 | ❌ 完全不可达 |
| **笔记本热点 `192.168.137.1`** | ✅ | ✅ |

**代价只有一条：真机测试时笔记本的移动热点必须开着**（只写代码不测真机则不受影响）。
⚠️ 手机热点当上行时，手机自己是 AP、**连不上笔记本热点**（一块网卡不能同时当 AP 和 STA）——
这种情况改用 **USB 共享网络**（手机 Wi-Fi 就空出来了），或临时用下面的逃生口。

##### ⚠️ 「不用再改」的边界：什么情况下会失效

> **先分清两件事**（问"是不是保证不会变了"时最容易混）：
> - 「**小程序配置里那个值不用再改**」= **成立**（前提是下面三条都没踩）。
> - 「**这台电脑的 IP 不会变**」= **不成立，而且我们没打算让它成立**。WLAN 网卡至今仍是
>   DHCP（`netsh interface ipv4 show config name="WLAN"` → `DHCP enabled: Yes`），
>   在移动WiFi 与手机热点之间切换、租约重分配，它照样换号。
>   **但没有东西指向它了** —— 只有 `-Lan` 逃生口会用到它，所以它变了也不影响真机。

| 会失效的情形 | 现象 | 怎么办 |
|---|---|---|
| 真机测试时**忘了开热点** | 真机（扫码预览）一片网络错误；**开发者工具不受影响**（走 `127.0.0.1`） | 设置 → 网络和 Internet → 移动热点 → 打开 |
| 手机既当上行热点、又要跑小程序 | 手机连不上笔记本热点（一块网卡不能同时 AP + STA） | 改用 **USB 共享网络**，或 `-Lan` 逃生口 |
| **ICS 换段**：「网络重置」，或上行网络本身正好占用 `192.168.137.0/24` | 写死的 `192.168.137.1` 指向一个不存在的地址 | 脚本会**读注册表 `ScopeAddress` 比对并报红**；按它给的 `-Ip <新段> -Apply` 修正 |

> ⚠️ **别指望用主机名**（计算机名 / `.local`）：微信小程序的 `wx.request` 不解析局域网主机名，
> 而且「不校验合法域名」只跳过域名白名单，**不跳过 DNS 解析**。

#### 1.1.1 改地址 / 查状态：`scripts/set-dev-api-host.ps1`

```powershell
pwsh -File scripts/set-dev-api-host.ps1              # 只打印：地址来源 + 热点开没开 + 两端现在配的是什么
pwsh -File scripts/set-dev-api-host.ps1 -Apply       # 写回规范地址 192.168.137.1（两端一起）
pwsh -File scripts/set-dev-api-host.ps1 -Lan -Apply  # 逃生口：改用当前 WLAN 地址
pwsh -File scripts/set-dev-api-host.ps1 -Ip 192.168.1.5 -Apply   # 逃生口：显式指定地址
```

**两端必须一起改** —— 只改一端会让那一端白屏，而现象是「网络错误」，很难联想到是 IP 不对。

> ⚠️ **脚本在规范地址下刻意不做「后端自检」**（实测 2026-09-21）：热点**没开**时
> `ipconfig` 与 `route print -4` 里**都看不到** `192.168.137.1`，但裸 TCP 连 `192.168.137.1:8080`
> （Tomcat）与 `:3306`（MySQL）**都通**（`:80 / :443` 不通 —— 那两个端口没有服务监听 0.0.0.0），
> `netstat` 里本地端点本身就是 `192.168.137.1` ⇒ **本机 TCP 栈把它当本地地址**。
> 所以从笔记本探这个地址**永远"可达"**，那是自己打自己，**证明不了手机能不能连上**。
> 真机能不能用，只看脚本打印的「热点状态」—— 判据是 **`icssvc` 服务**（不是 ipconfig）。

#### 1.1.2 备查：移动WiFi 与 WLAN 地址（2026-09-21 之前是主方案，已降级）

只有"笔记本热点用不了、必须退回 WLAN"时才需要看这一节。

**你的移动WiFi 就是 `192.168.0.1`。** 实测（2026-09-21）：

| 探测项 | 结果 |
|---|---|
| 网关 | `192.168.0.1`（正在做 DHCP 与 DNS 转发；WLAN 地址由它按 **12 小时**租约发放） |
| 开放端口 | 只有 **22 / 53 / 8443**；**80 与 443 是 `Connection refused`**（不是超时 —— 网关活着，只是没服务） |
| 22 | `SSH-2.0-dropbear` → 嵌入式 Linux |
| 8443 | **明文 HTTP**（用 `https://` 打连不上），且**不是网页后台**：`/`、`/login.html`、`/web/`、`/cgi-bin/luci` 等**全部**返回 `Content-Type: text/plain` 的 `{"result":4,"reason":"REQ PARAM ERR"}`；换成完整浏览器请求头（Chrome UA + `Accept: text/html`）也一样 |
| 厂商 | **认不出** —— 网关 MAC `0a-5b-8f-27-9a-64` 是**本地管理地址**，不是厂商 OUI |

⇒ **这类随身WiFi 没有可点的网页后台**，所以「登录网关 → 找 DHCP 地址保留」这条路走不通（硬要配只能
SSH 进去改 dnsmasq，需要 root 密码，本文不给步骤）。厂商若有 App / 云平台，入口在那里。

**逃生口：笔记本设静态 IP**（不需要任何路由器权限，但要记得改回去）：

```powershell
# 固定（必须用「以管理员身份运行」的 PowerShell）
netsh interface ipv4 set address name="WLAN" static 192.168.0.243 255.255.255.0 192.168.0.1
netsh interface ipv4 set dnsservers name="WLAN" static 192.168.0.1 primary

# ⚠️ 离开这个 Wi-Fi 之前必须改回 DHCP，否则在别处直接没网：
netsh interface ipv4 set address name="WLAN" dhcp
netsh interface ipv4 set dnsservers name="WLAN" dhcp
```

> **另一条线索（未验证，不要当结论）**：本机装了 Tailscale，tailnet 地址 `100.70.47.116` **永久不变**，
> 实测后端在该地址上可达（`HTTP 200`）。若手机也装 Tailscale 并连上，`dev.baseUrl` 写
> `http://100.70.47.116:8080` 就能换任何网络都不改。
> ⚠️ **手机侧没实测过**（微信小程序是否走 Tailscale 的 VPN 路由未知），按 AGENTS §9 纪律只作线索。

**IP 变了怎么办** —— 见 §1.1：**正常情况不用改**（规范值 `192.168.137.1` 是恒定的）。
只有走了逃生口退回 WLAN 时才会遇到"地址会变"，跑 `pwsh -File scripts/set-dev-api-host.ps1 -Apply` 写回规范值即可。

> ⚠️ 改这个 `.ps1` 后**必须确认前三字节是 `EF BB BF`**：PowerShell 5.1 对**无 BOM** 的 `.ps1`
> 按系统 ANSI(GBK) 解码，中文变乱码后**直接解析失败**（报 `Unexpected token`，行号还看着莫名其妙）。
> 2026-09-21 实测：用编辑器工具改这个文件会把 BOM 抹掉，必须回补 —— 校验与回补：
>
> ```powershell
> $p='scripts/set-dev-api-host.ps1'; $b=[IO.File]::ReadAllBytes($p); '{0:X2}{1:X2}{2:X2}' -f $b[0],$b[1],$b[2]
> # 不是 EFBBBF 就回补（内容按 UTF-8 读，写回时带 BOM）：
> $t=(New-Object System.Text.UTF8Encoding($false,$true)).GetString($b)
> [IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($true)))
> ```

**两端必须一起改** —— 只改一端会让那一端白屏，而现象是「网络错误」，很难联想到是 IP 不对。

## 3. 手机真机预览（同一 WiFi）

1. 开发者工具点「预览」，生成二维码；
2. 手机微信扫码打开**开发版**；
3. 手机上点右上角 `…` → **打开调试**，重启小程序。

   ⚠️ 这一步不能省：`request` 合法域名只接受**已 ICP 备案的 HTTPS 域名**，
   本机 `http://192.168.x.x:8080` 无法配置进白名单；只有打开调试才跳过域名校验。
4. 手机与笔记本必须在**同一个 WiFi**。

### 防火墙（手机连不上的最常见原因）

Windows 防火墙默认拦入站。本机已添加规则（2026-09-15）：

```
规则名: AquaFlow Backend 8080
方向: 入站  协议: TCP  本地端口: 8080  配置文件: Domain,Private,Public  动作: 允许
```

**坑（这次真实踩到）**：防火墙里原本只有 `jdk25` / `oracle jdk` / `java` 三个路径的程序级放行规则，
**没有项目实际使用的 `D:\backend\jdk17\bin\java.exe`**，所以手机一直连不上。
换 JDK 路径或换机器后，要么按端口放行，要么补程序规则。管理员 PowerShell 执行：

```powershell
netsh advfirewall firewall add rule name="AquaFlow Backend 8080" dir=in action=allow protocol=TCP localport=8080 profile=any
```

自查：

```powershell
netsh advfirewall firewall show rule name="AquaFlow Backend 8080"
```

### 连通性探针（不登录就能用）

`GET /api/stations/public` 是免认证接口，最适合验证链路：

```powershell
curl.exe -s http://192.168.0.243:8080/api/stations/public
# 正常返回：{"code":0,"data":[],"message":null}
```

**用手机浏览器打开同一个地址**能出这段 JSON，就说明「手机 → 笔记本:8080」链路通了。

> `GET /actuator/health` **不存在**（返回 HTTP 200 + body `code:404`，只看状态码会误判成"后端正常"）——
> 本项目没引 actuator。探活就用上面这个 `/api/stations/public`。

### CORS 不用为真机改（[2026-09-20] 明确记下来，省得白折腾）

`application.yml` 的 `app.cors-allowed-origins` 默认只含 `localhost:5173/5174`，
唯一使用点是 `CorsConfig` 里的 `CorsFilter`。**微信小程序的 `wx.request` 不是浏览器 XHR、不带 `Origin` 头，
完全不受它影响** —— 真机联调不需要往白名单里加局域网地址。
只有当你在浏览器页面里直连后端时，`Origin` 不在白名单才会被 `CorsFilter` 直接 403
（报 `Invalid CORS request`）。看到那个报错，说明请求是从浏览器发的，不是小程序发的。

### 上传体积的边界（[2026-09-20]）

- `spring.servlet.multipart.max-file-size` = 10MB、`max-request-size` = 20MB；
  单张图片另有 5MB 的业务限制（`CommonController.MAX_FILE_SIZE`），超了给可读提示；
- 整包超 10MB 由 Servlet 容器在进入 Controller **之前**就拒绝 → 现在有专门的
  `MaxUploadSizeExceededException` 分支返回 `code=1` 可读文案（此前会落成 `code=500` + 一条 SYSTEM 告警）；
- **COS 未配时上传一律失败**（`code=1`「文件上传失败」，不是 500）。本地 `application-local.yml`
  的 `cos` 段已解注释，但 `secret-id`/`secret-key` 是空串 = 等于没配，要用得填真实密钥。

>   另有 1 条 `id=3` 是 `已送达(3)` 却 `payment_status=0` —— 那是 §8.15 强类型 DTO 丢字段事故的历史残留，**不是新 bug**；

## 5. 开发者登录（dev-login）

只在本机生效：`application-local.yml` 里 `app.dev-login-enabled: true`，
`DevLoginController` 同时带 `@Profile("!prod")` + `@ConditionalOnProperty`，
**prod 环境该 Bean 根本不存在、接口 404；`DEV_LOGIN_ENABLED` 上线必须保持 `false`。**

```
POST /api/auth/dev-login
{"role":"STATION_MANAGER"}   → 站长（不存在则自动建 staff）
{"role":"DELIVERY"}          → 配送员（不存在则自动建 staff，并挑一个水站）
{}  或 {"openid":"dev-openid-001"} → 顾客（默认 openid dev-openid-001，不存在则自动建 customer）
```

实测（走局域网 IP，非 localhost）：

```powershell
curl.exe -s -X POST http://192.168.0.243:8080/api/auth/dev-login -H "Content-Type: application/json" -d '{\"role\":\"STATION_MANAGER\"}'
# {"code":0,...,"staffRole":"STATION_MANAGER","stationId":null,"bindingStatus":"UNBOUND"}
```

`stationId=null` + `bindingStatus=UNBOUND` 说明**还没建站**，先去第 4 节的第 1 步。

> PowerShell 里 `curl.exe` 传中文 JSON 会因控制台编码把中文写成 `????`
> （本次实测把顾客昵称写坏过一次，已修回）。要带中文请用文件 + `--data-binary @file`，
> 或让小程序端自己发请求。

## 6. 公网访问（不在同一 WiFi 时，可选项）

### 先判定：你家宽带有没有真公网 IPv4

本次实测证据（**高度疑似运营商大内网 CGNAT**）：

- 出口 IP 落在 `223.104.0.0/16`（中国移动）；
- `tracert` 到该出口 IP：第 1 跳是路由器 `192.168.0.1`，第 3/4 跳是 `172.21.x` / `192.168.x`
  运营商私网地址，之后超时——**说明那个"公网 IP"是运营商的 NAT 出口，不是你家的**。

自己确认（1 分钟）：登录路由器 `192.168.0.1` 看 **WAN 口 IP**，与 `curl.exe -s http://ifconfig.me/ip`
的结果比对：

| 路由器 WAN IP | 结论 | 能不能做端口映射 |
|---|---|---|
| 与出口 IP 相同 | 有真公网 IPv4 | 可以 |
| `10.x` / `100.64–127.x` / `172.16–31.x` / `192.168.x` | 运营商大内网(CGNAT) | **映射无效**，别白折腾 |

### 情况 A：有真公网 IP

1. 路由器做端口映射：`WAN 8080 → 192.168.0.243:8080`（TCP）；
2. 手机**关掉 WiFi 用 4G/5G**，浏览器开 `http://<公网IP>:8080/api/stations/public`，
   出 JSON 即通；
3. 把两端 `config/api.js` 的 `dev.baseUrl` 改成 `http://<公网IP>:8080`（**公网 IP 会变**，
   光猫重启/运营商重拨就可能换，出门前先 `ifconfig.me` 确认一次）。

### 情况 B：CGNAT（本机当前大概率是这种）

1. **打电话给运营商要公网 IP**：家宽可申请，通常免费，理由说"家里装了监控/NAS 要远程访问"。
2. **组网方案（不需要运营商配合）**：手机和笔记本都装 Tailscale / ZeroTier，
   走虚拟局域网 IP（如 `100.x.x.x`）访问笔记本的 8080。微信小程序请求走系统网络，
   系统级 VPN 生效后 `wx.request` 也会走这条路。这是个人学习最省事的"随时可用"方案。
3. **免费内网穿透**（cpolar / 花生壳 / natapp 免费版）：给一个公网地址，但**域名是服务商的、
   未备案**，小程序侧照样只能"开发版 + 打开调试"。

> 无论走 A 还是 B：**正式版/体验版都不能直连本机 HTTP 地址**。
> 微信 `request` 合法域名必须是 **HTTPS + 已 ICP 备案** 的域名，IP 与 HTTP 都不行。

## 7. 个人主体小程序的红线（为什么"正式版"跑不通本机服务器）

- **不能开通微信支付**：本项目的微信支付渠道本来就未接入（`PayMethod.availableMethods()` 里
  微信选项恒为 disabled），所以**没有影响**——学习环境用现金(货到付款)/水票即可。
- **合法域名必须 HTTPS + ICP 备案**：所以本机 IP/HTTP 只能靠「开发版 + 打开调试」跑；
  想上体验版/正式版就必须有备案域名 + HTTPS 证书 + 一台有公网 IP 的机器。
- 个人主体可选类目有限，**水/配送类目很可能过不了审核**——学习用途就别走到发布这一步。

### 当前实际在用的 appid 组合（2026-09-23 更新）

| 端 | appid | 来源 | 能否上传/发布 |
|---|---|---|---|
| `miniapp-user`（客户） | `wx12632a1cdca9fbcc` | **顾客端自有的正式 appid**（2026-09-23 启用） | ✅ 可以（它是正式小程序） |
| `miniapp-delivery`（员工端） | `wxc6211615c79da9f9` | 项目原有 appid | 看它是不是你自己注册的正式小程序 |

**两端 appid 各自独立 ⇒ 两个项目互不干扰**，不存在"上传配送端顶掉用户端"的问题；openid 也天然按端隔离
（同一个微信用户在两端拿到的 openid 不同，分别落在 `customer` / `staff`）。

#### 顾客端 appid 的三段历史（别照旧文档做）

1. **起初**：开发者工具「**小程序测试号**」`wxdf1b2dca1f4c56d0` —— **换不出 openid**：
   真机 `wx.login` 能拿到 code（拿不到的话前端根本不会去请求后端），但后端拿它调
   `jscode2session` 时微信回 **`invalid code`（errcode 40029）**，即该 code 不是以这个 appid 签发的。
   （同一现象见 `AGENTS.md` §9.4 与 skill `aquaflow-open-questions` 的「已结案」表。）
2. **2026-09-22 过渡**：临时借用员工端那对 appid 验证"换正式 appid 后登录能不能通"。
   过渡期有两条代价 —— ① 一个 appid 只能发布一个小程序，两套代码不能各自发布；② openid 不再按端隔离。
3. **2026-09-23 定型**：换成顾客端自有的正式 appid `wx12632a1cdca9fbcc`，**上面两条代价随之消失**。

> **回滚**：把 `miniapp-user/project.config.json` 的 `appid` 与 `application-local.yml` 的
> `wechat.miniapp.appid` + `secret` 换成另一对即可（改前的文件在
> `backup/application-local.yml.bak-<时间戳>`，`backup/` 是 gitignore 的）。
> ⚠️ **appid 与 secret 必须成套换**，见下面那节。

⚠️ **测试号分「小程序」和「小游戏」两种，绝对不能混用**：申请测试号页面会分别给出两个号，
把**小游戏**测试号的 appid 填进小程序项目（`compileType: "miniprogram"`），开发者工具会报错、无法正常编译。
本项目的配送端曾误用小游戏测试号，2026-09-15 已改回原 appid。**填之前确认拿到的是「小程序测试号」。**

测试号的能力边界（`miniapp-user` **2026-09-22 之前**用的是它，现已换成正式 appid）：

| 能力 | 测试号 |
|---|---|
| 本机开发、真机预览、跳过域名校验 | ✅ |
| **上传代码 / 发布 / 体验版** | ❌ 官方只承诺「开发测试 + 真机预览」（[测试号说明](https://developers.weixin.qq.com/miniprogram/dev/devtools/sandbox.html)） |
| 需认证接口（微信支付、手机号、订阅消息） | ❌ 不可用；`WeChatNotifyService` 发通知会失败，属预期 |

对应到本地配置（`application-local.yml`，gitignore，别贴进对话）：

```yaml
wechat:
  miniapp:
    appid: "wx12632a1cdca9fbcc"        # 客户端 = miniapp-user 的 appid（2026-09-23 起，自有正式 appid）
    secret: "<该 appid 的 secret>"      # 与 staff-secret **不是**同一个值（两端 appid 不同）
    staff-appid: "wxc6211615c79da9f9"  # 员工端 = miniapp-delivery 的 appid
    staff-secret: "<该 appid 的 secret>"
```

> ⚠️ **appid 与 secret 必须成套**（2026-09-16 踩到）：把 A 号的 appid 配 B 号的 secret，
> 微信只回 `40013 invalid appid`，且日志里没有指向性。**换 appid 时必须连 secret 一起换。**
> secret 只在微信公众平台 / 开发者工具「开发设置」里可见，本仓库任何**会提交的文件**
> （含本文档、`.env.example`、`application.yml`）都不写真实值。
>
> 两端**各有各的 appid**，所以"配错端"是真会发生的（换错端微信只回 `40013 invalid appid`、
> 日志无指向性）；`WeChatLoginService.code2Session` 因此**强制显式传端**（`CUSTOMER` / `STAFF`）。

⚠️ **只配 `appid` / `secret` 两行是不够的**（2026-09-15 真实踩到）：配送端登录页点「微信登录」走的是
`/api/auth/wx-login-staff`，只要 `staff-appid` / `staff-secret` 没配，后端**不会去调微信**，直接返回
`微信登录失败: 员工端微信登录未配置：请配置 wechat.miniapp.staff-appid / staff-secret`。
看到这句话别怀疑登录坏了——它就是"配置没填"的专用提示。改完 `application-local.yml` **必须重启后端**才生效
（`@Value` 只在启动时读一次）。

> 另一种更省事的验证路径：登录页的**「开发者登录」**（`devLogin('DELIVERY')`）不经过微信，
> 任何 appid/secret 都没配也能进（`code=0`），本地联调优先用它。

**后端支持两对 appid（2026-09-15 改造）**：客户端与员工端各配一对，`code2Session` 按「端」取：

| 端 | 配置键 | 环境变量 | 谁在用 |
|---|---|---|---|
| 客户端（顾客） | `wechat.miniapp.appid` / `secret` | `WX_APP_ID` / `WX_APP_SECRET` | `/api/auth/wx-login` |
| 员工端（站长+配送员） | `wechat.miniapp.staff-appid` / `staff-secret` | `WX_STAFF_APP_ID` / `WX_STAFF_APP_SECRET` | `/api/auth/wx-login-staff`、`/api/auth/bind-staff` |

- 调用点必须与小程序实际 appid 一致，**换错端微信只回 `40013 invalid appid`**，日志里没有指向性，
  现象是"某一端登录永远失败"。所以 `WeChatLoginService.code2Session(WeChatApp, code)` 强制显式传端。
- 员工端那对**缺失只 WARN 不阻塞启动**（本地 `dev-login` 兜底）；但 `prod` profile 里是必填，
  缺失直接拒启（生产两端都是真实小程序）。
- 页面/日志里出现的 `[CUSTOMER]` / `[STAFF]` 就是端名，排查登录失败时先看它。

appid 一换，**openid 命名空间就变了**：同一个微信用户在两端拿到的 openid 不同，分别落在
`customer.openid` 与 `staff.openid`，互不影响（旧号登录产生的身份记录则会对不上——
当前库里只有 dev-login 造的假 openid，无影响）。

## 8. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 手机上一切请求都"网络错误" | ①`dev.baseUrl` 还是 `127.0.0.1`；②局域网 IP 变了（改两端 `api.js`）；③防火墙没放行 8080；④手机不在同一 WiFi |
| 「不在以下 request 合法域名列表中」 | 手机没点「打开调试」；或开发者工具没勾「不校验合法域名」 |
| 接口"成功"了但数据没变 | 业务错误 HTTP 状态仍是 **200**，要看响应体 `code`（`0` 成功 / `1` 业务错 / `500` 系统错），别只看状态码 |
| 某个功能静默失效、没报错 | 多半是权限 403 被前端吞了：顾客 token 调了站长端接口（`/api/manager/*`、`/api/stations/mine`）。顾客端「当前服务水站」一律走 `utils/station.js` 的 `resolveStationId()` |
| `gradlew` 报 `fileHashes.lock` | 后端 `bootRun` 还在跑；停掉它，或统一加 `--no-daemon` |
| Gradle 报无法写缓存 | 没设 `$env:GRADLE_USER_HOME='D:\backend\project\AquaFlow\.gradlehome'` |
| 启动即退出、报 `IllegalStateException` | 缺 `JWT_SECRET` / `WX_APP_ID` / `WX_APP_SECRET`（`RequiredConfigChecker` 硬校验），检查 `application-local.yml` |
| 日志里中文变乱码 | 控制台按 GBK 渲染所致；核对数据是否真坏要比字节（`HEX(col)`），不要看控制台 |
| 端口监听是 `127.0.0.1:8080` 而不是 `0.0.0.0:8080` | 有人加了 `server.address`；删掉它，否则手机必然连不上 |
