# 25 站长信息完善引导

写给站长端维护者和运营人员。现行引导帮助站长补齐影响计费、发工资和联系的经营资料，不能替代真实营业验收。

## 1. 规则目录

引导项、完成条件、重要级别、原因和下一步入口统一由服务端规则目录下发。站长端展示同一清单，不另外推导一套上线资格。

地址和坐标是一项位置引导的两个条件：地址已填、只缺坐标时应说明缺什么，不能要求重填。工资配置只在存在相关配送员工时成为条件项，水票相关配置随经营条件出现；具体规则以 `StationOnboardingService` 当前目录为准。

## 2. 状态与提醒

待上线站缺必填项时提示完善后上线；已营业站缺资料时提示完善以便算准，不能说它尚未营业。未完成总数与 P0 数量用途不同：清单徽标用总数，底栏重点提醒用 P0。

条件项刚出现时，在现有返回页面或操作刷新点给应用内提醒；首次运行建立基线，避免升级后突然反复弹所有旧问题。提醒记忆在手机本地，换设备可能重现，这不是跨设备统一通知能力。

## 3. 能力边界

当前没有微信订阅推送，不能写“站长离线也会立即收到”。资料完整不能保证有库存、运力或已接入真实支付。新业务待办中的缺货、审批、待退款和站间返还也不是信息完善清单，由具体业务办理入口处理。

营业说明见 [13](13-营业状态与公告.md)，计费见 [17](17-配送计费与配送范围.md)，工资见 [18](18-配送员计件与工资.md)。当前没有需要再次拍板的独立引导策略。
