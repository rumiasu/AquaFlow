# 20 · 经营责任与收口边界

状态：当前能力及未完成目标清单；2026-10-09 按已验收基线 a751aec 核对。产品待决策只登记于 design/16，具体实现方法不在本清单重新评审。

## 1. 已能分别办理的业务

| 业务 | 当前收口方式 |
|---|---|
| 正常消费 | 分配、交付、实际收款或应收；交付后售后不抹实际历史 |
| 桶权益 | 独立实际收款生效，按数量分配，线上申请退出，实际交桶/退钱分别登记 |
| 水票 | 批次购买、FIFO 消耗、原资格回补、真实原款剩余退出 |
| 信用与账期 | 逐客户到付授权，账期快照，逾期提醒，确认拒付保留旧债 |
| 跨站 | 接受前完整报酬，净桶协商，实际交接，正常结清及取消/全退后返还 |
| 库存 | 需求及预留，足额交付出库，FIFO 待补，真实损失登记 |
| 员工工资 | 配送产生计件，人工调整有依据，草稿/确认/实际发放台账 |

## 2. 已决定的目标仍有实现缺口

实际经营结果必须能看出 A 的外包补差、退款及责任损失；现有销售/利润报表未完整纳入新协议，不把“订单营收算 B”解释成 A 没损失。已接受固定报酬路径已覆盖履约站 B 实收现金 C 与约定报酬 F 的补差：F>C 时 A 向 B 支付 F-C，F<C 时 B 向 A 交回 C-F，相等时无补差；方向与核销由 `InterStationSettlementServiceImpl` 和 `CashDispatchSettlementRepairIntegrationTest` 核验。该逐单补差能力不等于完整经营现金、销售或利润报表已收口。

真实微信收退款、真机验证、生产迁移仍未完成。业务待办能展示等待，不代表站方已给客户明确承诺期限；部分售后无法自动形成责任分摊。实现入口和业务能力完备是两件事。

## 3. 信用与拒付

正常企业账期及客户争议不能直接等同恶意拒付。确认拒付留债、不扣押金；相关资产站核实后冻结，支付新单前补旧债，偿还不自动恢复赊账。

本案误判纠正已有出口：原债权站附理由撤销自己判断，同站仅解除本案冻结；跨站资产站独立复核解冻，原欠款、原判断及追加审计保留，不恢复赊账、不解除其他有效案件。实现为 `ConfirmedRefusalService`，已验收基线覆盖真实 HTTP/MySQL 角色、幂等及并发边界。延期、真正免债和会计认损仍不是已完成的自动结案流程。

## 4. 欠桶与实际损耗

客户欠桶只提醒、不阻断下单，退该商品押金前须归还。它与本站库存真实损失、合作站问题桶及工人工资扣项不同。不开自有桶固定资产模块，不自动扣配送员工钱，更不能直接扣客户押金当损耗。

额外借桶按回桶异常提醒和真实差额留痕，原因选填，不新增事前借桶审批或固定欠桶上限，完整裁定见 C-02；已有批次/数量账与现金新增押金收齐护栏保留，不保证无押金实物暴露不会累积。

## 5. 身份、特权及资料

个人和固定联系人企业共用客户身份。企业申请及账期不构成独立企业资产账户。当前可用特权是免起送门槛；未实现的免费配送次数不能当成无流水开关授予。

站长联系方式、坐标、费用及工资配置按条件引导，不替站长自动宣布开业或授予经营权限。公告当前全平台可见；客户档案跨站仍隔离。

## 6. 永久退出

已定方向见 [design/16 C-06](16-范围决策与实施路线图.md#c-06站点停业或更换经营者时客户资产由谁继续承担)：退出时停止新业务，保留历史订单、客户资产、债务、待退款及未结合作款；停业前已创建的购票/押金原申请可继续付款并由原站履行，不自动取消原款或迁移资产。休息/暂停配送仍按原软提示处理。

当前可逐笔办理退出，完整关站清结和实际经营者承接尚未完成；真实主体、承接与客户同意方案及正式经营条件须明确，不自动跨站移账或伪称平台兜底。已定保留责任规则不再列为整体待拍板。

暂不自动资产移站，不能把这项范围取舍写成客户资产可以失去联系人或退款入口。保留原责任记录，清结目标定完再实现。

## 7. 首期不扩展

不做社区交易、自动平台结算、独立企业资产账户、跨商品兼容、逐桶编号、车辆分仓、正常部分交付、免押循环桶或通用促销。以后扩展须明确产品目标，本轮不为这些未来功能制造实施待办。
