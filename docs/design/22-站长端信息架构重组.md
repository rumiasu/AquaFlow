## 2. 分类与合并方案（建议）

### 2.1 判据：按「经营对象」分，不按「技术模块」分

一条水站的经营主线只有四样东西 —— **订单、钱、桶、客户**；其余是「货（商品与定价）」与「人（员工与水站自身）」。
18 张卡片逐张归类，**没有一张需要新造概念**，就是把已经成组的东西摆到一起。

### 2.2 归类结果

| 目标分组 | 收进哪些（现状卡片/页） | 合并后形态 |
|---|---|---|
| **A. 订单** | 首页 tab 的 5 个页签 + 订单管理 + 代客下单 | 1 个页 + 6 页签（见 §2.3） |
| **B. 资金** | 待确认收款 + 应收账款 + 计件工资 + 毛利报表 | 1 个页 + 4 页签 |
| **C. 桶** | 退桶审批 + 欠桶台账 + 桶异常 + 资产调整单 | 1 个页 + 4 页签 |
| **D. 客户** | 客户查询 + 客户画像 + 企业身份审核 + 客户反馈 | 1 个页 + 4 页签 |
| **E. 商品与配置** | 商品与库存 + 水票档位 + 配送计费 + 营业状态与公告 | 1 个页 + 4 页签 |
| **F. 员工与水站** | 员工管理 + 员工画像 + 绑定申请 + 水站资料/坐标 | 1 个页 + 3~4 页签 |
| **G. 独立保留** | 数据看板 | 并列第 7 张卡（它是"看"，不是"办"） |

**18 张卡 → 6 张分组卡 + 1 张看板卡。** 页数不变（页面仍然各自独立），变的是**入口层级与归类**。

### 2.3 每个分组的页签构成

**A. 订单与配送**（页签顺序 = 一天里的时间顺序）
1. 待处理（现「待分配」，含转单审批）
2. 审批（现「审批」，客户 / 站内两个子页签保留）
3. 抢单池
4. 外派（现「外派」+「他站外派」两页签合并为「外派」下的一组，因为它们是同一件事的两个方向）
5. 订单台账（现「订单管理」）
6. 代客下单（现「代客下单」—— 它是订单的**写入口**，理应和订单台账同页）

**B. 资金与工资**
1. 待确认收款（写操作：确认到账）
2. 应收账款（写操作：核销 / 设账期）
3. 计件工资（已是 3 页签：单价 / 结算单 / 自定义条目）
4. 毛利报表（含补录进货成本）

**C. 桶**
1. 退桶审批（待办区）
2. 欠桶台账（只读预警）
3. 桶异常 + 桶损耗读数（只读）
4. 资产调整单（人工补正，写操作，含新建/详情）

**D. 客户**
1. 客户查询（+ 企业身份待审角标）
2. 客户画像（从列表点入，**同时把「资产调整」「还空桶」留在画像页**，它们是客户级动作）
3. 企业身份（待审列表 + 提示阈值设置）
4. 客户反馈（只读）

**E. 商品与配置**
1. 商品与库存（选品/上架/定价/盘点/库存流水/自定义商品）
2. 水票档位（按商品的全部档位管理）
3. 配送计费（起送量/范围/运费/楼层费）
4. 营业状态与公告（软状态 + 公告 + 水站坐标）

**F. 员工与水站**
1. 员工列表（现「员工管理」）
2. 绑定申请（**从「我的」搬过来**，与员工列表同页页签）
3. 员工画像
4. 水站资料 / 坐标

### 2.4 明确**不合并**的三处（附理由）

| 项 | 理由 |
|---|---|
| 待确认收款 ≠ 应收账款 | 口径不同：前者是 `payment_record` 待确认流水（钱已到、系统未确认），后者是 `payment_status=1 且未取消`（钱还没到、有账期）。一个写"确认到账"，一个写"核销+设账期"。**合并会诱导站长点错按钮**，只同页页签相邻即可 |
| 桶异常 ≠ 运营告警 | 告警是投递流水（含补偿已执行等），异常单是业务单据；`alert_log` 还有 `SYSTEM` 类型**永远不给站长看**。同组但不同页签 |
| 退桶审批 ≠ 欠桶台账 | 前者是**待办**（有同意/驳回/退押金按钮），后者是**只读台账**。一个页面里"有的行能点、有的行不能点"会让站长困惑；分页签，但同页可互相看到 |

## 3. 风险与不做的事

- **不改后端**：本方案纯前端路由与页面归并，`controller/**` 与 `sql/**` 零改动。
- **不动口径**：所有金额、状态、文案仍由服务端下发；不新增任何前端算术或映射表。
- **`app.json` 的 tabBar 保持 3 项**（微信限制 2–5 项，且加 tab 会改变"首页"语义）；分组卡在宫格内完成，不新增 tab。
- **首页「待办」卡的 4 个 key → 页面映射**（`coordination/index.js:103-108`）要跟着改：改成指到分组页 + 页签参数。
- **删除类改动单列**：P7 两个死接口建议直接删（零引用），但要先按 §0.3 重新证一遍零引用。
