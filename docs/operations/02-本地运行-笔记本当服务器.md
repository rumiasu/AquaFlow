# 本地运行与真机联调

写给在自己的电脑上联调后端及两个小程序的人。本文说明方法，不承诺沿用某次实测的网卡、IP 或服务状态就仍可运行。

## 1. 启动前提

使用 Java 17、MySQL 和后端 Gradle Wrapper；开发库与可清空测试库分别配置。步骤、凭据注入及 schema 导入见 [CONTRIBUTING](../../CONTRIBUTING.md)。本机配置不入库，不复制给其他开发者。

新建隔离开发/测试库须使用当前完整 `AquaFlow-backend/sql/schema.sql` 基线；已有库先核已安装结构，再按 [SQL 清单](../../AquaFlow-backend/sql/README.md)补齐适用增量，只有 v71 不足以运行当前版本。真实业务库升级另按备份和目标授权规则办理，不为本地连通清空已有真实数据。`seed_dev_account.sql` 是不兼容当前基线的历史样本，不作为造数入口；隔离开发登录及现行业务API保留。

## 2. 同一网络下访问

手机与电脑接入同一可互通网络，查电脑当前 IPv4 和后端监听地址，再配置两个小程序的开发 API 基址。手机的 `127.0.0.1` 是手机本身，不能访问电脑后端。

```powershell
ipconfig
netstat -ano | Select-String ':8080'
```

本项目开发配置使用过 Windows 移动热点的 `192.168.137.1`。这是当前配置约定，不是每台电脑都固定有的地址。切换机器、网卡或热点时先验证，必要时使用仓库的 `scripts/set-dev-api-host.ps1` 更新开发地址；不要改生产占位地址来解决本机问题。

若端口未监听，先查后端启动输出；已监听但手机不通，再核对网络隔离、防火墙和实际 IP。不要因网络不通反复创建新账号或重新执行数据库迁移。

## 3. 微信开发者工具与 AppID

分别打开 `miniapp-user`、`miniapp-delivery`。两端 AppID、登录 code 和服务器 Secret 必须配套，不能用另一端的 Secret 换 code。

局域网 HTTP 调试需要开发者工具关闭合法域名校验，真机也打开调试；正式发布使用合法 HTTPS 地址。当前两端生产 API 域名仍为占位值。

两端 `config/api.js#getBaseUrl` 当前只有 `release` 走 prod；`trial`/`develop` 都走 dev，工具使用回环、手机使用核准局域网地址。体验版联通不等于正式域名验收，不在本轮改环境路由。

### 当前实际在用的 appid 组合

两端 AppID 以各自 `project.config.json` 为正本，服务器分别读客户端和员工端配置。不在本文再复制数值。旧微信测试号的历史验证不能作为正式小程序登录成功的证明。

## 4. 模拟能力

本地可显式启用现有开发登录和模拟微信支付；生产必须关闭。模拟支付成功只验证业务编排，不代表微信商户收款、退款和真机页面验收完成。独立押金的现金方式以站长确认实际收款为生效事实，创建待收款不能等价到账。

员工登录页的开发按钮固定请求 `DELIVERY`，不能用它证明站长权限；站长须另用明确授权隔离环境的合成站长会话，或真实匹配/绑定的测试身份。记录实际角色与站别，不打印令牌，不拿开发登录证明微信换码成功。

## 5. 联调记录

2026-10-09 当前恢复方式：订单已创建但支付与原单回查均未回应时显示「支付结果未知」，带原订单号与查原单入口；继续支付沿用原单，已查明付款成功则不重付。客户搜索只采用当前关键词、筛选及页面周期结果，失败常驻并可重试；地址命中注明档案或本站历史订单来源，不是当前配送地址。退桶修改商品/数量后立即清旧试算，核实当前资产站/商品/数量的试算后才可提交，最终金额仍由后端重算；原申请持续显示应退押金，水站登记退款时间不代表客户实际收到。配送提交结果未知可点「核实原订单」读取最新详情，已送达或已完成无需重提，仍在配送中可保留现场内容再提交。确认订单页始终显示当前报价/提交站，缺名显示水站编号；没有新增选站、退桶审批或收款确认步骤。

本次后端验证仅使用新建、可丢弃的合成 MySQL 容器 `aquaflow-experience-20261009`，回环端口 33318、库 `aquaflow_test_experience`，权威 `schema.sql` 建库；构建输出与 project cache 位于独立工作树。没有读取或改动原开发/业务库，无需原库恢复；任务后移除该容器及匿名卷。真实微信、手机与部署未执行，本地定向结果与 CI 全套结果分别记录。

将实际使用的版本、地址和现象写入带日期的本机记录，不把网卡 MAC、私人路径和凭据编入通用使用说明。真机验证逐一走首次权益、购票、配送、退桶与售后出口，并记录未覆盖项。

订单状态2（配送中）的客户取消是申请，须跟踪原申请结果，不能写成点击即取消。退桶先申请批准，免费原安排免再次确认；收费或水站新安排才要求当前版本确认，实际交桶与实际退钱分别核实。已做过的局部模拟器检查与剩余真机/完整联调见 [统一交付清单](../audit/2026-10-08-四路收尾统一验收.md#closeout-checklist-20261009)。
