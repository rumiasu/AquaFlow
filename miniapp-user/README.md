# 艾泉订水（AquaFlow 顾客端）

品牌标记取自已确认的艾泉 AquaFlow 首图，使用白底资源；品牌名称为页面文字。微信后台名称和图标需另行设置。

客户在这里选择水站、订水、购买水票、查看桶与押金、申请退还和查询订单。它与员工端是两个独立微信小程序，登录配置不可混用。

## 主要路径

| 客户意图 | 流程 |
|---|---|
| 首次使用循环桶 | 选站和商品 → 可先独立办理，或在订水报价后明确确认随单新增押金 → 实际收齐后形成容量并交付 |
| 提前购买水票 | 已有该站该商品权益 → 查看档位 → 独立付款 → 实际款确认后入票 |
| 再订水 | 选地址、商品、数量 → 查看费用及可用权益 → 单一方式支付 → 等待配送 |
| 结束用桶 | 查看可退数量和原押金金额 → 在线申请 → 确认站长安排 → 实际交桶 → 查询实际退款 |
| 处理异常 | 查看可读原因和原订单；消费售后与退押金分别办理 |

买权益成功不代表拿到了桶，也不代表随后买水成功。付款未知时重试原意图，不能引导客户重复付款。水票不足、权益占用、缺货等待和资料加载失败各自说明原因，空列表不等于加载成功。

## 范围和展示

权益、水票和押金按站及商品隔离；不自动跨站使用或换成另一种商品。权益数量和客户实际持桶分别显示。新增权益只对尚未领取部分免回桶，旧有桶换水仍核对回收。

水票与现金/微信不混付；水款与本次新增押金可同次付款、分项记账，也保留独立办理。水票不能付新模型的新增押金。客户有一个桶权益可以多买张水票，但同一份权益不能同时分配给两张进行中订单。退还申请占用对应数量，不把闲置权益一并封锁。

## 开发与联调

用微信开发者工具打开本目录。页面注册以 `app.json` 为准，连接方式以 `config/api.js` 为准：当前 `develop` 与 `trial` 使用配置的云容器，`release` 使用正式 HTTPS 地址（当前为占位符，发布前须配置并核验）。本地地址只在显式切换连接方式后使用。客户端 AppID 与 Secret 必须来自本端应用，Secret 不写入小程序。

环境路由与登录契约可在仓库根目录用 `node tests/js/run-all.js` 验证。开发版和体验版显示受限测试账号入口，是否可用由服务端开关与测试库限制决定；正式版和未知版本不允许测试登录。模拟支付依赖服务端能力授权，正式版拒绝模拟付款；真实微信支付尚未接入。

局域网联调见[本地运行说明](../docs/operations/02-本地运行-笔记本当服务器.md)。模拟支付仅供开发，不表示真实支付可用。当前流程测试模拟 `wx` 和网络回调，不能替代开发者工具及真机验收。

业务规格见[流程地图](../docs/design/15-业务流程地图.md)、[桶与资金模型](../docs/architecture/02-领域模型.md)、[水票规则](../docs/design/19-水票档位与批次单价.md)。
