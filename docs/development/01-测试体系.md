# 测试与验证边界

写给新增或复核验证的工程师。核对日期：2026-10-01；件数读取本次运行报告，不在规格中维护增长指标。

## 1. 后端验证

集成测试启动完整 Spring 容器、随机端口、真实 HTTP 和 MySQL。AbstractIntegrationTest 每例清空当前测试库，须是专门可重建的 `aquaflow_test` 或允许的会话后缀；名字不代表数据可删。准备及直接 Gradle 均要求 `AQUAFLOW_ALLOW_DB_RESET` 精确库名与 `AQUAFLOW_ALLOW_TEST_DB_TARGET=IPv4:端口/库名`，host/port/name/JDBC URL 和存在时的 DB_URL 必须一致，禁止隐藏配置改变目标；配置例见 CONTRIBUTING §4。

测试资源 `META-INF/spring.factories` 注册的 initializer 在数据源建立前校验有效配置，覆盖不继承基类的根上下文启动。基类在同一实际 Connection 上核 URL、catalog、SELECT DATABASE，再枚举表并清表；不符合时停止。允许的 JDBC 参数及 IPv4 子集由脚本/Java 目标保护器定义；完整 verify 当前仅本机 `127.0.0.1:3306`，独立准备/直接测试可用经确认的其它 IPv4/端口。纯单元与假连接测试能验证拒绝和调用顺序，不替代真实 MySQL metadata、锁/回滚或 CI 容器验证。

测试结构由独立准备脚本安装，`application-test` 和 initializer 禁用自动 SQL 初始化。启动 SQL/迁移配置在环境变量、JVM 属性与有效 PropertySource 三层预检；`spring.sql.init.mode=never` 是该家族唯一允许值，外部脚本位置或初始化凭据即使伴随 never 也拒绝。检查先于固定 never 和数据源建立，防止启动脚本在每例护栏之前改变当前库。无护栏假连接对照可以故意记录 USE，用于证明夹具有效；这类缺陷成立断言不能算作保护通过。

AbstractScenarioTest 复用水站、客户、库存和动作夹具。夹具必须同时建批次/流水，不往派生资产账户塞数制造“余额存在但来源不存在”的测试世界。FIFO、现金未收窗口、原路退款和站别边界都应断言业务后果。

## 2. 新旧模型

test profile 默认旧规则，IndependentBarrelBusinessIntegrationTest 显式开启新权益及模拟支付，维护任务关闭避免背景作业干扰。历史路径通过不代表新路径通过，反之亦然。

本轮业务用例验证权益未领与实物分开、并发不复用、资产退出批准/交桶/退款不同、信用跨站边界、冻结报价、实际净桶、库存损失待补和真实余票退出；没有真实银行或微信退款结果。

## 3. 小程序流程

tests/js/run-all.js 执行实际页面函数并模拟 API/微信回调，检查请求次数、失败重试意图、状态、文案与跳转。套件完成标记和退出码共同判断成功；静默退出不是通过。

流程模拟不能证明 WXML 在真机正确渲染，开发者工具/真机仍需单独验收。

## 4. 静态与契约门禁

语法、事件绑定、页面可达性、样式选择器、场景矩阵、API 参考、SQL 清单、待拍板指针、入库依赖、秘密扫描和发布包检查各有独立入口。完整配置由 CI 与 verify 脚本定义，不手写固定门禁总数。

## 5. 重跑与并行

用 --rerun-tasks 或必要的 cleanTest 保证真实执行，不把 UP-TO-DATE 报成这次已验证。并行必须独立数据库、build 和项目缓存，测试 TRUNCATE 或并发编译互删输出都会造假绿/假红。

## 6. 报告

读取目标构建目录 test-results/test/TEST-*.xml，分别报告 tests、failures、errors、skipped、实际执行范围和未跑部分。后续补改的选定回归不累加成更多唯一场景。2026-10-01 的业务执行证据见 design/16 §11.6。

## 7. 产品决策不能由测试代替

用例可以证明“按既定规则发生什么”，不能替经营方决定谁承担客户资产、服务期限、额外借桶或争议。未决目标仍留在 design/16；不要把实现现在这样写成产品已经选择。
