# 部署与运行责任

写给部署及运维人员。核对日期：2026-10-01。开发运行见 CONTRIBUTING，迁移适用顺序见 sql/README；生产操作须确认具体目标和备份。

## 1. 当前部署边界

单实例后端和 MySQL 8.4，正式 HTTPS 入口及两个微信小程序。内存限流及部分作业未按多实例设计；增加实例之前需解决集中计数和作业重复执行。

## 2. 配置

变量清单为 AquaFlow-backend/.env.example，生产 profile 为 application-prod.yml。数据源、JWT、两端微信及 CORS 配置须解析为真实可用值；生产关闭 DEV_LOGIN_ENABLED、MOCK_WECHAT_PAY。配置样例是占位符，不是可复用真实密钥。

JWT 长度及危险开关由 RequiredConfigChecker 检查，数据源缺值在 prod 显式拒启。COS/告警外部渠道未配置可降级，但影响上传或消息实际发送。BarrelBusinessPolicy 在新模型开启时检查 v71 表组。

## 3. 发布前条件

确认产品主体和相关未决业务目标，真实渠道不可用时不能开放假付款。正式 API 域名、小程序应用配置、必要上传域名及真机可用性核对。发布包不含 application-local.yml，启动姿态及探针按发布脚本验证。

通过测试不证明真实资金可收退或真机页面可用。本轮没有完成生产迁移和正式发布；具体记录见 design/16 §11.6。

## 4. 数据库升级

新库才导入 schema；真实存量库先备份、确认已安装版本和待结业务，再按清单只执行适用增量。v71 先兼容代码和完整结构，切换核对后启用；新业务发生后不能回退旧代码或关闭模型继续旧规则营业。

## 5. 备份与恢复

备份结构、业务和必要渠道凭据配置，存储在受控位置，不提交 backup。恢复演练使用 scripts/backup-restore-drill.js 及专门目标库，真实恢复前验证目标，不能把演练件指向生产。库名像 test 也不能证明里面没有必须保留的数据。

## 6. 日常业务等待

站长跟进未收款、缺货、退还审批、收到桶后退款和站间交接。新未付桶装订单仅在有权益分配且没有活跃支付请求时可按超时取消；付款未知和已付等货不自动丢弃。系统不通过提醒替站方许诺具体送达时间。

## 7. 对账与告警

系统作业按配置生成结果；站长只读本站即时视角。对账不平先核事实及来源，不通过直接写派生账户“消掉差异”。系统故障向系统管理员，经营问题向对应站长，渠道失败仍保留落库告警，通知不能连累主业务。

## 8. 故障处理

健康探针、数据库探针和授权拒绝分别验证，不把 HTTP 200 当业务成功。付款/退款结果未知核实原交易；预留不足核当前站和原凭据；客户投诉核原款、实际交接与责任，不恢复终态订单当补救。

## 9. 暂停与永久退出

暂休/预约状态是软经营提示，不能当停用账号或永远清结。需要停业时关闭适用业务入口并保留客户资产办理路径。永久退出和经营者变更的资产清结责任仍待 C-06，不把“暂不移站”写成“可以删除资产”。

## 10. 仓库重新发布

见 [03-仓库重新发布](03-仓库重新发布.md)。本地新 Git 快照与数据库升级是两个操作，上传代码不授权改生产数据，也不自动启用未接通资金渠道。
