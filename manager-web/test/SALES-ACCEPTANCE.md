# 电脑站长端促销与配送承诺：隔离环境复验

这是浏览器到真实 HTTP 服务再到 MySQL 的验证，不使用模拟 API 返回；数据库、身份、手机号和地址均是人工合成夹具，不涉及真实业务数据。只验收本次三个业务面，不宣称电脑版全量上线。

## 前置与恢复

1. 使用开发分支 `2af281d2e58d83903fad5ef7549c5f01bb6cb22f` 对应的后端构建和本批冻结 `manager-web/public`。复制公共网页到独立 QA 目录，保存每个文件 SHA-256；复验后再次与冻结源文件比较。
2. 启动全新 MySQL 8.4 专用数据目录，只绑定 `127.0.0.1` 随机空闲端口。通过 `SELECT @@datadir` 核实确为该目录。只创建 `aquaflow_test_manager_liveqa`，保存其空库可恢复 dump。不要使用正在工作的共享库或生产库。
3. 导入当前 `schema.sql`。其已包含 v93–v98，不能重复执行非幂等迁移。创建人工合成 A/B 水站、各自站长、A 站客户和地址；两站均正常营业，00:00–23:59、正常时段承诺 60 分钟。站点配送费配置显式存在且为零。
4. 创建同一瓶装商品：平台参考价 23，A 站常规价 20，B 站常规价 22；每站库存 30，无押金和水票。A 客户有本站关系且可现金支付。仅为此临时库生成随机密码、BCrypt 存储和随机 JWT 密钥，不复用任何真实凭据。
5. 后端只绑定回环随机端口；禁用测试登录、开发登录、模拟支付；无真实微信/COS 凭据。通过另一随机回环同源静态代理挂载网页和 `/api/`。使用全新无头 Chromium profile，不继承用户浏览器会话。

## 浏览器步骤与断言

1. 使用 A 站合成站长账号在真实登录页登录，确认页面水站为 A。
2. 进入商品库存→站内促销，将促销开启为 15.25，接受确认。回读 A 站目录有效价为 15.25；B 站仍为 22。
3. 将促销价填 20 并提交，页面明确拒绝“促销必须低于日常售价”，没有发出商品更新请求。
4. 填 13，在浏览器原生确认框取消，数据库/目录保留 15.25，没有更新请求。
5. 进入代客下单，选择合成客户、地址和两件瓶装商品。实际页面商品价格为 15.25，真实服务端试算水费为 30.50。
6. 确认创建现金订单，点击“查看订单与付款状态”。读取真实 `/api/delivery/orders/{id}` 中的 `deliveryDeadlineText`；页面显示完全相同的已保存最迟送达文字。下单前不把当前营业时段推算成已承诺日期。
7. 回到商品库存，将促销改为 14，连续触发两次表单提交。只有一个商品 PUT 请求；有效价最终为 14。
8. 回读刚创建的订单，水费仍为 30.50；已保存配送承诺不变。
9. 结束促销，A 站回读有效价 20、促销关闭、促销金额空值。完整开启/修改/结束生命周期共三个商品 PUT 请求。
10. 退出并以 B 站合成站长登录，商品列表仍显示 22，不串用 A 站促销状态。

## 数据库核对及结果

实际两轮都通过。最终一轮 17 条真实浏览器/HTTP 断言通过：订单明细价格 15.25、小计及订单水费 30.50，订单 `delivery_deadline` 非空；促销结束后库存经营价 A=20、B=22，均无促销金额。网页冻结版 28 个文件与执行复制件 SHA 一致。此统计不与其他模拟测试相加。

结束先关闭专用网页代理与后端，重新核对 MySQL 的 `@@datadir`，导入空库备份，重新 dump 并比较 SHA-256 完全一致，再关闭该临时 MySQL 和专用 Chromium。两轮均恢复成功，未触碰原业务库、线上服务、原源码或部署。

未在本轮执行：真机微信、真实支付或退款、生产部署、其他网页模块的完整端到端验收；使用的是实际 Chromium 无头模式，不把截图检查声称为真人试用验收。
