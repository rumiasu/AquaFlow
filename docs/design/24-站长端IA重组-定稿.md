# 24 站长端当前入口与权限

写给使用或维护员工小程序的人。本文描述当前入口，旧信息架构的取舍保留在 22、23、29、30，不再将当时宫格当作现行界面。

## 1. 两个角色共用一端

站长负责接单分配、经营配置、收款与售后；配送员处理派给自己的履约任务。客户端另有小程序。角色分流不改变后端判权：未分配单只有站长可见，配送员不能通过编造订单 ID 接走。

## 2. 当前导航

### 2.1 管理入口

管理页采用分组行列表，每行说明要办理的事，并有可达的目标页。

| 分组 | 当前事项 |
|---|---|
| 订单与客户 | 全部订单、异常、客户、反馈、资产调整台账 |
| 收款与工资 | 应收账款、站间结算、业务待办与退出、待确认收款、工资、利润报表 |
| 桶与库存 | 退桶审批、欠桶台账、商品与库存 |
| 水站设置 | 配送计费、营业说明与公告、员工、水站资料 |
| 经营数据 | 经营看板 |

订单管理直达订单台账，首页协调队列用于待分配等即时工作，两者不是同一个入口。代客下单服务已经存在，但独立页面没有当前可达入口；不能把 API 可用写成站长已能从页面走完代客流程。

### 2.2 上下文入口

新建资产调整从客户详情进入，固定客户；水票档位从商品的本站配置进入。管理页台账入口与针对某客户的新建入口不能互相替代。

### 2.3 待办

已有重点待办、底栏红点和用户可选提醒设置；它们是应用内信息，不是离线订阅推送。v71 业务待办页处理缺货、等待超时、拒付核实、站间返还与实物/桶款交接、剩余票退出。存在该列表不等于新增事项已经全部进入旧红点汇总。

### 2.4 客户资产

资产页面区分有效权益、实物和占用；只办理独立押金但没下水单的客户可按本站绑定查询资产。普通客户画像列表仍按本站订单取人，详见 [21](21-站长端客户搜索口径.md)，不能将资产查询资格与画像列表资格混为一件事。

### 2.5 经营数据

“订单已付款”不是本站实收，毛利不是完整站间补差后的净利润。界面说明和服务端口径一起展示，见 [32](32-看板已收款口径-决策件.md)。

### 2.6 导航与底栏约束

tab 页使用 `switchTab`，普通详情页使用正常页面导航。自绘底栏的页面注册与组件配置同时维护；页面根容器保留 `custom-tabbar-page`，显示时调用 `syncTabBar`，重点红点由统一提醒工具更新。

每条可操作行必须同时有目标和处理函数。只检查页面注册或处理函数存在不足以证明可达性，还需核对实际入口、跳转和返回路径。本轮没有用静态核对冒充微信真机点击验收。

## 3. 当前业务动作

订单详情办理消费组成退款和外派报价；待确认收款区分消费、水票、独立押金和收桶费，不能一律叫水票款。退桶页按批准安排、客户确认、实际交桶、实际退款分别操作。

异常与调整是站长留痕处置，不能作为无限额正常退款，也不能替代尚未决定的拒付申诉或跨站售后裁决。未决责任只维护在 [16 §12](16-范围决策与实施路线图.md#12-核心业务决策复核2026-10-01)。

## 5.1 异常和告警入口

桶异常与运营告警共用现有处理入口。系统告警由运维负责，不向站长泄露其他站或系统内部数据。配送员看到自己任务的订单快照，不得到归属站客户画像。

## 7. 验证边界

本轮 v71 已有页面处理函数回归和静态核对，未完成开发者工具渲染或真机全过程验收。页面路径以 `app.json` 和实际入口为准，本文不维护易漂移的页面件数。
