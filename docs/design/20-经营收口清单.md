# 20 · 经营责任与收口边界

状态：当前能力及未完成目标清单；2026-10-01 核对。产品待决策只登记于 design/16，具体实现方法不在本清单重新评审。

## 1. 已能分别办理的业务

| 业务 | 当前收口方式 |
|---|---|
| 正常消费 | 分配、交付、实际收款或应收；交付后售后不抹实际历史 |
| 桶权益 | 独立实际收款生效，按数量分配，线上申请退出，实际交桶/退钱分别登记 |
| 水票 | 批次购买、FIFO 消耗、原资格回补、真实原款剩余退出 |
| 信用与账期 | 逐客户到付授权，账期快照，逾期提醒，确认拒付保留旧债 |
| 跨站 | 接受前完整报酬，净桶协商，实际交接，正常结清及取消/全退后返还 |
| 库存 | 需求及预留，足额交付出库，FIFO 待补，真实损失登记 |
| 员工工资 | 配送产生计件，人工调整有依据，草稿/确认/实际发放台账 |

## 2. 已决定的目标仍有实现缺口

实际经营结果必须能看出 A 的外包补差、退款及责任损失；现有销售/利润报表未完整纳入新协议，不把“订单营收算 B”解释成 A 没损失。正常台账还不能覆盖所有 B 直接收款但约定报酬高于实收的补差核销。

真实微信收退款、真机验证、生产迁移仍未完成。业务待办能展示等待，不代表站方已给客户明确承诺期限；部分售后无法自动形成责任分摊。实现入口和业务能力完备是两件事。

## 3. 信用与拒付

正常企业账期及客户争议不能直接等同恶意拒付。确认拒付留债、不扣押金；相关资产站核实后冻结，支付新单前补旧债，偿还不自动恢复赊账。

## 4. 欠桶与实际损耗

客户欠桶只提醒、不阻断下单，退该商品押金前须归还。它与本站库存真实损失、合作站问题桶及工人工资扣项不同。不开自有桶固定资产模块，不自动扣配送员工钱，更不能直接扣客户押金当损耗。

额外借桶的交付义务和授权边界见 C-02；已有批次/数量账保证不能重复分配，不保证无押金实物暴露不会累积。

## 5. 身份、特权及资料

个人和固定联系人企业共用客户身份。企业申请及账期不构成独立企业资产账户。当前可用特权是免起送门槛；未实现的免费配送次数不能当成无流水开关授予。

站长联系方式、坐标、费用及工资配置按条件引导，不替站长自动宣布开业或授予经营权限。公告当前全平台可见；客户档案跨站仍隔离。

## 7. 首期不扩展

不做社区交易、自动平台结算、独立企业资产账户、跨商品兼容、逐桶编号、车辆分仓、正常部分交付、免押循环桶或通用促销。以后扩展须明确产品目标，本轮不为这些未来功能制造实施待办。
