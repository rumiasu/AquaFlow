# 拒付复核与恢复：安全实施建议

写给接手拒付异常实现的工程师。已定业务口径以 [design/16 C-03](16-范围决策与实施路线图.md#c-03拒付错判免债与解冻的结案权) 为正本；本文说明实现、权限与验证边界，不另建产品决策清单。

状态：2026-10-08 已按用户确认规则补齐误判撤销、资产站解除冻结及追加审计。程序和专项测试已编写；JS 和静态检查已通过，后端编译、真实 MySQL 回归及 v77 迁移尚待统一验证。未连接业务库、未执行收退款或会计反向操作。

## 1. 三种处理分别保留事实

| 动作 | 权限及效果 | 保留的边界 |
| --- | --- | --- |
| 撤销拒付误判 | 本案原债权站站长提交必填理由，撤销本案拒付判断；同站时一并解除本案资产冻结 | 原欠款、原判断、已收押金和其他案件完整保留；不记实收、不免债、不恢复线下付款资格 |
| 解除资产冻结 | 本案资产归属站站长提交必填理由，解除本案已经确认的冻结 | 跨站债权站不能代为解除；不撤销拒付判断，不解除其他案件，不改变款项或权益 |
| 实际偿还欠款 | 继续既有真实收款凭据与订单支付 CAS | 收到钱后本案基于待收款状态的限制自然不再生效；原判断及确认事实仍保留，线下付款资格不会自动重开 |

真正免债、认损、部分金额处理仍不是本次纠错命令。不得创建 PAID 流水冒充实收，也不得从押金扣账；冻结金额、商品范围、期限及相关未决项仍沿 C-03 处理。

## 2. 原事实、状态与审计分开

`customer_refusal_case` 保留原判断、作者、理由、确认冻结人及时间。新增 `customer_refusal_resolution` 只保存本案 `judgment_revoked`、`asset_freeze_released` 与版本；缺状态行按原判断未撤销、冻结未解除解释，迁移不自动改历史案件。`customer_refusal_action` 逐行追加动作、必填理由、会话操作者、站别、时间、前后版本和请求摘要，不覆盖原判断。

`ConfirmedRefusalService.resolve` 使用 READ_COMMITTED 事务，以既有拒付行作为锁锚。先按会话核对原债权站或资产站，再串行化本案动作；同操作者、同站、同对象的请求键重放先返回原回执，同键改动作、理由或期望版本拒绝。新动作须匹配期望版本并命中状态 CAS，审计写入失败整笔回滚。未知提交结果由小程序保存原键、原理由和原版本重试，不能改用新键重复办理。

同站撤销原判断时，在同一次版本 CAS 内设置解除标记；跨站仅撤销原判断，资产站已有的确认继续保留并独立生效，直到资产站复核解除或原欠款实际收口。支付前拒付闸门只读未撤销案件；资产冻结只读已确认且未解除案件，两者不能共用撤销标记。多个有效案件仍按并集限制，不因处理一个案件清空其余案件。

既有 `confirmFreeze` 改为同一条 `UPDATE ... JOIN orders` 校验原单仍待收款、未取消、资产站身份、尚未确认且没有撤销/解除；受影响行数必须为1。已收款、已取消或已撤销后迟到的确认不能新增确认人和时间。

## 3. 入口与最小授权

全部入口仍位于站长专属 `/api/manager/refusal-cases`：

| 方法/路径 | 请求或响应 | 规则 |
| --- | --- | --- |
| `GET /` | 原事实、欠款状态、版本、服务端文案及动作能力 | 仅资产站或原债权站的案件，不提供客户画像 |
| `PUT /{orderId}/confirm-freeze` | 既有确认冻结命令 | 仅资产站；保持原门槛并补当前状态 CAS |
| `POST /{orderId}/revoke` | `expectedVersion`、`idempotencyKey`、`reason` | 仅原债权站站长，撤销误判 |
| `POST /{orderId}/release-freeze` | 同上 | 仅资产站站长，解除本案冻结 |
| `GET /{orderId}/history` | 追加动作、理由、操作者、时间与版本 | 仅双方当事站站长 |

员工小程序「站务 → 业务待办」展示原判断、当前限制及处理记录，按服务端能力展示撤销/解除入口。必填理由、同键重试、切身份和离开页面后迟到响应隔离均在页面处理器中执行。请求不能指定客户、站别、金额、收款状态或赊账配置。

## 4. 守恒与上线边界

纠错/解除前后必须逐表保持：订单金额和支付状态、原实收/退款流水、应收口径、押金余额、桶 E/H/R、票账户与批次、库存和预留、线下付款配置、原拒付记录全部相同。仅本案的新状态与追加审计可变化。确认冻结沿既有事实模型，只允许本案原确认标记、人和时间变化；不得覆盖已有确认或其他案件。

结构来自 `sql/migration_v77_exception_closeout.sql`，包含拒付状态/审计与退款争议状态/审计四张增量表。`ExceptionCloseoutSchemaGuard` 只读检查字段、非空、默认值、二进制幂等键、完整唯一索引、主键、自增审计ID及 InnoDB；结构缺失拒启，不自动迁移。部署由统一验证者核准目标及备份后安装结构；发生新业务后，不能直接回到忽略撤销/解除状态的旧代码，也不能删新表。

专项 `ConfirmedRefusalFreezeIntegrationTest` 与 `ExceptionCloseoutIntegrationTest` 已覆盖授权、同站原子撤销、跨站分别复核、多案件叠加、同键重放及改内容拒绝、并发、迟到确认和逐表守恒，但尚未执行。`ExceptionCloseoutSchemaGuardTest` 已编写，亦未执行。新异常页面 JS 专项11项（含真实WXML投影）、既有反馈17项及业务待办53项通过；Java只做语法解析，JS语法、WXML事件绑定、文本和 diff 检查通过。以上不代表后端编译、真实数据库事务、原生GUI、真机或真实支付验收。
