## 第二批：文件归属与告警报文

- 文件删除必须有明确上传人且属于当前站长；平台级可见性不构成删除权。保留平台历史行明确上传人本人的原删除路径，他站文件仍拒绝。`FileManageControllerOwnershipTest` 断言拒绝时 COS 与数据库删除均零调用；`FileUploadIntegrationTest` 覆盖双 NULL、未绑定站长、他站、配送员及客户等 HTTP 分支。
- WECOM、DINGTALK 和 RAW 使用 JSON 序列化，控制字符可严格往返；SERVERCHAN 保持 URL 编码表单。`AlertWebhookPayloadTest` 逐通道验证，`AlertWebhookIntegrationTest` 的本地接收桩先解析 JSON，另用非法报文和 HTTP 拒绝作负对照，拒绝不得记成 PUSHED。
- 该批原实现的七项反例中四项失败；修复后报文、文件及告警路由和分层共 28 项通过。不涉及迁移、真实对象删除或外部通知；平台双 NULL 的真实记录是否存在仍未知。

## 保存反馈：资料与计件单价

- 两端本人资料的成功回执先更新已保存基线，再单独同步本机缓存与草稿。缓存异常不能改称写入失败；草稿清理不确定有独立提示。回执绑定原身份、原请求，换账号、卸载或后来输入不能被旧回执清除或跳走。
- 资料请求明确业务拒绝时保留“未保存”；网络结果未知只读 `/api/auth/me`，身份及字段匹配才能确认。核对失败保留输入并提示“结果未确认”；核对按钮不会再次 POST。沿用既有空手机号表示保留的服务端契约，不伪造清空成功。
- 单价 PUT 成功后，列表 GET 或应发预览失败单独提示“单价已保存，尚未刷新”，保留旧列表并标明旧数据。刷新按钮只读；清草稿只针对原身份与原商品，离页/换站的迟到响应不能污染新页面或解除新请求锁。
- `save-result-feedback.test.js` 执行真实页面处理函数，资料修复前18项中12项失败，单价修复前新增分支有6项失败；修复后26项通过。与既有个人草稿、员工会话、工资预览、工资请求、普通表单和文案共7套102项通过。此记录不等于最终全量或真机验收；该批无后端变更或迁移。
