# AquaFlow 站长桌面端 · 真实接口开发版

本目录是对接当前开发分支的静态站长客户端，不是线上站点。功能和未验证项见[覆盖清单](COVERAGE.md)，促销回归步骤见[测试说明](test/SALES-REGRESSION.md)。

这是使用 AquaFlow 真实 API 的桌面前端开发版。业务内容由后端返回，写操作须由站长确认。已在本机用合成数据验证，尚未部署或使用真实账号联调。

## 已实现
- 已有站长账号密码登录 `/api/auth/login`，再用 `/api/auth/me` 校验当前身份、绑定水站。
- 内存保存会话，刷新页面需重登。令牌过期单飞刷新，账号切换丢弃旧响应，退出清空内存。下单、纯还桶、异常和认领的待核对请求保存在当前标签页的会话存储中，按员工及水站隔离。令牌和密码只在内存中使用。
- 经营看板：今天、近7天、近30天，显示服务端金额和桶数；历史桶数未知不显示零。
- 订单：状态、日期筛选，每页30条，详情使用服务端状态文案和固定订单金额。
- 客户：服务端姓名/电话/地址搜索，不在客户端重做归属判断。
- 只请求当前源的白名单接口；不传自选 stationId，不修改后端授权。

- 本站未分配订单可分配在职配送员。配送协作支持指定外派及接收，按服务端提示确认押金和桶权益风险，接收报价沿用原报价令牌。
- 待确认收款：游标分页，显示支付记录编号/用途/金额后确认到账，调用支付确认而非订单改状态。
- 异常与客户反馈可查处理历史，按当前后端能力提交核实归还、已解决、误报/无需处理、回复及结案。桶账支持实收空桶登记和原请求回查。
- 新接代客下单、本站配送完成、欠桶、应收、站间台账、工资试算与发放登记、水票档位及配送权益、员工绑定审批、历史资产认领、利润报表、商品库存、营业和公告。逐项范围见覆盖清单。
- 写操作提交前复验身份；同一动作单飞，网络结果不明不自动重放，提示刷新核对。

## 部署方式（尚未执行）
把 `public/` 作为站长端静态目录，由现有 HTTPS 网关提供；同一源的 `/api/` 转发到已有 AquaFlow 后端。可以使用独立的管理子域名，但静态页与 API 必须同源，避免开放通配 CORS。不要把此目录直接部署到现有演示 Site 后宣称已经接入。

网关转发保留浏览器访问的 `Host`，同时转发原始协议及来源。HTTPS 在网关终止且 Spring 上游使用 HTTP 时，将浏览器实际访问的 HTTPS 站长源加入 `CORS_ALLOWED_ORIGINS` 的明确允许列表，并保留已授权的其他源。用浏览器联调 POST；本地测试已复现错误改写 `Host` 导致 Spring 返回 403。网关示例的主机名和端口替换成实际测试环境。

```caddyfile
manager.example.invalid {
    header {
        Cache-Control "no-store"
        X-Content-Type-Options "nosniff"
        Content-Security-Policy "frame-ancestors 'none'"
        Referrer-Policy "no-referrer"
    }
    handle /api/* {
        reverse_proxy 127.0.0.1:8080
    }
    handle {
        root * /srv/aquaflow/manager-web/public
        file_server
    }
}
```

需要现有站长账号已设置密码，且在职、绑定水站。微信登录不自动意味着存在可用密码。不要在源代码或部署包中放密码/令牌。

运维须给管理页配置 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff` 和 `frame-ancestors 'none'` CSP 响应头。HTML 已限定 self 脚本/网络。浏览器内存会话有 XSS 风险，本实现转义所有服务端展示字段且无外部脚本。

当前后端的账号密码、已绑定员工微信等正式员工登录新增独立会话。部署前在目标库备份并核实后执行 `AquaFlow-backend/sql/migration_v93_staff_sessions.sql`，然后切换全部认证实例。旧后端登录会撤销新会话，切换期间应统一认证流量。小程序继续使用原 API 与响应格式。历史刷新令牌按原格式继续续期，重新登录取得独立会话。旧格式访问令牌仍按原签名、有效期和实时员工状态校验。迁移在隔离库的旧表上已验证，存量凭据保留且新会话索引为可空唯一键。

## 验证

本次 24 项 Node 测试通过。9 个真实 Chromium DOM 场景（51 处断言）覆盖重复提交、切站、取消及不确定回执；使用真实后端和专用 MySQL 的 [17 项验收与复现步骤](test/SALES-ACCEPTANCE.md) 独立验证，不和模拟检查混计。
执行 `npm test` 运行客户端契约测试，执行 `npm run check` 检查浏览器脚本。后端定向回归应使用独立 MySQL 测试库，包含双端刷新、单端退出、改密撤销、收款分页、先付款后派单、桶账和异常办理。上线前需用测试账号验证浏览器到同源网关的全链路，再由实际站长确认日常操作。

2026-11-13 的历史验收记录为 21 项网页测试通过。隔离 MySQL 的 164 项后端定向用例全通过，Gradle 在生成报告后因 Windows Java 注册表权限退出 1，结果以测试 XML 为准。Chromium 通过本机同源代理跑通合成客户的现金订单从试算、下单到站长接单、送达和实收，数据库核实只写入一笔 15 元已付流水、一次出库。Chromium 也用合成响应核对了异常处理结果及页面跳转。真实微信、真实 COS 和完整跨站、退款、工资等网页办理流程仍待联调。

## 站内促销及配送承诺

代客下单展示服务端成交价，不用参考价推算；旧接口不返回成交价时提示试算。订单详情只显示服务端已经生成的配送承诺。商品库存页支持开启、修改和结束本站促销；保存前核对账号、站点与价格，保存后回读，回执不明不重复发送。接口暂不支持版本条件写入，多端同时编辑不能保证检测到每一处竞争。

共享电脑用毕请退出并关闭标签页。收款、退款、工资等完整经营流程仍需逐项验收，不应仅因开发分支有源码就上线。
