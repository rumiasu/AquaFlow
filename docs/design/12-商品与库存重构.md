## 1. 产品口径（本次改造的全部决定）

| # | 决定 | 说明 |
|---|---|---|
| 1 | **平台方维护"通用商品库"，站长选品** | 站长打开商品页第一眼是**选项列表**（"选什么水"），而不是空白表单 |
| 2 | **通用库商品的名称/规格/图片/描述对站长锁死** | 站长只能改**本站**的：上架 / 库存 / 本站售价 / 本站押金 / 水票开关与价格 / 优先展示 |
| 3 | **只有"自定义商品"能改名称/规格/图片/描述** | 即"默认锁死，自定义才可编辑" |
| 4 | **自定义商品不入通用库** | 仅本站可见、可用；站长可**上报**给开发者，由开发者人工补进通用库 |
| 5 | **历史订单与历史桶权益继续用快照** | 改价只影响**之后**新产生的订单与批次；退桶金额按批次买入单价 |
| 6 | **站级价不做强制护栏，超出给提醒** | 相对通用库参考价超出阈值 → 返回 `warnings`，**不阻断**保存 |
| 7 | **不做平台级功能，只做本站级** | 没有"平台停售影响所有站"这类动作；**站长之间严格隔离，无权干预别站** |
| 8 | **上架但 0 库存仍可下单（保持现状）** | 客户确认后下单，语义是"暂时没货，需要等待配送"（`OrderServiceImpl:349-352`） |
| 9 | **不考虑"最小改动"，按最优解做** | 目标是长期可运维，允许必要的接口替换与前端页面重做 |
| 10 | **文档必须与设计对齐** | 见 §12 文档同步清单 |

> 推论：`product.status` 只作为**开发者维护目录**时的数据位（撤掉某个选品），站长的任何界面都不出现"平台停售"概念。

## 2. 领域模型

```
通用商品库 product（owner_station_id IS NULL，开发者/运维维护，站长只读）
        │  ← 站长"选用"（选品）
        ▼
本站设置 inventory（station_id + product_id 唯一，一行 = 本站对某商品的全部可售信息）
   ├─ enabled          本站是否上架
   ├─ quantity         本站库存（唯一写入口：InventoryService，必须落 inventory_record 流水）
   ├─ sale_price       本站售价（NULL → 回落 product.price 参考价）
   ├─ deposit_price    本站押金（NULL → 回落 product.deposit 参考押金）
   ├─ ticket_enabled   本站是否开水票
   ├─ ticket_price     本站水票价（>0 生效，NULL/0 → 回落 product.price）
   └─ priority_display 优先展示（上限 3）

> **「上限 3」的正本**：`CatalogServiceImpl.MAX_PRIORITY_DISPLAY = 3`（校验在设置保存分支 `count >= MAX_PRIORITY_DISPLAY` 时抛业务异常）。**旧文档写的 `ManagerProductController.togglePriority` —— 该类已不存在**（商品写入口早已收归 `/api/manager/catalog*`），引用前先认类名。

自定义商品 product（owner_station_id = 本站，完整可编辑，仅本站可见）
   └─ 同时自动建一行本站 inventory（与通用库商品走**完全相同**的可售模型）
   └─ 站长可上报 → product_submission（开发者人工补进通用库）
```

**为什么不拆表**：`product.id` 是 15 张业务表（`order_item`/`orders`/`barrel_record`/`customer_barrel_{asset,lot,over,in_transit}`/`ticket_account`/`ticket_record`/`inventory_record`/`station_adjustment`/`order_barrel_exception`/`order_template_item`）与 7 个含 `product_id` 唯一键的锚点。物理拆出第二张商品表会让这些引用的 id 语义分叉（历史行对不上新表），运维与对账都会变痛苦。**"不入通用库"是查询口径，不是物理分表。**

**一个商品对一站最多一行**：`uk_inventory_station_product(station_id, product_id)` 保持不动。
（注意：`inventory.station_id` 可空，唯一键含它 → NULL 行可重复；因此**不要**用 `inventory` 承载"平台默认库存"，平台默认值一直在 `product` 上。）

## 3. 数据模型（v31）

> 全部为**新增可空列/新增表**，不改既有列类型与含义，不动存量数据；回滚脚本写在迁移文件头。

| 对象 | 变更 | 语义 |
|---|---|---|
| `product.owner_station_id` | 新增 `bigint NULL` | NULL = 通用库；非 NULL = 该站自定义。配 `idx_product_owner_station(owner_station_id, status)` |
| `product.preset_uk` | 新增 STORED 生成列 + `uk_product_preset` | `IF(owner_station_id IS NULL, CONCAT(name,'|',IFNULL(spec,'')), NULL)` → 防通用库重复录入 |
| `product.station_uk` | 新增 STORED 生成列 + `uk_product_station` | `IF(owner_station_id IS NULL, NULL, CONCAT(owner_station_id,':',name,'|',IFNULL(spec,'')))` → 防同站重复自定义 |
| `inventory.sale_price` | 新增 `decimal(10,2) NULL` | 本站售价覆盖；NULL = 用 `product.price` |
| `inventory.deposit_price` | 新增 `decimal(10,2) NULL` | 本站押金覆盖；NULL = 用 `product.deposit` |
| `product_submission` | 新增表 | 自定义商品上报登记（status 0 待处理 / 1 已纳入 / 2 已驳回） |

**为什么用生成列**：`owner_station_id` 可空，MySQL 唯一键中 NULL 互不冲突 → 普通 `UNIQUE(owner_station_id, name, spec)` 对"通用库行"零保护。生成列表达"条件唯一"是本仓已验证的手法（先例 `payment_record.active_order_id`，见 v28）。

**存量回填口径**：v31 **不自动回填**归属——现有 `product` 行没有 creator 字段，无法判断当初是哪个站长建的。当前真实库 2 行均为 2026-09-15 的测试种子，一律保持 NULL（=通用库）。若某行确应归某站私有，手工 `UPDATE`（迁移文件 §7 给了示例与前置检查）。

## 4. 计价与金额口径

### 4.1 唯一入口

| 金额 | 唯一入口 | 阶梯 |
|---|---|---|
| 单价（零售 / 水票） | `util/PriceUtil#calcUnitPrice(product, inventory, paymentMethod)` | 水票：`inventory.ticket_price > 0` → `product.ticket_price > 0` → 站级售价 → `product.price`；其余：**`inventory.sale_price > 0` → `product.price`** |
| 押金 | `util/PriceUtil#calcDeposit(product, inventory)`（本次新建，禁止各处自己 if） | `inventory.deposit_price > 0` → `product.deposit` |

> **覆盖判定统一为「非空且 > 0」**：留空或填 0 都表示"用通用库参考值"。
> 理由不是偷懒——`customer_barrel_lot.unit_price = 0` 会被 `BarrelLedgerService#resolveUnitPrice` 按 [DEF-2]
> 当成"无快照"而回退到商品押金，即**"免押金"在当前桶账模型下表达不出来**。要做免押金活动得先改那条口径。
> 前端"清除覆盖"用一个显式的 0 表达（后端归一化为 NULL）。

调用方（必须全部改走上面两个入口，**不允许再出现第 4 处自成一体的计价**）：
- 报价 `PaymentServiceImpl.quote:705` / `:712` / `:735`
- 下单 `OrderServiceImpl:333` / `:339` / `:386` / `:472`
- 买水票 `TicketAccountServiceImpl:245-247`
- 员工端水票价值展示 `CustomerServiceImpl:361-370`
- 批次单价来源 `BarrelLedgerService:216-217`、`BarrelAssetServiceImpl:81-83`、`StationAdjustmentServiceImpl:242-252`

### 4.2 快照（改价不影响历史，**必须保持不变**）

下单时已快照，改造后**不许退化**：
`order_item.price/deposit/subtotal`（`OrderServiceImpl:485-489`）、`orders.water_amount/deposit_amount/total_amount`（`:433-435`）、`customer_barrel_in_transit.unit_price`（`:415`，本站押金）。
`customer_barrel_lot.unit_price` 必须继续**优先取 in_transit 快照**（`BarrelLedgerService:209-211`）——它直接决定退桶能退多少钱（`BarrelServiceImpl:497-499`）。
`ReconciliationService:218-225` 的对账口径（`Σ lot.remain_qty × unit_price`）本来就与当前押金解耦，**不要改回去**。

**唯一的调价泄漏点**：`BarrelLedgerService:216-217` 的第三级兜底（无快照的老/迁移数据）读的是当前 `product.deposit`。
→ 改造要求：该兜底改为**本站押金**，且这类批次（`customer_barrel_lot.is_migrated=1`）的退款继续走"二次确认"。

### 4.3 展示口径（本次明确）

| 场景 | 口径 |
|---|---|
| 商城 / 商品详情 / 下单页 | 后端下发**本站有效价**（`effectivePrice` / `effectiveDeposit` / `effectiveTicketPrice`），前端不再自己拼价 |
| 订单详情 / 支付流水 | 用订单快照（`order_item.price`、`orders.*`） |
| 桶权益"可退金额" | 用批次快照（`customer_barrel_asset.right_amount` / `Σ lot.remain_qty × lot.unit_price`） |
| 概览类"押金合计"（`BarrelServiceImpl:137/209/225`、`CustomerServiceImpl:323`） | **P0：改为本站押金**（与下单实收同口径，消除"展示按参考价、实收按站级价"）；**P3：再改为批次快照口径**（`Σ lot.remain_qty × unit_price` + 配送中按 `in_transit.unit_price`），因为它会改变站长/客户看到的既有数字，需要产品确认展示口径后再动 |

### 4.4 站级价提醒（不阻断）

保存本站售价/押金/水票价时，若偏离通用库参考价超过阈值 → 响应带 `warnings`（**保存照常成功**）。
- 参考值：`product.price` / `product.deposit`；水票参考 `product.price`。
- 阈值：配置项 `catalog.price-warn-ratio`（默认 `0.5` = ±50%），以及绝对值兜底（如 ≥ 10000 元直接提醒）。
- 与既有的"欠桶提醒 `warnings`"同构，前端以非阻断提示展示。

## 7. 员工端页面设计

### 7.1 结构

`pages/station-mgmt/products/index` **整体重做**（现 558 行、兼 11 项功能）：

1. **顶部**：搜索框 + 分类筛选（桶装水/瓶装水/饮水器）+ 分段「已选用 / 全部」。
2. **主列表（选品）**：每行 = 商品（图/名/规格/通用库参考价）+ 本站状态徽标（已上架/未上架/库存 N/本站价 ¥X/水票 ¥Y/★优先展示）。
   - 点行 → 半屏「本站设置」：上架开关、库存、本站售价（占位"默认 ¥参考价"）、本站押金、水票开关与水票价、优先展示；超阈值时**非阻断提醒**。
   - 未选用行显示「选用」按钮。
3. **库存与流水**：行内"入库"入口 + 底部「库存流水」（合并现孤岛页 `station-mgmt/inventory`，页面重做后删除该孤岛）。
4. **底部独立入口**：「＋ 自己定义商品」→ 自定义商品表单（名称/规格/图片/描述**可编辑** + 同样的本站设置），保存后进入"我的商品"。
5. **我的商品（自定义）**：编辑 / 停用 / **上报给开发者**。

> 「自己定义」入口放在**新版商品页底部**（现行卡片墙是两列 grid、8 张同款卡，无行式样式，不适合塞一个语义不同的入口）。卡片墙 `station-mgmt/index.wxml:18-22` 的「商品与库存」卡片指向不变。
